# Курс JS / TypeScript для команды wl-e2e

Материалы менторства: от базового JS до уровня, на котором можно самостоятельно
писать и чинить тесты в `wl-e2e`.

Курс **не** строится вокруг учебного пет-проекта. Все примеры — либо настоящий код
из `wl-e2e`, либо его упрощённая версия, чтобы знания сразу ложились на рабочий репозиторий.

## Установка

```bash
nvm use          # версия из .nvmrc (25.9.0)
yarn install     # или npm install — здесь одна зависимость, typescript
```

Нужен Node **≥ 22.18** — на нём `node file.ts` запускается напрямую.

## Команды

```bash
node playground/scratch.ts                           # запустить свой код
node lessons/lesson-03/examples/02-functions.ts       # запустить пример урока
yarn typecheck                                       # типы: playground + примеры
yarn typecheck:hw2                                   # типы: домашка урока 2
yarn typecheck:hw3                                   # типы: домашка урока 3
yarn typecheck:hw5                                   # типы: домашка урока 5
yarn typecheck:hw6                                   # типы: домашка урока 6
yarn typecheck:hw10                                  # типы: домашка урока 10
yarn typecheck:hw12                                  # типы: домашка урока 12
yarn typecheck:hw13                                  # типы: домашка урока 13
yarn typecheck:modules                               # типы: пример про импорты
yarn typecheck:broken                                # намеренно сломанные файлы

bash lessons/lesson-08/examples/01-three-trees.sh     # запустить пример по git
```

> Примеры уроков 8, 9, 11 и 12 — не TypeScript, а исполняемые сценарии `bash`.
> Каждый заводит свою песочницу в `/tmp/wl-git-examples/` (git) или
> `/tmp/wl-pw-examples/` (Playwright), выполняет команды и по ходу объясняет вывод. Ничего за пределами `/tmp` они не трогают, рабочий репозиторий
> в безопасности.

> Корневой `tsconfig.json` **дословно повторяет `tsconfig.json` из wl-e2e** —
> поведение компилятора здесь и на проекте совпадает один в один. Он покрывает
> `playground/`, включая любые подпапки. У домашки свой конфиг: он наследует те же
> настройки и меняет только список файлов — до выполнения она намеренно не проходит
> проверку, и её ошибки не должны мешаться с вашими.

## Как устроен курс

```
tsconfig.json      настройки компилятора — копия wl-e2e

lessons/lesson-NN/
├── README.md      ← конспект урока: разобранные темы с объяснениями
├── examples/      ← готовый код всех блоков, с комментариями. Запускается
│   └── broken/    ← файлы, которые намеренно не проходят проверку
└── homework/      ← домашка. До выполнения намеренно не проходит проверку

playground/        ← где набираем код: на уроке и самостоятельно
└── lesson-NN/     ← если хочется разложить по урокам. Конфиг не нужен
```

`playground/scratch.ts` к началу занятия уже заполнен кодом урока — без
комментариев, только код и разделители блоков. На уроке его запускают по кускам
и разбирают вывод; можно править и дописывать своё прямо там.

После занятия тот же код лежит в `lessons/lesson-NN/examples/` — разбитый
по темам, с комментариями и ожидаемым выводом, каждый файл запускается сам
по себе. Туда и стоит возвращаться: `scratch.ts` перезаписывается перед
следующим уроком.

Пропустили занятие или хотите повторить — начинайте с `README.md` урока: там краткое
объяснение каждой темы и ссылка на соответствующий пример. В конце — словарь терминов.

## Соглашения в коде методичек

`// ❌` перед закомментированной строкой — код, который **не должен** компилироваться.
Рядом указан код ошибки (`TS####`). Раскомментируйте, посмотрите на подчёркивание
в редакторе, верните обратно — это часть упражнения, а не опечатка.

## Если увидите `TS2451: Cannot redeclare block-scoped variable`

Появится, когда в `playground/` окажется **два** файла и оба объявят переменную
с одним именем. Причина: файл без единого `import` или `export` — это не модуль,
а *глобальный скрипт*, и его объявления верхнего уровня попадают в общую область
видимости со всеми такими же файлами.

Лечится любым из двух способов: что-нибудь из файла экспортировать или дописать
в конец пустой `export {};` — этого достаточно, чтобы файл стал модулем.

На рабочем проекте вы это вряд ли встретите: в `wl-e2e` каждый файл что-то
импортирует или экспортирует, поэтому модулем является автоматически.
