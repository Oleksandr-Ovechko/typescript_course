# Урок 6. `call`, `apply`, `bind`, деструктуризация, обход объекта, ошибки

Всё держится на трёх мыслях:

1. `this` — то, что слева от точки в момент вызова. Нет точки — `this`
   потерян. Его можно задать вручную: `call` и `apply` вызывают функцию
   с нужным `this`, `bind` делает новую функцию с `this`, прибитым навсегда;
2. деструктуризация — шаблон **слева** от `=`: у объекта берёт по имени,
   у массива — по позиции. Умолчание в шаблоне срабатывает только
   на `undefined`;
3. ошибка обрывает выполнение и летит наверх, пока её не поймает
   ближайший `try`.

## Повторение урока 5

Подробно — в [уроке 5](../lesson-05/README.md). Три правила:

- **Замыкание.** Функция помнит окружение места, где её **написали**.
  Не только та, которую вернули из другой функции, — любая. `tick`
  из `makeCounter` держит переменную `calls`, а не её копию: второй вызов
  даёт `2`.
- **Ссылка.** В переменной лежит не объект, а ссылка на него. Массив —
  тоже объект: `sameColors = colors` — тот же массив, `push` виден через
  обе переменные. `[...colors]` — новый массив, `===` даёт `false`.
  Объекты — это объекты, массивы и функции. Строки, числа, `true`/`false`,
  `null`, `undefined` — **не** объекты, это примитивы.
- **`this`** — то, что слева от точки в момент **вызова**:
  `user.greet()` → `this` — `user`.

Глубокую копию делает `structuredClone`. Копия через
`JSON.parse(JSON.stringify(obj))` не устарела, но **теряет данные**: методы
и `undefined` пропадают, `Date` становится строкой.

## `this`: без точки, у стрелки, вручную

Пример: [`01-this-call-apply-bind.ts`](examples/01-this-call-apply-bind.ts).

### Метод без точки

```ts
const user = {
  name: 'Ann',
  greet(): string {
    return `Привет, я ${this.name}`;
  },
};
const greetLater = user.greet;
console.log(typeof greetLater, greetLater === user.greet); // function true
greetLater(); // TypeError: Cannot read properties of undefined (reading 'name')
```

В `greetLater` лежит та же самая функция: `===` даёт `true`. Но вызывают
её без точки, и брать `this` неоткуда. В модуле (наши файлы) он
`undefined`, и чтение `.name` падает.

**TypeScript эту строку не подчёркивает**, `yarn typecheck` проходит
чисто. В типе `user.greet` не записано, какой `this` ей нужен, и он
не следит, как метод вызовут потом. Ловит только запуск.

`TypeError` в сообщении — это вид ошибки **JavaScript** при выполнении.
С проверкой типов TypeScript он связан только названием.

На практике так бывает, когда метод **передают в другую функцию**: та
вызывает его у себя, тоже без точки. Как этого избежать — [ниже](#как-передать-метод-дальше).

### У стрелки своего `this` нет

```ts
const lamp = {
  color: 'зелёная',
  describe(): string {
    const say = () => `лампа ${this.color}`;
    return say();
  },
};
console.log(lamp.describe()); // лампа зелёная
```

`say()` вызвана без точки — и всё равно работает. Своего `this`
у стрелки нет: она берёт его снаружи, по цепочке окружений, — у
`describe`. А там `this` — `lamp`, потому что вызвали `lamp.describe()`.

```text
метод — обычный:        describe() { … }            this = lamp (слева от точки)
внутри — стрелка:       const say = () => this.color   своего this нет → берёт у describe
стрелка ВМЕСТО метода:  describe: () => this.color     this снаружи объекта → undefined
```

- **Обычная функция вместо стрелки** — `const say = function () { … }` —
  не работает: у неё свой `this`, и в вызове `say()` без точки он пустой.
  TypeScript подчеркнёт `TS2683`.
- **Стрелка вместо самого метода** тоже не работает:
  `{ describe: () => this.color }` берёт `this` снаружи объекта, там, где
  объект написан. На верхнем уровне модуля это `undefined`, TypeScript
  подчеркнёт `TS2532` ещё до запуска. Вызов с точкой не спасёт: дело
  не в том, что метод «оторвали», — стрелке точка просто не важна.

Отсюда правило: **метод пишут обычным, стрелкой — функцию внутри него**.

И ещё: стрелка берёт `this` вызова `describe`, а не «объект навсегда».
Оторвите сам метод — `const d = lamp.describe; d()` — и он упадёт
так же, как `greetLater()`.

### `call` и `apply` — задать `this` вручную

```ts
function greetFrom(this: { name: string }, greeting: string, ending: string): string {
  return `${greeting}, я ${this.name}${ending}`;
}
const ann = { name: 'Ann' };
const bob = { name: 'Bob' };
greetFrom.call(ann, 'Привет', '!');   // Привет, я Ann!
greetFrom.apply(bob, ['Hello', '.']); // Hello, я Bob.
greetFrom.length;                     // 2
```

| Запись | Что делает |
|---|---|
| `this: { name: string }` первым в скобках | **не параметр**: только подсказка TypeScript, каким будет `this`. В JavaScript его нет |
| `f.call(объект, a, b)` | **вызвать сейчас**, подставив `объект` как `this`. Аргументы функции — после, по одному |
| `f.apply(объект, [a, b])` | то же самое, аргументы — **одним массивом** |
| `f.length` | сколько у функции параметров |

- **У `greetFrom` два параметра**, `greeting` и `ending`: `greetFrom.length`
  — `2`. `this:` в скобках — не параметр, при вызове его не передают.
  Объект для `this` идёт первым аргументом **самого `call`**, а не
  функции.
- Без `call` вызвать `greetFrom('Привет', '!')` TypeScript не даст —
  `TS2684`: `this` здесь был бы пустым.
- `call` и `apply` ничего не привязывают: они **один раз вызывают**
  функцию с заданным `this` и возвращают результат.
- Разница между ними — только в форме аргументов: **a**pply — **a**rray,
  **c**all — **c**omma (запятые). `apply` — из времён до спреда
  (урок 4), сегодня встречается в старом коде.

### `bind` — не вызвать, а сделать новую функцию

```ts
const annGreets = greetFrom.bind(ann);
annGreets('Хай', '!');                       // Хай, я Ann!
typeof greetFrom.call(ann, 'Хай', '!');      // string
typeof annGreets;                            // function
annGreets === greetFrom;                     // false
annGreets.bind(bob)('Хай', '?');             // Хай, я Ann?
```

```text
f.call(obj, a, b)     вызвать сейчас   → результат
f.apply(obj, [a, b])  вызвать сейчас   → результат
f.bind(obj)           НЕ вызывать      → новая функция, this прибит навсегда
```

- `call` вернул **строку** — результат вызова. `bind` ничего не вызвал
  и вернул **новую функцию** (не саму `greetFrom`: `===` даёт `false`).
  Вызывать её будем сами, когда захотим.
- **Второй `bind` поверх первого не действует.** `annGreets.bind(bob)` —
  ещё одна новая функция, но `this` у неё всё тот же: Ann. Перепривязать
  привязанную функцию нельзя.

### Как передать метод дальше

```ts
function runLater(action: () => string): string {
  return action();
}
const boundGreet = user.greet.bind(user);
const wrappedGreet = () => user.greet();
runLater(boundGreet);   // Привет, я Ann
runLater(wrappedGreet); // Привет, я Ann
```

Два лекарства от `greetLater()`:

- `boundGreet` — `bind`: `this` прибит к `user`;
- `wrappedGreet` — стрелка-обёртка: внутри неё `greet` вызывают
  **с точкой**, у `user`.

Обе можно класть в переменную и передавать в другую функцию — `this`
не потеряется. И обе устроены как замыкание из урока 5: новая функция
помнит объект, который ей дали.

## Деструктуризация

Пример: [`02-destructuring.ts`](examples/02-destructuring.ts).

### Спред и деструктуризация

Обе записи используют `...` и фигурные или квадратные скобки, поэтому их
легко спутать. Различает их сторона от `=`:

```ts
const colorsCopy = [...colors, 'blue']; // СПРАВА — спред: новый массив
const [firstColor] = colors;            // СЛЕВА — деструктуризация: взять из готового
```

- **Спред** (урок 4) — справа от `=` или в вызове. Раскладывает массив
  или объект в **новый**. Так делают поверхностную копию (урок 5).
- **Деструктуризация** — шаблон **слева** от `=`. Раскладывает готовый
  объект по переменным. Работает в одну сторону: собрать переменные
  в объект — это уже литерал `{ a, b }`, короткая запись из урока 5.

### Объект: по имени

```ts
const order: { item: string; count?: number; note?: string | null; price: number } = {
  item: 'чай',
  note: null,
  price: 40,
};
const { item: product, count = 1, note = 'без пометки', ...restOfOrder } = order;
console.log(product, count, note, restOfOrder); // чай 1 null { price: 40 }
```

| Часть шаблона | Что значит |
|---|---|
| `{ … }` **слева** от `=` | не объект, а шаблон: какие свойства взять |
| `item: product` | взять свойство `item`, положить в переменную `product`. Переменной `item` **не** появится (`TS2304`) |
| `count = 1` | если `count` в объекте `undefined` — взять `1` |
| `...restOfOrder` | всё, что **не** взяли по имени, — новым объектом. Только последним |
| `note?: string \| null` в типе | необязательное, а если есть — строка или `null` |

В `restOfOrder` нет ни `item`, ни `note`: остаток собирает только то, что
не названо в шаблоне. Остался один `price`.

Нужно одно свойство — берут одно, остальные писать не нужно:
`const { price } = order`.

### Умолчание — только на `undefined`

Почему `note` — `null`, а не `'без пометки'`?

Умолчание в шаблоне срабатывает **только на `undefined`**, как
у параметра функции (урок 4). `null` — это значение, его взяли как есть.
`count` в заказе нет совсем, он `undefined` — и умолчание сработало.

```ts
const { note: missing = 'без пометки' } = {};             // без пометки
const { note: empty = 'без пометки' } = { note: null };   // null
```

Порядок имён в шаблоне на результат не влияет: «объявили позже —
перезаписалось» здесь не бывает. Каждое имя берёт своё свойство.

### Двоеточие в шаблоне — не тип

`const { item: string } = order` не проверяет тип, а заводит переменную
с именем `string`, в ней `'чай'`. TypeScript не возразит. Тип пишут
**после** всего шаблона:

```ts
const { item }: { item: string } = order;
```

### Массив: по позиции

```ts
const podium = ['Ann', 'Bob', 'Kate', 'Max'];
const [winner, , third, ...others] = podium; // Ann Kate [ 'Max' ]
const [gold] = podium;                       // Ann
const [, , bronze] = podium;                 // Kate
```

| Часть | Что значит |
|---|---|
| `[winner, , third]` | **по позиции**, имена любые; пустое место между запятыми пропускает элемент |
| `...others` | остальные — **новым массивом**, даже если остался один |

Перечислять все элементы не нужно: хвост можно просто не писать.
Пропускать запятыми приходится только то, что стоит **до** нужного.

### Объект-параметр

```ts
function formatPrice({ amount, currency = 'грн' }: { amount: number; currency?: string }): string {
  return `${amount} ${currency}`;
}
formatPrice({ amount: 120 });             // 120 грн
formatPrice({ currency: '$', amount: 5 }); // 5 $
```

Вместо имени параметра — шаблон: аргумент-объект разобран сразу. Поля
именованные, порядок не важен, необязательное можно не передавать.
Тип — после шаблона.

Так устроены колбэки в тестах: библиотека передаёт объект, а вы берёте
из него нужное — `test('заголовок', async ({ page }) => { … })`.

## Обход объекта

Пример: [`03-object-iteration.ts`](examples/03-object-iteration.ts).

### `for...in` — ключи

```ts
const prices = { tea: 40, coffee: 60 };
for (const key in prices) {
  console.log(key); // tea, потом coffee
}
```

`for...in` даёт **ключи**, значений он не даёт. По массиву — тоже ключи,
то есть номера, и это **строки** `'0'`, `'1'`, а не числа.

Значение по ключу так просто не взять: `prices[key]` TypeScript
подчеркнёт `TS7053`. Тип `prices` он знает — он есть в самом сообщении:
`{ tea: number; coffee: number; }`. Дело в `key`: для TypeScript это
**любая** строка, а не только `'tea'` или `'coffee'`.

### `Object.keys`, `Object.values`, `Object.entries`

```ts
Object.keys(prices);    // [ 'tea', 'coffee' ]
Object.values(prices);  // [ 40, 60 ]
Object.entries(prices); // [ [ 'tea', 40 ], [ 'coffee', 60 ] ]

for (const [drink, cost] of Object.entries(prices)) {
  console.log(`${drink}: ${cost}`); // tea: 40, потом coffee: 60
}
```

| Запись | Что даёт |
|---|---|
| `Object.keys(obj)` | массив ключей |
| `Object.values(obj)` | массив значений |
| `Object.entries(obj)` | массив пар `[ключ, значение]` |

Пара — это массив, поэтому в заголовке `for...of` её сразу раскладывают
шаблоном массива. `Object.entries` и `for...of` — обычный способ обойти
объект: ключ и значение есть сразу, и TypeScript не возражает.
`for...in` в современном коде встречается редко.

### Логическое присваивание

Обход только читает объект. Дописать свойство, только если его ещё нет, —
логическое присваивание:

```ts
const settings: { theme?: string; volume?: number } = { volume: 0 };
settings.theme ??= 'light';
settings.volume ??= 50;
console.log(settings); // { volume: 0, theme: 'light' }

const loudSettings: { volume?: number } = { volume: 0 };
loudSettings.volume ||= 50;
console.log(loudSettings); // { volume: 50 }
```

| Запись | Что делает |
|---|---|
| `a ??= b` | записать `b`, только если `a` — `null` или `undefined` |
| `a \|\|= b` | записать `b`, если `a` ложное: ещё и `0`, `''`, `false` |
| `a &&= b` | записать `b`, только если `a` истинное |

Та же разница, что у `??` и `||` в уроке 3. `0` — нормальная громкость:
`??=` её не тронул, `||=` затёр. `0` — ложное **значение** (тип у него
`number`), поэтому `&&=` на нём дальше не идёт и громкость остаётся `0`.

## Ошибки

Пример: [`04-errors.ts`](examples/04-errors.ts).

### `try`, `catch`, `finally`

`greetLater()` из начала урока уронила весь файл: ниже неё ничего
не выполнилось. `try` позволяет сказать: «если здесь упадёт — не умирай,
сделай вот что».

```ts
try {
  console.log('до');
  console.log(greetLater());
  console.log('не напечатается: после ошибки');
} catch (error) {
  console.log('поймали:', String(error));
} finally {
  console.log('finally — всегда');
}
console.log('файл живёт дальше');
```

```text
до
поймали: TypeError: Cannot read properties of undefined (reading 'name')
finally — всегда
файл живёт дальше
```

| Часть | Что значит |
|---|---|
| `try { … }` | «попробуй». Ошибка в любой строке обрывает блок на ней |
| `catch (error) { … }` | выполняется, **только если** в `try` бросили ошибку; в `error` — брошенное |
| `finally { … }` | выполняется **всегда** — после `try` или после `catch` |

`TypeError` — вид ошибки, после двоеточия — её сообщение. Виды ошибок
бросает сам движок: `TypeError` — когда со значением нельзя сделать то,
что просят (прочитать свойство у `undefined`), `ReferenceError` — когда
имя нигде не объявлено или ещё в мёртвой зоне (урок 4). В своём коде бросают обычный `Error`.

### В `catch` — `unknown`

`console.log(error.message)` в `catch` `node` выполнит, а `yarn typecheck`
подчеркнёт: `TS18046: 'error' is of type 'unknown'`.

Бросить можно что угодно, хоть строку, поэтому TypeScript не знает, что
прилетит в `catch`. `String(...)` из урока 2 работает с чем угодно —
отсюда `String(error)` в примерах. Как проверить, что прилетел именно
объект ошибки, — урок 10.

### `throw new Error` — бросить свою

```ts
function divide(total: number, parts: number): number {
  if (parts === 0) {
    throw new Error('делить на ноль нельзя');
  }
  return total / parts;
}
try {
  console.log(divide(12, 4));                    // 3
  console.log('не напечатается:', divide(12, 0));
} catch (divideError) {
  console.log('поймали своё:', String(divideError)); // поймали своё: Error: делить на ноль нельзя
}
```

| Часть | Что значит |
|---|---|
| `new Error('текст')` | создать объект ошибки; текст ляжет в его свойство `message`. Как работает `new` — урок 15 |
| `throw x` | бросить `x`: оборвать выполнение и отправить наверх |

- Сам по себе `new Error(...)` ничего не обрывает — это просто объект.
  Обрывает только `throw`.
- Без нашего `throw` ошибки бы не было: `12 / 0` в JavaScript —
  `Infinity` (`node -e "console.log(12 / 0)"`). Ошибкой его делаем мы:
  решили, что такой результат дальше пускать нельзя.
- **Зачем бросать, если можно напечатать?** `console.log` ничего
  не останавливает: код пойдёт дальше с плохим значением и сломается
  позже, в другом месте. `throw` останавливает **здесь**, с вашим текстом
  про причину. В тесте так и выглядит падение: строка бросила ошибку —
  тест красный, с этим сообщением.

### Бросают `Error`, и создают его при броске

**`throw 'текст'` бросает саму строку**, ни во что она не заворачивается.
В `catch` прилетит строка, у неё нет ни `message`, ни записи о месте,
где её бросили. Поэтому бросают объект `Error` с осмысленным сообщением.

**`new Error` пишут прямо в `throw`, а не заранее.** Заманчиво создать
ошибку один раз — `const zeroError = new Error('…')` — и бросать её
везде. Но:

- объект `Error` запоминает место (стек вызовов), где его **создали**,
  а не где бросили: все броски укажут на строку создания;
- это один объект на все броски: поменяли его `message` в одном `catch` —
  изменилось у всех следующих.

Оба эффекта показаны в примере, строки `11)` и `12)`.

### Ошибка летит наверх

```ts
const portions = [4, 0, 2];

try {                                   // try СНАРУЖИ цикла
  for (const portion of portions) {
    console.log(divide(12, portion));   // 3
  }
} catch (loopError) {
  console.log('цикл прерван:', String(loopError));
}

for (const portion of portions) {       // try ВНУТРИ цикла
  try {
    console.log(divide(12, portion));   // 3, потом 6
  } catch {
    console.log('пропустили', portion); // пропустили 0
  }
}
```

```text
throw  (внутри divide)
  │
  ▼
из функции — туда, откуда её вызвали
  │
  ▼
ближайший try снаружи? ── да ──▶ catch ловит; дальше программа идёт как обычно
  │ нет
  ▼
следующий try снаружи … и так до самого верха
  │ никто не поймал
  ▼
файл упал (как greetLater() без try)

try СНАРУЖИ цикла — ошибка обрывает весь цикл
try ВНУТРИ цикла  — только этот проход
```

- В первом варианте ошибка вылетела из `divide`, потом из цикла, и её
  поймал `try` вокруг цикла. Цикл оборвался: до `2` не дошли.
- Во втором `try` внутри: ошибка обрывает только проход, цикл идёт
  дальше.
- `catch` без `(переменной)` — можно, когда неважно, что именно упало.
- В `catch` пойманное можно бросить **дальше**: `throw error;`. Тогда его
  ловит следующий `try` снаружи — по той же схеме.

> ⚠️ **Пустой `catch {}` глотает любую ошибку молча** — код идёт дальше,
> как будто её не было, и причину потом не найти. Внутри должно быть хоть
> что-то: сообщение или хотя бы комментарий, почему ошибка здесь не важна.

## Итог урока

1. Метод без точки теряет `this`, и TypeScript этого не ловит. Лечат
   `bind` или стрелкой-обёрткой. У стрелки своего `this` нет: стрелкой
   пишут функцию **внутри** метода, но не сам метод.
2. `call` и `apply` вызывают функцию с заданным `this`, `bind` делает
   новую функцию с прибитым `this`. Второй `bind` ничего не меняет.
   `this:` в скобках — не параметр.
3. Деструктуризация — шаблон слева от `=`: `{ }` берёт свойства по имени,
   `[ ]` — элементы по позиции. Умолчание — только на `undefined`. Спред
   справа от `=` — это другое: он делает новый массив или объект.
4. По объекту ходят через `Object.entries` и `for...of` с шаблоном
   `[ключ, значение]`. `??=` дописывает, только если пусто.
5. Ошибка обрывает выполнение и летит наверх до ближайшего `try`.
   `finally` — всегда. В `catch` — `unknown`, поэтому `String(error)`.
   Бросают `new Error(...)`, прямо в `throw`.

## Словарь терминов

| Термин | Что значит |
|--------|------------|
| **привязанная функция** (bound function) | функция, которую вернул `bind`: у неё `this` задан раз и навсегда, как её ни вызывай. Повторный `bind` его не меняет |
| **деструктуризация** (destructuring) | шаблон слева от `=`, который раскладывает объект или массив по отдельным переменным: `const { item } = order`, `const [first] = list`. У объекта берут по имени, у массива — по позиции |
| **логическое присваивание** | `??=`, `\|\|=`, `&&=`: присвоить, только если проверка `??`, `\|\|` или `&&` слева пропускает дальше. `a ??= b` записывает `b`, только если `a` — `null` или `undefined` |
| **бросить ошибку** (throw) | оборвать выполнение и отправить наверх объект ошибки с сообщением. Строки после места броска не выполняются, пока ошибку не поймает `try`/`catch` |

Знакомые слова: **замыкание**, **ссылка**, **контекст** (`this`),
**поверхностная копия** — [словарь урока 5](../lesson-05/README.md#словарь-терминов);
**спред**, **остаточные параметры**, **значение по умолчанию** — урок 4.
