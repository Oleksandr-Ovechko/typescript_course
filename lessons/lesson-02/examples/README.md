## Папка `broken/`

Два файла, которые **намеренно** не проходят проверку. Они исключены из
`yarn typecheck`, для них своя команда.

| Файл | Что показывает |
|------|----------------|
| [`broken/01-type-error.ts`](broken/01-type-error.ts) | `node` его запускает и печатает `NaN`, `yarn typecheck:broken` даёт две ошибки. Один файл, две команды — вся суть темы «типов в рантайме нет» |
| [`broken/02-enum.ts`](broken/02-enum.ts) | `node` вообще отказывается запускать `enum`. Но под Playwright он работает — почему, написано в файле |

```bash
node lessons/lesson-02/examples/broken/01-type-error.ts   # ✅ отработает
yarn typecheck:broken                                     # ❌ покажет ошибки
```

## Как читать пометки в коде

`// ❌ TS####` перед закомментированной строкой — код, который **не должен**
компилироваться, и код ошибки, которую вы увидите. Раскомментируйте, посмотрите
на подчёркивание в редакторе, верните обратно. Это часть упражнения.

`export {};` в конце каждого файла — техническая строка. Без неё файл считается
глобальным скриптом, и его объявления столкнутся с соседними примерами
(`TS2451: Cannot redeclare`). В реальном коде `wl-e2e` она не нужна: там каждый
файл что-нибудь импортирует или экспортирует и потому уже является модулем.
