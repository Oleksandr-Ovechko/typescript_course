## Две команды урока

Как устроен сам проект — `.nvmrc`, `package.json`, `yarn` — разобрано
в [конспекте урока 1](../lesson-01/README.md#как-устроен-проект-на-javascript).
Весь урок 2 — две команды в корне курса:

```bash
node playground/scratch.ts     # выполнить файл
yarn typecheck                 # проверить типы, ничего не выполняя
```

| Часть | Что значит |
|---|---|
| `node` | программа, которая выполняет JavaScript вне браузера: в терминале, на сервере, в CI. Тесты запускаются им же. Внутри у Node тот же движок V8, что в Chrome |
| `playground/scratch.ts` | какой файл выполнить. Node 22.18 и новее запускает `.ts` напрямую: типы перед запуском **выбрасывает** и выполняет то, что осталось |
| `yarn typecheck` | скрипт из `package.json`, внутри — `tsc --noEmit`: компилятор TypeScript читает файлы и ищет ошибки типов, ничего не собирая |

`node` без имени файла открывает **интерактивный режим**: набираете строку
кода — сразу видите результат (`2 + 2` → `4`). Выход — `.exit` или
дважды `Ctrl+C`.

Редактор (VS Code, WebStorm) проверяет типы сам, пока вы пишете, и
подчёркивает ошибки красным. `yarn typecheck` делает то же для всего
проекта разом — по команде.

## Значение и имя для него

Пример: [`01-values-and-names.ts`](examples/01-values-and-names.ts).

### `console.log`

```ts
console.log('1)', 'Ann', 42, true);
console.log('2)', 'визитов:', 3, '· активен:', false);
```

```
1) Ann 42 true
2) визитов: 3 · активен: false
```

**Значение** — сами данные: текст в кавычках (`'Ann'`), число (`42`),
«да/нет» (`true`/`false`). `console.log(…)` печатает всё, что в скобках
через запятую, **через пробел** в одну строку; строки — без кавычек.
`'1)'` — тоже обычная строка, метка, по которой строку легко найти
в выводе.

### `const` и `let`

Напечатанное значение пропадает. Чтобы использовать его ещё раз, ему
дают имя.

```ts
const clientName = 'Ann';
let visitCount = 3;
visitCount = 4;
console.log('3)', clientName, visitCount);   // 3) Ann 4
```

| Часть | Что значит |
|---|---|
| `const` / `let` | «заводим имя»: навсегда или с правом заменить значение |
| `visitCount` | само имя; слитно, каждое следующее слово — с большой буквы |
| `=` | **положить** значение справа под имя слева. Не «равно»: сравнение — ниже, `===` |
| `visitCount = 4` | без `const`/`let` — заменить то, что уже лежит под этим именем |

Заменить значение у `const` нельзя: `clientName = 'Bob'` — `yarn typecheck`
даст `TS2588`, а сам JavaScript при запуске упадёт.

**По умолчанию пишут `const`**, `let` — только когда значение правда
меняется. Видишь `const` — знаешь, что ниже по коду значение то же самое,
искать замену не нужно. Есть и третий способ, `var`, — старый, в новом
коде его не пишут. Чем он плох — урок 4.

### Аннотация `: string`

```ts
const city: string = 'Kyiv';
let spotsLeft: number = 12;
```

`: string` после имени — **аннотация типа**: обещание, что под этим
именем будут только строки. `string` — строка, `number` — число.
TypeScript — это JavaScript плюс такие типы.

Пообещаем число, а положим строку — `let spotsLeft: number = 'двенадцать';`:

```bash
node playground/scratch.ts     # выполнит и напечатает «двенадцать» — типов для него нет
yarn typecheck                 # error TS2322: Type 'string' is not assignable to type 'number'.
```

Один и тот же файл: `node` выполнил, `yarn typecheck` отказался.
**Проверку типов делает только `yarn typecheck`** (или редактор).

Писать `: string` у `'Kyiv'` не обязательно: TypeScript сам видит, что
это строка. Аннотацию пишут там, где он сам не видит, — чаще всего на
входе в функцию (урок 4).

### Строка в обратных кавычках

```ts
const greeting = `Клиент ${clientName}, визитов: ${visitCount}`;
console.log('5)', greeting);                      // 5) Клиент Ann, визитов: 4
console.log('6)', `мест: ${spotsLeft - 2}`);      // 6) мест: 10
```

| Часть | Что значит |
|---|---|
| `` `…` `` | обратные кавычки — клавиша под `Esc` |
| `${clientName}` | «подставь сюда значение»; внутри `${}` — имя или любое выражение |
| `${spotsLeft - 2}` | сначала посчитали, потом подставили |

Подстановка происходит **при выполнении**, на той строке, где стоит
строка: какое значение лежит под именем в этот момент, такое и
подставится. В обычных кавычках `'…'` подстановки нет — `${` останется
просто символами.

Так собирают, например, текст ошибки, который потом читают в отчёте
упавшего теста: `` `не найден клиент "${clientName}"` ``.

## Какого типа значение

Пример: [`02-types-of-values.ts`](examples/02-types-of-values.ts).

### `typeof` и семь примитивов

```ts
console.log('7)', typeof 'Ann', typeof 42, typeof 1.5, typeof true, typeof 10n);
// 7) string number number boolean bigint
```

`typeof` — **оператор**, как `+` или `-`: пишется перед значением, без
точки и без скобок, и отдаёт **строку** с именем типа. Работает и с именем
переменной — смотрит на то, что в ней лежит.

- `42` и `1.5` — один тип `number`: отдельного «целого» в JavaScript нет.
- `10n` — `bigint`, целые любой длины. В тестах не нужен — знать, что есть.

**Примитив** — простое значение, которое не состоит из других. Их семь:

```
string     'Ann'
number     42, 1.5
boolean    true, false
bigint     10n
undefined  значения не было
null       нарочно пусто
symbol     уникальная метка — урок 12

Всё остальное — объект: и {…}, и массив, и функция.
```

Всего типов значений в JavaScript восемь: семь примитивов и объект.

### `undefined` и `null`

```ts
let notAssigned;
const cleared = null;
console.log('9)', notAssigned, cleared);     // 9) undefined null
```

- **`undefined`** — значения **не было**: имя завели, а положить ничего
  не положили. Его выдаёт сам язык.
- **`null`** — значение **нарочно пустое**: кто-то положил «пусто» сам.

Два вида «ничего» нужны, чтобы отличать «ещё не дошли» от «проверили —
пусто». В тестах `null` выдаёт Playwright: `getAttribute('id')`
возвращает `null`, если такого атрибута у элемента нет. Сами в коде
«пусто» обозначают `null`, а `undefined` вручную не кладут.

### Объект и массив

```ts
const client = { name: 'Ann', visits: 3 };
const prices = [10, 20, 30];
console.log('11)', client, prices);                        // 11) { name: 'Ann', visits: 3 } [ 10, 20, 30 ]
console.log('12)', client.name, prices[0], prices[2]);     // 12) Ann 10 30
```

**Объект** держит значения под именами, достаём через точку —
`client.name`. **Массив** — объект, где значения лежат по порядку под
номерами, достаём по номеру в квадратных скобках — `prices[0]`. Номера
идут **с нуля**: `prices[0]` — первое.

`console.log` печатает объект со всеми его полями.

### Что `typeof` скажет про объект

```ts
console.log('13)', typeof client, typeof prices, typeof cleared);   // 13) object object object
```

- `typeof prices` — `'object'`: массив и правда объект. Но отличить так
  массив от объекта нельзя.
- `typeof null` — `'object'`. Это **ошибка в самом языке**, сделанная
  в 1995 году. Исправить нельзя: на неё завязано слишком много кода.
  `null` — примитив, врёт только `typeof`.

### Точка и метод

```ts
console.log('14)', Array.isArray(prices), Array.isArray(client));   // 14) true false
console.log('15)', 'ann'.toUpperCase(), prices.includes(20));       // 15) ANN true
```

**Метод** — действие, которое есть у значения. Вызывается через точку
и круглые скобки: `значение.метод(…)`. В скобках — с чем выполнить;
пустые скобки — «ни с чем, просто выполни».

| Часть | Что значит |
|---|---|
| `Array` | встроенный объект для работы с массивами |
| `.isArray(prices)` | его метод: «`prices` — массив?» Так и отличают массив от объекта |
| `'ann'.toUpperCase()` | у строки метод «всё большими буквами» |
| `prices.includes(20)` | у массива метод «есть ли в тебе 20?» |

Через точку достают и данные (`client.name`), и действия (`.isArray(…)`):
со скобками — **вызов**. `console.log` — тоже метод: `console` —
встроенный объект, `log` — его метод «напечатай».

У строки методы есть, хотя она примитив: на время вызова язык сам
оборачивает её в объект с методами строк. Происходит это при выполнении,
в момент вызова. Как это устроено — урок 17; пользоваться можно уже сейчас.

## Язык приводит типы сам

Пример: [`03-coercion.ts`](examples/03-coercion.ts).

### Явное приведение

```ts
const parsedBadge = Number('12');
const badgeText = String(12);
console.log('16)', parsedBadge, typeof parsedBadge, badgeText, typeof badgeText, Boolean(1));
// 16) 12 number 12 string true
```

**Приведение типов** — превращение значения одного типа в значение
другого. Бывает **явное** — мы попросили — и **неявное** — язык сделал
сам, когда операции понадобился другой тип.

`Number(…)`, `String(…)`, `Boolean(…)` — явное: «сделай из этого число /
строку / `true`-`false`». Это встроенные функции, вызываются без точки.

В выводе `12` и `12` выглядят одинаково: `console.log` печатает строку
без кавычек. Различает их только `typeof`.

**Всё, что тест достаёт со страницы, — строка.** Цена «12.50» на экране
приходит в тест как `'12.50'`.

### `+` склеивает, `-` вычитает

```ts
const fromBadge = '12';
console.log('18)', fromBadge + 1, Number(fromBadge) + 1);   // 18) 121 13
console.log('19)', 1 + 2 + '3', '1' + 2 + 3);               // 19) 33 123
```

`+` умеет две вещи: **складывать** числа и **склеивать** строки. Если
**хотя бы одна сторона** — строка, он склеивает, и неважно, с какой
стороны она стоит: `'12' + 1` — `'121'`, `1 + '12'` — `'112'`. Цена со
страницы плюс доставка — и сумма стала длиннее.

Считается **слева направо**, по паре за раз: `1 + 2` — `3`, потом
`3 + '3'` — `'33'`. А в `'1' + 2 + 3` строка с самого начала: `'12'`,
потом `'123'`.

У `-` «строкового» смысла нет. Чистый JavaScript молча превратит строку
в число (`node` типы не проверяет, `-e` — выполнить код прямо из кавычек):

```bash
node -e "console.log('5' + 1, '5' - 1, '5' * 2)"
# → 51 4 10
```

TypeScript строку у минуса не пропускает вовсе: `fromBadge - 1` — `TS2362`.

> ⚠️ **Главное в блоке.** От `-` со строкой TypeScript вас **защитит**,
> а от `+` — **нет**: склеить строку с числом — законная операция,
> `yarn typecheck` промолчит. Правило: значение со страницы — сначала
> `Number(…)`, потом арифметика.

`${}` тоже превращает в строку что угодно:

```ts
console.log('17)', `${prices}`, `${client}`, `${cleared}`);   // 17) 10,20,30 [object Object] null
```

Массив — в значения через запятую, `null` — в слово `null`, объект —
в бесполезное `[object Object]`. Увидите `[object Object]` в тексте
ошибки теста — значит, в `${}` подставили объект целиком.

### Ложные значения и `||`

```ts
console.log('20)', Boolean(false), Boolean(0), Boolean(''), Boolean(cleared), Boolean(notAssigned));
// 20) false false false false false
console.log('21)', Boolean('0'), Boolean(' '), Boolean('false'), Boolean([]), Boolean({}));
// 21) true true true true true
```

**Ложное значение** (falsy) — значение, которое при приведении
к `true`/`false` даёт `false`. Их ровно **восемь**:

```
false    0    -0    0n    ''    null    undefined    NaN
```

Все остальные — **истинные** (truthy). Среди чисел ложные только `0`,
`-0` и `NaN`: `Boolean(5)` и `Boolean(-1)` — `true`, `Boolean(0)` —
`false`.

- `'0'`, `' '`, `'false'` — **непустые** строки, значит истинные. Пустая
  только `''`.
- `[]` и `{}` — объекты, а **любой объект истинный**, даже пустой.

`||` — **логическое ИЛИ**. `a || b` — «если `a` ложное, взять `b`, иначе
`a`». Если ложные обе стороны, получится `b`.

```ts
const emptyCell = '';
const filledCell = 'Ann';
const zeroBalance = 0;
console.log('22)', emptyCell || 'нет данных', filledCell || 'нет данных', zeroBalance || 'нет данных', emptyCell || zeroBalance);
// 22) нет данных Ann нет данных 0
```

Пустую ячейку заменили на «нет данных» — этого и хотели. **Но и ноль
заменили**: баланс `0` — настоящие данные, а `||` выбросил их как «ложь».
Для случаев, где `0` и `''` — настоящие значения, есть `??` — он заменяет
только `null` и `undefined` (урок 5). `&&` и `!` — урок 3.

Клавиша `|` — `Shift` + клавиша `\` (на обычной раскладке — под `Backspace`, над `Enter`).

### `===` против `==`

```ts
console.log('23)', fromBadge === '12', Number(fromBadge) === 12, cleared === null);   // 23) true true true
console.log('24)', cleared == notAssigned, cleared === notAssigned);                  // 24) true false
```

- `===` — **строгое** равенство: «то же значение того же типа?». Ничего
  не приводит.
- `==` — **нестрогое**: если типы разные, сначала приводит, потом
  сравнивает. `null == undefined` — `true`: так `==` устроен нарочно,
  `null` и `undefined` равны друг другу и больше ничему (`null == 0` —
  `false`).
- Строку и число TypeScript не даст сравнить ни так, ни так — `TS2367`.

Что делает `==` без TypeScript:

```bash
node -e "console.log('5' == 5, '5' === 5, 0 == '', 0 == '0', '' == '0')"
# → true false true true false
```

**В какую сторону приводит `==`.** При «строка `==` число» к **числу**
приводится **строка** — с какой бы стороны она ни стояла: `'5'` → `5`,
`''` → `0`, `'0'` → `0`. Проверить можно так: `'1e1'` — запись числа
10.

```bash
node -e "console.log('1e1' == 10, 10 == '1e1', '10' == '1e1')"
# → true true false
```

Если бы `==` превращал число в строку, вышло бы `'10' == '1e1'` — ложь.

Отсюда и последние три в первой команде: `0 == ''` — правда, `0 == '0'` —
правда, а `'' == '0'` — две строки, приводить нечего, строки разные —
ложь. Два значения равны третьему, но не равны друг другу.

**Правило: всегда `===`.** Запись `x == null` в чужом коде — короткое
«`null` или `undefined`»: её достаточно узнавать.

## Строки

Пример: [`04-strings.ts`](examples/04-strings.ts). Строка со страницы
почти всегда «грязная»: пробелы по краям, валюта, запятые.

### Методы строки ничего в ней не меняют

```ts
const rawName = '  Ann  ';
const trimmedName = rawName.trim();
rawName.trim();
console.log('25)', `[${rawName}]`, `[${trimmedName}]`);   // 25) [  Ann  ] [Ann]
```

`trim()` убирает пробелы, табуляции и переносы строк по краям.
Квадратные скобки в выводе — наши, чтобы пробелы было видно.

**Ни один метод строки не меняет строку** — каждый отдаёт новую.
Результат надо положить под имя: `const trimmedName = rawName.trim()`.
Строка `rawName.trim();` сама по себе не делает **ничего** — и ошибки
тоже не будет.

### Регистр и язык

`toUpperCase()` и `toLowerCase()` знают любой алфавит, не только
английский: `'привет'.toUpperCase()` — `'ПРИВЕТ'`.

У некоторых языков свои правила. В турецком у строчной `i` заглавная —
`İ`, с точкой. Это учитывает `toLocaleUpperCase` с кодом языка:

```ts
console.log('i'.toUpperCase(), 'i'.toLocaleUpperCase('tr'));   // I İ
```

Без кода языка `toLocaleUpperCase()` берёт язык системы, и на разных
машинах результат может отличаться. Поэтому язык указывают явно.

### `replace` заменяет только первое

```ts
const amount = '1,234,567';
console.log('27)', amount.replace(',', ''), amount.replaceAll(',', ''));   // 27) 1234,567 1234567
```

| Часть | Что значит |
|---|---|
| `.replace(',', '')` | найти `','` и заменить на `''` (пустую строку) — **только первое** найденное |
| `.replaceAll(',', '')` | то же, но **все** найденные |

Когда первое — именно то, что нужно (отрезать известное начало строки),
`replace` правилен. В чужом коде «заменить всё» чаще записано
регулярным выражением: `amount.replace(/,/g, '')`, где `g` — «все
совпадения». Регулярки — урок 13; сегодня достаточно узнавать `/…/g`.

Запятые в суммах — не везде разделитель разрядов. В американской записи
`1,234.56` запятая отделяет тысячи, точка — дробную часть; в украинской
наоборот: `1 234,56`. Чистить строку надо под запись, в которой она
пришла.

### `.length` считает ячейки, а не буквы

```ts
console.log('28)', 'Ann'.length, 'привет'.length, '中'.length, '👍'.length);   // 28) 3 6 1 2
console.log('29)', 'привет'.slice(0, 3), '👍'.slice(0, 1));                    // 29) при �
```

`.length` пишется без скобок: это не метод, а данные, как `client.name`.

- Строка в памяти — ряд **ячеек**. Почти любой символ — одна ячейка:
  латиница, кириллица, иероглиф `'中'`.
- Эмодзи — **две** ячейки и больше: он лежит за пределами основной
  таблицы символов. Поэтому `'👍'.length` — `2`.
- Это не байты: в файле `'привет'` занимает 12 байт, а `.length` у него — 6.
  У массива `.length` — число элементов.

`slice(0, 3)` — кусок с ячейки 0 **до** ячейки 3, саму ячейку 3 не берёт:
`'при'`. У эмодзи `slice(0, 1)` отрезал **половину** — получился мусор `�`.
Иероглиф так не ломается: он одна ячейка. Обрезая текст со страницы по
`.length`, можно разрезать эмодзи.

`splice`, похожий на `slice`, — метод массива, а не строки.

## Числа

Пример: [`05-numbers.ts`](examples/05-numbers.ts).

### Дробные числа

```ts
console.log('30)', 0.1 + 0.2, 0.1 + 0.2 === 0.3);       // 30) 0.30000000000000004 false
console.log('31)', 0.5 + 0.25, 0.5 + 0.25 === 0.75);    // 31) 0.75 true
```

- Число хранится в **двоичной** записи. `0.5` — это `1/2`, `0.25` — `1/4`:
  в двоичной записи они короткие и хранятся точно.
- `0.1` и `0.2` в двоичной — **бесконечные** дроби, как `1/3` в десятичной
  (`0.333…`). Их обрезают, и погрешность всплывает при сложении.

```
десятичная:  1/3 = 0.3333...             — бесконечно
двоичная:    0.1 = 0.0001100110011...    — бесконечно, обрезали
             0.5 = 0.1                   — точно
```

Это не особенность JavaScript: так хранит дробные почти любой язык, и
сумма получается та же самая. Python тоже печатает `0.30000000000000004`.
Языки различаются только тем, сколько знаков показывают при печати.

**Дробные не сравнивают через `===`.** В тестах для этого есть проверка
`toBeCloseTo` («равно с точностью до знаков», урок 15): она проверяет,
что разница меньше половины последнего знака — по умолчанию меньше
`0.005`. А если суммы надо **считать**, их переводят в целые центы.

### `NaN`

```ts
const notNumber = Number('двенадцать');
console.log('32)', notNumber, typeof notNumber, notNumber === notNumber, Number.isNaN(notNumber));
// 32) NaN number false true
```

- `NaN` — «не число» (Not a Number): результат неудачного превращения
  (`Number('двенадцать')`) или неудачной арифметики (`'abc' - 1` без
  TypeScript).
- `typeof NaN` — `'number'`. Это не ошибка языка: `NaN` — особое значение
  **внутри** числового типа, так устроены дробные числа во всех языках.
- `NaN` — **единственное значение, не равное самому себе**. Поэтому
  `x === NaN` всегда ложь.
- Проверяют методом `Number.isNaN(x)`. Это метод встроенного объекта
  `Number`, у самого числа его нет: `(5).isNaN()` не сработает.

`NaN` — восьмое ложное значение.

### `Number`, `parseInt`, `parseFloat`

```ts
console.log('33)', Number('12.5'), Number('12.5 USD'), Number(''), Number('  7 '));   // 33) 12.5 NaN 0 7
console.log('34)', parseInt('12.5 USD'), parseFloat('12.5 USD'), parseFloat(''));    // 34) 12 12.5 NaN
```

| Что | Как читает | `'12.5 USD'` | `''` |
|---|---|---|---|
| `Number(s)` | вся строка должна быть числом, иначе `NaN`; пробелы и переносы по краям прощает | `NaN` | **`0`** |
| `parseFloat(s)` | слева, пока читается, с дробной частью | `12.5` | `NaN` |
| `parseInt(s)` | слева, пока читается, **только целое** | `12` | `NaN` |

Две ловушки:

- **`Number('')` — ноль.** Пустая ячейка со страницы молча станет `0`,
  и сумма сойдётся, хотя данных не было.
- **`parseInt` теряет копейки.** `parseInt('12.5')` — `12`. Для денег —
  `parseFloat` или `Number`, не `parseInt`.

Что выбрать: `Number` строгий — `'19.99 USD'` для него не число, зато
мусор он не пропустит. `parseFloat` прочитает `19.99` и молча отбросит
хвост. Нужна строгость — `Number`, нужна терпимость к хвосту — `parseFloat`.

**Пустая ячейка и `|| 0`.** Частый приём — `parseFloat(text) || 0`:
`NaN` ложное, и вместо него получится `0`. Тест перестаёт падать на
пустой ячейке. Но у приёма есть цена: «ячейка пустая» и «в ячейке 0»
становятся неразличимы. Если пустая ячейка — это баг, лучше, чтобы тест
упал, чем молча посчитал её нулём.

### `toFixed` отдаёт строку

```ts
const orderTotal = 19.999;
const shownTotal = orderTotal.toFixed(2);
console.log('35)', shownTotal, typeof shownTotal);          // 35) 20.00 string
console.log('36)', shownTotal + 1, Number(shownTotal) + 1); // 36) 20.001 21
console.log('37)', (1.005).toFixed(2), (25).toFixed(2));    // 37) 1.00 25.00
```

- **`toFixed` отдаёт строку.** `'20.00' + 1` — склейка, `'20.001'`.
  Результат `toFixed` нельзя складывать и сравнивать с числами; нужно
  число обратно — `Number(…)`.
- Он округляет **то, что хранится в памяти**. `1.005` в двоичной хранится
  чуть **меньше** 1.005 — поэтому `'1.00'`, а не `'1.01'`.
- Добавляет нули: `(25).toFixed(2)` — `'25.00'`. `25` в скобках, потому
  что точку сразу после цифр язык читает как начало дробной части.

**Для чего он тогда?** Для **вывода** — последним шагом, когда число
превращается в текст для поля ввода или отчёта: в поле цены уходит
`'25.00'` — ровно то, что набрал бы человек. Считают — числами.

### Округление через `Math`

`Math` — встроенный объект с математикой. Его методы отдают **число**,
а не строку, и лишних нулей не добавляют. Округляют до целого:

```ts
console.log(Math.ceil(19.01), Math.floor(19.99), Math.round(19.5));   // 20 19 20
```

| Метод | Куда округляет |
|---|---|
| `Math.ceil` | вверх |
| `Math.floor` | вниз |
| `Math.round` | к ближайшему; ровно посередине — вверх, и у отрицательных тоже: `Math.round(-2.5)` — `-2` |

Округлить до центов приёмом «умножить на 100, округлить, разделить» —
та же ловушка, что у `toFixed`:

```ts
console.log(1.005 * 100, Math.round(1.005 * 100) / 100);   // 100.49999999999999 1
```

## Всё вместе: как проект достаёт цену

Пример: [`06-extract-price.ts`](examples/06-extract-price.ts).
Почистить строку, превратить в число, не потерять копейки. Сначала
своими руками:

```ts
const cellText = '$1,234.56';
const digitsOnly = cellText.replaceAll('$', '').replaceAll(',', '');
console.log('38)', digitsOnly, parseInt(digitsOnly), parseFloat(digitsOnly));
// 38) 1234.56 1234 1234.56
```

Методы идут цепочкой: каждый отдаёт новую строку, и у неё сразу
вызывается следующий. `parseInt` потерял 56 центов, `parseFloat` — нет.

А так это сделано в рабочем проекте на Playwright. Это **хелпер** —
функция, которую вызывают тесты:

```ts
export async function extractPrice(locator: Locator): Promise<number> {
  const text = await locator.evaluate((el) => el.getAttribute('data-amount') || el.textContent || '');
  return parseFloat(text.replace(/[^0-9.]/g, ''));
}
```

| Часть | Что значит |
|---|---|
| `export async function extractPrice(locator: Locator): Promise<number>` | хелпер: получает элемент страницы, отдаёт число. Как такое пишется — уроки 4 и 11 |
| `locator.evaluate((el) => …)` | выполнить код над элементом в браузере — урок 14 |
| `el.getAttribute('data-amount') \|\| el.textContent \|\| ''` | атрибут с суммой; нет его (`null`) — текст элемента; нет и текста — пустая строка. Цепочка `\|\|` |
| `text.replace(/[^0-9.]/g, '')` | убрать **всё**, кроме цифр и точки (`g` — во всей строке). Наш `replaceAll` в два шага делает то же для двух символов |
| `parseFloat(…)` | читать с дробной частью — копейки целы |

Что функция вернёт для `'Free'` и для пустой ячейки — задание 3
домашки.

## Сверх плана: типы объектов и свои функции

Пример: [`07-asked-during-lesson.ts`](examples/07-asked-during-lesson.ts).
На занятии забежали вперёд. Подробно это будет в уроках 8 и 4, здесь —
чтобы узнавать запись в чужом коде.

**Тип объекта и массива.** После двоеточия вместо имени примитива —
описание объекта: какие поля, какого типа. Массив строк — `string[]`.

```ts
const client: { name: string; visits: number } = { name: 'Ann', visits: 3 };
const clients: string[] = ['Ann', 'Bob', 'Charlie'];
```

Каждое поле, перечисленное в типе, обязательно. Добавить в тип
`retries: number`, а в объект не положить — `TS2741: Property 'retries'
is missing`. Сделать поле **необязательным** — знак вопроса:
`retries?: number`. Тогда при чтении под ним `number` или `undefined`
(не `null`).

**Свои функции и глобальный объект.** Свою функцию вызывают без точки:
`greetClient('Ann')`. Попадает ли она в глобальный объект (в браузере
это `window`), зависит от того, как загружен код:

- в старом браузерном `<script>` — да, `function` верхнего уровня
  становится `window.greetClient`;
- в **модулях** — нет. Файлы курса и тесты на Playwright — модули
  (`export {}` в конце файла и `"type": "module"` в `package.json`);
- в Node объекта `window` нет вообще. Общий для браузера и Node
  глобальный объект называется `globalThis`.

**Точка с запятой.** JavaScript в большинстве мест сам расставляет
пропущенные `;`, но есть случаи, где он склеивает строки не так, как
задумано. Поэтому в проектах `;` ставят всегда, и за этим следит
форматтер (Prettier) — он расставит их сам при сохранении.

## Итог в семи строках

1. Значение под именем: по умолчанию `const`, `let` — когда правда
   меняется. `: string` проверяет только `yarn typecheck`.
2. Примитивов семь. `typeof null` и `typeof []` — `'object'`; массив
   отличает `Array.isArray`.
3. Всё со страницы — строка. `+` со строкой склеивает, и TypeScript
   промолчит: сначала `Number(…)`.
4. Ложных значений восемь; `'0'` и `[]` — истинные. `||` заменяет и ноль.
5. Всегда `===`. `== null` — узнавать, не писать.
6. Методы строки не меняют строку; `replace` со строкой — только первое.
7. Дробные — не через `===`. `toFixed` отдаёт строку. Деньги — `parseFloat`,
   не `parseInt`.

## Словарь терминов

| Термин | Что значит |
|--------|------------|
| **переменная** (variable) | имя, под которым лежит значение. `const` — положили один раз; `let` — можно положить другое |
| **аннотация типа** (type annotation) | запись `: тип` после имени — обещание, какие значения будут под этим именем. Добавка TypeScript; `node` её выбрасывает, проверяет `yarn typecheck` |
| **примитив** (primitive) | простое значение, которое не состоит из других: `string`, `number`, `boolean`, `bigint`, `undefined`, `null`, `symbol` |
| **объект** (object) | значение, которое держит внутри другие значения под именами: `{ name: 'Ann' }`, достают через точку. **Массив** (array) — объект, где значения лежат по порядку под номерами с нуля: `[10, 20]`, `prices[0]` |
| **метод** (method) | действие, которое есть у значения: `значение.метод(…)` |
| **приведение типов** (type coercion) | превращение значения одного типа в значение другого: явное (`Number('12')`) или неявное — язык сам (`'12' + 1`) |
| **ложное значение** (falsy) | значение, которое при приведении к `true`/`false` даёт `false`. Их восемь: `false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN` |

Узнать в лицо, запоминать пока не нужно: **оператор** (`+`, `===`,
`typeof`, `||` — значок или слово, которое что-то делает со значениями),
**`NaN`** (особое число «не число»), **`tsc`** (компилятор TypeScript —
то, что внутри `yarn typecheck`), **интерактивный режим `node`** (`node`
без файла: строка кода — сразу результат), **хелпер** (готовая функция,
которая делает один шаг теста).
