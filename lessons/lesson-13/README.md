`TestRailReporter`.

## Уточнения к занятию

Места, где на занятии прозвучала неточность. Всё проверено запуском.

**1. Общий массив в прототипе — ошибка, а не приём.** Пример, где два
отчёта пишут в один `results`, показывает, чего делать **нельзя**. Правило
обратное: в прототип — то, что у всех одинаковое (методы), в сам объект —
то, что у каждого своё (данные). У настоящего `TestRailReporter` `results` —
поле экземпляра: у каждого репортера свой массив.
→ [Данные в прототипе](#данные-в-прототипе-делят-все)

**2. У объекта нет свойства `prototype`.** `Object.create(x)` нельзя
записать как `obj.prototype = x`: такое присваивание создаст обычное
свойство с именем `prototype`, а прототип не поменяет. Свойство `prototype`
есть только у **функций**. Назначить прототип готовому объекту —
`Object.setPrototypeOf(obj, x)`.

**3. Функция-конструктор не входит в цепочку своих экземпляров.** Цепочка
отчёта, созданного через `LegacyReport`: `отчёт → reportMethods →
Object.prototype → null`. Самой функции в ней нет — она только хранит
в свойстве `prototype` ссылку на первое звено.
→ [Функция, её `prototype` и экземпляр](#функция-её-prototype-и-экземпляр)

**4. Порядок строк в теле класса ничего не значит.** Поле остаётся
собственным свойством экземпляра, а метод — общим, где бы они ни стояли:
до `constructor` или после. Разницу делает форма записи: `имя = значение` —
поле, `имя() { … }` — метод. «Поля раньше конструктора» — просто общепринятый
вариант написания.

**5. В `new Date(...)` формат не передают.** Аргументы — ничего, число
миллисекунд, строка с датой или части по порядку (год, месяц с нуля,
день…). Вид даты задают методы готового экземпляра: `toISOString()`,
`toLocaleDateString()`.

**6. `Reporter` в Playwright — тип, а не класс.** Это `interface`: от него
нельзя наследоваться, ему можно только соответствовать. При запуске его
нет. Playwright вызывает `onBegin`, `onTestEnd`, `onEnd` просто потому,
что такие методы у объекта есть; `implements Reporter` — проверка для нас.

**7. Репортер по умолчанию — `list` (на CI — `dot`), а не `line`.** В `wl-e2e`
умолчание не участвует: список репортеров задан в конфиге явно. Путь
к тесту в команде запуска — необязательный аргумент: без него
запускаются все тесты проекта.
→ [Как репортер подключён](#как-репортер-подключён)

## Прототип своими руками

### У ста объектов — сто копий метода

```ts
const makeReport = (runId: number) => ({
  runId,
  results: [] as string[],
  record(caseId: string) { this.results.push(caseId); },
  summary() { return `run ${this.runId}: ${this.results.length}`; },
});
const reportA = makeReport(924);
const reportB = makeReport(926);
reportA.summary === reportB.summary;   // false
```

Функция возвращает объект с данными и двумя методами. Работает — но у двух
отчётов **разные** функции `summary`: каждый вызов создаёт объект заново,
вместе с методами. А у двух локаторов `click` — одна и та же функция
(урок 12). Как так сделать?

### Методы — в общий объект

```ts
const reportMethods = {
  record(this: Report, caseId: string) { this.results.push(caseId); },
  summary(this: Report) { return `run ${this.runId}: ${this.results.length}`; },
};
const reportC = Object.create(reportMethods) as Report;
reportC.runId = 924;
reportC.results = [];
```

`Object.create(x)` создаёт **пустой** объект, у которого прототипом стоит
`x`. Больше ничего. Данные кладём в сам объект, методы остаются
в `reportMethods` — в одном экземпляре на всех.

`reportC.summary()`: в самом `reportC` метода нет → поиск идёт в прототип →
найден → вызван. А `this` внутри — по-прежнему объект **перед точкой**,
то есть `reportC`. Метод общий, данные у каждого свои. Это вся идея
прототипа.

`this: Report` в скобках метода — не параметр, а подсказка TypeScript,
какого типа будет `this`. При запуске её нет.

Переписать метод прототипа из объекта нельзя: присваивание всегда создаёт
**собственное** свойство, и оно закрывает прототипное — только у этого
объекта.

### Данные в прототипе делят все

```ts
const sharedState = { ...reportMethods, results: [] as string[] };
const reportE = Object.create(sharedState) as Report;
const reportF = Object.create(sharedState) as Report;
reportE.record('C157112');
reportF.summary();   // 'run 926: 1' — хотя в reportF ничего не писали
```

Своего `results` нет ни у одного из двух — оба нашли **один и тот же
массив** в прототипе. Два рана пишут в один список. **Так не делают.**

Почему с методами всё хорошо, а с массивом плохо — зависит от того, что
делают со свойством:

| Действие | Что происходит |
|---|---|
| **прочитать** `obj.limit` | своего нет — берётся из прототипа; все видят одно значение |
| **присвоить** `obj.limit = 5` | у `obj` появляется **своё** свойство; прототип и остальные не тронуты |
| **изменить** `obj.tags.push('x')` | меняется сам массив в прототипе; он один, изменение видят все |

> **Правило.** В прототип — то, что у всех одинаковое: методы. В сам
> объект — то, что у каждого своё: данные.

Пример — [`01-prototype-by-hand.ts`](examples/01-prototype-by-hand.ts).

## Что делает `new`

На каждый отчёт уходит три действия: создать объект с нужным прототипом,
заполнить данными, отдать. Шаг «заполнить» у каждого вида объектов свой,
а первый и третий одинаковые всегда — и язык делает их сам. Это `new`.

`new Date(0)`:

1. создаёт пустой объект и ставит ему прототипом **`Date.prototype`**;
2. вызывает функцию `Date`, подставив этот объект как `this`, — она
   заполняет его данными;
3. возвращает объект.

**Функция-конструктор** — функция, которую вызывают через `new`.
**Экземпляр** — объект, который она создала.

`new` можно написать самим — в четыре строки:

```ts
function LegacyReport(this: Report, runId: number) {
  this.runId = runId;
  this.results = [];
}
LegacyReport.prototype = reportMethods;

const myNew = (Ctor: Function, runId: number) => {
  const fresh = Object.create(Ctor.prototype);   // шаг 1
  Ctor.call(fresh, runId);                       // шаг 2
  return fresh;                                  // шаг 3
};
```

Так писали «классы» до 2015 года, и так до сих пор устроены `Date`,
`Error`, `Array`. TypeScript обычную функцию конструктором не считает
(`new LegacyReport(932)` — `TS7009`), поэтому в проекте `new` всегда стоит
перед встроенным или перед классом.

### Функция, её `prototype` и экземпляр

Самое путаное место темы. Участников трое, а у слова «prototype» два смысла:

```text
LegacyReport ── .prototype ──►  reportMethods  ◄── прототип ── reportH
 (функция)       (свойство)      (объект)                      (экземпляр)
```

- у **функции** есть **свойство** `prototype`: «что поставить прототипом
  тем, кого создадут через `new`»;
- у **экземпляра** есть **прототип** — тот самый объект. Узнать его —
  `Object.getPrototypeOf(экземпляр)`. Свойства `prototype` у экземпляра нет;
- сама функция в цепочку экземпляра **не входит**:
  `reportH → reportMethods → Object.prototype → null`.

Одной строкой: `Object.getPrototypeOf(экземпляр) === Функция.prototype`.

Пример — [`02-what-new-does.ts`](examples/02-what-new-does.ts).

## Класс

```ts
class RunReport {
  runId: number;
  results: string[] = [];
  constructor(runId: number) {
    this.runId = runId;
  }
  record(caseId: string) { this.results.push(caseId); }
  summary() { return `run ${this.runId}: ${this.results.length}`; }
}
const reportI = new RunReport(924);
```

**Класс** — запись, которая в одном месте описывает конструктор и методы
прототипа. Нового механизма в ней нет:

| Руками | В `class` |
|---|---|
| `function LegacyReport(this, runId) { this.runId = runId; }` | `constructor(runId) { this.runId = runId; }` |
| `this.results = []` в функции | `results: string[] = [];` — поле с начальным значением |
| `reportMethods = { record() {…}, summary() {…} }` | методы в теле класса |
| `LegacyReport.prototype = reportMethods` | делается само |
| `myNew(LegacyReport, 931)` | `new RunReport(924)` |

**Где что лежит:**

- `typeof RunReport` — `'function'`: класс и есть функция-конструктор;
- **поля** — собственные свойства экземпляра, заводятся заново для каждого.
  Ловушки с общим массивом нет;
- **методы** — в `RunReport.prototype`, одни на всех экземпляров;
- `runId: number;` без значения — тоже поле: экземпляр получает собственное
  свойство `runId` со значением `undefined` ещё до тела `constructor`,
  а конструктор потом записывает в него число. Поэтому в `Object.keys`
  `runId` стоит первым. Тип TypeScript берёт отсюда же.

```text
pool     →  Array.prototype      →  Object.prototype  →  null
reportI  →  RunReport.prototype  →  Object.prototype  →  null
runId,      record, summary
results
```

`Object.keys(reportI)` и `JSON.stringify(reportI)` показывают только
собственные перечисляемые свойства, то есть поля:
`{"runId":924,"results":[…]}`. Методов в логе нет — они в прототипе.

### Оторванный метод теряет `this`

Правило урока 6: `this` вычисляется **при вызове** — это объект перед
точкой. Нет точки — `this` равен `undefined`.

```ts
const detached = reportI.summary;
detached();                         // Cannot read properties of undefined (reading 'runId')

caseIds.forEach(reportI.record);    // то же самое: forEach получил функцию без объекта
caseIds.forEach((caseId) => reportI.record(caseId));   // так — работает
```

Сам вызов законен, поэтому ошибки «так нельзя» нет. Метод падает на той
строке, где трогает `this`; метод, которому `this` не нужен, отработал бы.

**С `page` и локаторами так же** — это экземпляры классов Playwright:

```text
const { getByRole } = page;
getByRole('button', { name: 'Book Yoga' });
// → Cannot read properties of undefined (reading 'mainFrame')
```

«Cannot read properties of undefined» из глубины Playwright, когда `page`
на месте, — почти всегда оторванный метод. TypeScript этого не ловит.

Пример — [`03-class.ts`](examples/03-class.ts).

## Свой репортер и `TestRailReporter`

```ts
class MiniReporter {
  private enabled = false;
  private readonly results: string[] = [];
  onBegin() { this.enabled = true; }
  onTestEnd(caseId: string, status: string) {
    if (!this.enabled) return;
    this.results.push(`${caseId} ${status}`);
  }
  onEnd() { return this.results.join(', '); }
}
```

Три метода вызывает Playwright: перед прогоном, после каждого теста,
в конце. Между вызовами репортер **помнит состояние** в полях. Вот зачем
здесь класс, а не три функции: методам нужны общие данные, которые живут
между вызовами, и Playwright нужен один объект, у которого их позвать.

`constructor` в классе нет — поля с `=` заполняются сами. Он нужен, только
когда значения приходят снаружи.

**`private`** — **модификатор доступа**: обратиться к полю можно только
изнутри класса, `mini.enabled` снаружи — `TS2341`. Следит за этим
**только TypeScript**: при запуске поле обычное, `Object.keys(mini)` его
показывает. Настоящая приватность в JavaScript — `#поле`; в проекте её нет.

**`readonly`** — как `const` для поля: присвоить заново нельзя (`TS2540`),
а менять содержимое можно.

```ts
const statuses: string[] = [];
statuses.push('passed');     // можно
// statuses = ['failed'];    // ❌ нельзя — и с readonly-полем так же
```

**`implements X`** — просьба к TypeScript проверить, что класс подходит
под тип `X`. Не наследование: класс ничего от `X` не получает, при запуске
слова нет. Если в типе есть обязательные методы — они обязательны
и в классе.

### Настоящий репортер

`helpers/utils/testrail-reporter.ts` устроен так же, как мини-копия:
девять полей, все `private`, у каждого начальное значение, `constructor`
нет; три метода без `private` — `onBegin`, `onTestEnd`, `onEnd`; ещё
тринадцать `private`-методов — внутренняя кухня.

### Как репортер подключён

Вопрос с занятия. В нашем коде нет строки `new TestRailReporter()` —
`new` делает Playwright. Репортер указан в конфиге **путём к файлу**:

```text
reporter: [
  ['list'],
  ['allure-playwright'],
  ['../../helpers/utils/testrail-reporter.ts'],
  …
],
```

Playwright импортирует файл, берёт `export default` и создаёт экземпляр —
при **каждом** прогоне. Но работает репортер, только если его включили —
флагом `-- --testrail` или переменной `TESTRAIL_ENABLED=true` — и заданы
доступы; иначе печатает одну строку и молчит. Это то самое поле `enabled = false`.

Флаг `--reporter=…` в командной строке **заменяет** весь список из
конфига — с ним TestRail-репортер не запустится вовсе. В `package.json`
репортеров нет: там только сокращения команд.

Пример — [`04-reporter.ts`](examples/04-reporter.ts).

## Что спрашивали на занятии

**«Это как `extends` у классов?»** Да — тот же механизм. `extends` ставит
прототипом одного класса прототип другого; на следующем занятии.

**«Зачем двум объектам общие значения?»** Незачем — это ошибка.
→ [Данные в прототипе](#данные-в-прототипе-делят-все)

**«Класс — это по сути функция?»** Да: `typeof` класса — `'function'`.
Класс — функция-конструктор, записанная вместе с методами прототипа.

**«Почему оторванный метод даёт `undefined`, а не ошибку?»** Потому что
вызвать функцию без объекта можно. `this` в этот момент равен `undefined`,
и падает только строка, которая к нему обращается.

**«Откуда берётся наш репортер?»** → [Как репортер подключён](#как-репортер-подключён)

## Итог занятия

1. Методы объекта лежат в прототипе, данные — в самом объекте. В прототип —
   общее, в объект — своё. Данные в прототипе делят все объекты сразу.
2. `new` делает три шага: создаёт объект с прототипом `F.prototype`,
   вызывает `F` с этим объектом как `this`, возвращает его.
3. У функции — **свойство** `prototype`, у экземпляра — **прототип**. Это
   один и тот же объект, а сама функция в цепочку не входит.
4. `class` — запись того же: `constructor` заполняет `this`, поля —
   собственные свойства экземпляра, методы — в `Класс.prototype`.
5. Оторванный метод теряет `this`: `forEach(obj.method)` падает,
   `forEach((x) => obj.method(x))` — нет. С `page` и локаторами так же.
6. `private`, `readonly`, `implements` существуют только для TypeScript.
7. Класс нужен там, где нескольким методам нужны общие данные между
   вызовами, — как `TestRailReporter`.

## Словарь терминов

| Термин | Что значит |
|--------|------------|
| **функция-конструктор** (constructor) | функция, которую вызывают через `new`. Она заполняет новый объект через `this`. Её свойство `prototype` становится прототипом всех созданных ею объектов. `Date`, `Error`, `Array` — функции-конструкторы |
| **экземпляр** (instance) | объект, созданный через `new`. `new Date(0)` — экземпляр `Date` |
| **класс** (class) | запись, которая в одном месте описывает конструктор и методы прототипа. Нового механизма в ней нет: это функция и её `prototype` |
| **поле класса** (class field) | данные экземпляра, объявленные в теле класса: `results: string[] = [];`. Заводится заново для каждого экземпляра |
| **модификатор доступа** (access modifier) | слово перед полем или методом класса, которое говорит TypeScript, откуда к нему можно обращаться. `private` — только изнутри класса. Работает только при проверке типов |
| **прототип** (prototype) | объект, в котором JavaScript ищет свойство, если его нет в самом объекте. Не путать со **свойством** `prototype` у функции |
| **цепочка прототипов** (prototype chain) | объект → его прототип → прототип прототипа → … → `null`. Первое найденное свойство побеждает |
| **собственное свойство** (own property) | то, что лежит в самом объекте, а не в прототипе. Проверяется `Object.hasOwn(obj, 'имя')` |
