Четыре задания. Первые три — файлы в этой папке, запускаются `node`.
Четвёртое — чтение настоящего кода в `wl-e2e`. **Против стенда ничего
запускать не нужно.**

| № | Файл | Что делаем | Готово, когда |
|---|------|-----------|---------------|
| 1 | [`01-predict-output.ts`](01-predict-output.ts) | Предсказать десять строк вывода про класс и его экземпляры | Прогноз стоит у всех десяти, у несовпавших — объяснение, где лежит свойство |
| 2 | [`02-literal-to-class.ts`](02-literal-to-class.ts) | Переписать счётчик попыток из функции с литералом в класс | Все девять проверок печатают ✅, на вопрос в конце есть ответ |
| 3 | [`03-lost-this.ts`](03-lost-this.ts) | Найти два места, где метод оторван от объекта, и починить | Все три фрагмента печатают ✅, под каждым записано, чему был равен `this` |
| 4 | [`04-read-testrail-reporter.md`](04-read-testrail-reporter.md) | Прочитать `TestRailReporter` по пяти вопросам | Пять ответов вида `файл:строка` и один — словами |

```bash
node lessons/lesson-13/homework/01-predict-output.ts      # запустить любой файл
yarn typecheck:hw13                                        # проверить типы домашки
```

## Как проверять себя

**Задание 1** — прогноз пишется **до** запуска. Угадать строку — не цель;
цель — найти место, где ваша картина расходится с настоящей. Не совпало —
припишите, в каком звене цепочки лежит свойство. Перед заданием стоит
ещё раз посмотреть на схему «функция — её `prototype` — экземпляр»
в [конспекте](../README.md#функция-её-prototype-и-экземпляр): строка 6
именно про неё.

**Задания 2 и 3 проходят `yarn typecheck:hw13` сразу** — и до того, как вы
что-нибудь сделали. Это не недосмотр: потерянный `this` и неправильный
счётчик TypeScript не ловит. Единственный сигнал — `❌` при запуске.

**В задании 3 сломаны два фрагмента из трёх.** Пометка «чинить здесь»
стоит у всех трёх, чтобы не подсказывать, — в одном чинить нечего.

**Задание 4** — отвечайте по коду, а не по памяти о занятии. Номера
строк называйте по своей копии `wl-e2e`: файл меняется, и строки плывут.
