# Задание 2. Три `evaluate` из проекта

`evaluate` — дверь из теста в страницу. В `wl-e2e` её открывают часто:
`.evaluate(` в файлах `.ts` — около 7 900 раз. Задача — понять, **зачем**
каждый раз понадобился браузерный код, если у Playwright есть локаторы.

## Как искать

```bash
cd ~/work/wl-e2e
git grep -n "page.evaluate(" -- 'helpers/*.ts' | head -40
git grep -n "\.evaluate((el" -- 'helpers/*.ts' | head -40
```

Выберите **три** разных случая. Хорошо, если среди них будет хотя бы
один из этих видов:

- выставляют значение полю или списку и отправляют событие
  (`dispatchEvent(new Event(…))`, `trigger('chosen:updated')`);
- читают что-то, чего локатор не даёт: свойство элемента, `window.…`,
  `localStorage`;
- меняют DOM: убирают, прокручивают, добавляют.

## Что написать про каждый

1. Файл и строка.
2. Что код делает со страницей — своими словами, по шагам.
3. Почему этого нельзя (или неудобно) сделать локатором. Подсказки —
   в конспекте: «Формы» (родной сеттер, Chosen), «Размеры, прокрутка,
   координаты» (`dispatchEvent`), «`MutationObserver`».
