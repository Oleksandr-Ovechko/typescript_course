# Задание 3 · Прочитать регулярки проекта

Чтение `wl-e2e`, ничего не запускаем. Ветка — `test-generation`: примеры
из конспекта — по ней, на `draft` части файлов нет. Искать можно и не
переключаясь — `git grep -n "name: /" origin/test-generation`.
Ответы — прямо в этом файле, под каждым пунктом.

## 3.1 Регулярки в локаторах

Найдите в `wl-e2e` три регулярки в `name:` или `hasText:`:

```bash
git grep -n "name: /" | head -50
git grep -n "hasText: /" | head -50
```

Для каждой напишите:

- файл и строку;
- какую подпись хотел найти автор;
- какие **ещё** подписи она найдёт — хотя бы одну, которой там быть
  не должно. Если таких нет — почему (какие якоря, флаги, проверки её
  защищают).

| № | Файл:строка | Регулярка | Задумано | Найдёт ещё |
|---|---|---|---|---|
| 1 | | | | |
| 2 | | | | |
| 3 | | | | |

## 3.2 Одна длинная регулярка по кускам

Найдите в проекте регулярку длиннее 30 символов — **не** из тех, что были
на занятии (не время, не кнопка оплаты, не `script`/`style`, не
`escapeRegExp`). Например:

```bash
git grep -nE "/.{30,}/[gimsuy]*[,;)]" -- '*.ts' | head -50
```

Разберите её так, как в конспекте разобрана кнопка оплаты: кусок →
что он значит. В конце — одна фраза «найдёт строки вида …» и пример
строки, которую она **не** найдёт.

Проверить себя — на [regex101.com](https://regex101.com/), flavor
ECMAScript: панель Explanation справа разбирает шаблон по кускам. Сначала
свой разбор, потом сайт.

**Важно:** если шаблон стоит внутри функции, прочитайте функцию целиком.
Строки до него могут менять текст, который он получит, — как
`toLowerCase()` перед шаблоном времени в `schedule.ts`.
