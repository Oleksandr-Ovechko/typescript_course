## Порядок чтения

01 стоит особняком: это циклы, которыми пишут каждый день, и больше в нём
ничего нет. Если нужно только это — хватит его одного.

02 → 03 → 04 → 05 идут лесенкой. В 02 появляется вопрос «что делает объект
перебираемым», в 03 на него отвечают, в 04 тот же ответ записывают короче,
в 05 — то же самое с промисами. Если в 04 непонятно, откуда взялись `value`
и `done`, вернитесь в 03.

06 — ответы на вопросы, заданные вслух. Если после занятия осталось
«а зачем это вообще, если в проекте генераторов нет», начинать можно с конца
этого файла.

## Чего ждать от вывода

- **`01-loops.ts`**, строки 8 и 9: одна и та же переменная сначала пустая,
  через 30 мс — полная. Так `forEach` с `async` теряет клики.
- **`03-iterator-protocol.ts`**, строка 3: последний элемент отдан, а `done`
  всё ещё `false`. `true` приходит отдельным, четвёртым вызовом.
- **`04-generators.ts`**, строка 8: `ИТОГ` из `return` в спреде
  не появляется. Так и задумано.
- **`04-generators.ts`**, строка 10 печатается после строк 9: `finally`
  срабатывает в момент `break`.
- **`05-async-iteration.ts`** и **`06-asked-during-lesson.ts`**: номера строк
  вывода идут не подряд в коде, а в порядке печати — строка 3 стоит внутри
  генератора и печатается между 2 и 4.
- Номера строк сквозные внутри файла, но **не** совпадают между файлами:
  каждый пример самостоятельный.

## Демонстрации, которых нет в файлах

**`for...in` с деструктуризацией** — TypeScript её не пропускает, поэтому
смотреть в чистом JavaScript:

```bash
node -e "for (const [k, v] in { short: 1 }) console.log(k, v)"
```

Печатает `s h`: разобрали не пару «ключ — значение», а саму строку-ключ.

**Настоящий поток ноды** уже умеет `for await` — в курсе нет типов ноды,
поэтому проверка вынесена в команду:

```bash
node -e "const {Readable}=require('node:stream');console.log(typeof Readable.from(['a'])[Symbol.asyncIterator])"
```

Печатает `function`.

**Бесконечный генератор в спреде** — `[...forever()]` вешает процесс,
поэтому его нет нигде. Бесконечный генератор перебирают только с `break`.

## Строки, которые не должны компилироваться

Пять штук, все помечены `// ❌ TS####`. Раскомментируйте и запустите
`yarn typecheck` — код ошибки должен совпасть с заявленным.

| Где | Код | Что не так |
|---|---|---|
| [`02-iterable-and-array-like.ts`](02-iterable-and-array-like.ts) | `TS2488` | То же самое — спред массивоподобного |
| [`02-iterable-and-array-like.ts`](02-iterable-and-array-like.ts) | `TS2488` | Спред над `NodeList`: в `tsconfig` нет `DOM.Iterable`. Ловит `yarn typecheck` (TypeScript 5.9); редактор на TypeScript 6.0 — нет |
| [`02-iterable-and-array-like.ts`](02-iterable-and-array-like.ts) | `TS2488` | `for...of` над `NodeList` — по той же причине |

Три из пяти — один и тот же код с разными словами: «здесь нет
`Symbol.iterator`». Его стоит запомнить в лицо. Последние два особенно:
в браузере такой код работает, а компилятор проекта его не пропускает —
отсюда больше двух тысяч `Array.from` в `wl-e2e`.
