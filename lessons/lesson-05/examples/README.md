## Чего ждать от вывода

Асинхронные примеры печатаются не в том порядке, в каком написаны, — это и есть
тема урока, а не сбой:

- **`00-corrections.ts`** и **`03-microtasks.ts`** печатают тайминги `t≈…мс`.
  Смотреть надо на них, а не на порядок строк: микрозадача и `setTimeout`
  срабатывают на нулевой миллисекунде, то есть **до** того, как закончилась
  пауза, стоящая выше по коду.
- **`05-forgotten-await.ts`**, строка 6 — печатает пустой массив `[]`. Так
  и должно быть: `forEach` уже вернул управление, а колбэки ещё не доработали.
- **`06-many-promises.ts`** идёт около секунды — там настоящие паузы по 100
  и 200 мс. Остальные файлы отрабатывают мгновенно.
- Номера строк в выводе сквозные внутри файла, но **не** совпадают с номерами
  между файлами: каждый пример самостоятельный.

## Две демонстрации, которых нет в файлах

Обе убивают процесс, поэтому они вынесены в комментарии
[`03-microtasks.ts`](03-microtasks.ts) и запускаются отдельной командой:

```bash
node -e "
async function angry() { throw new Error('внутри async'); }
angry();
console.log('этот лог напечатался');
"

node -e "Promise.reject(new Error('отказ')).finally(() => console.log('finally отработал'));"
```

В обоих случаях код досчитывает до конца, печатает свою строку — и только потом
процесс умирает. Ошибка приходит **после** того, как всё «прошло успешно».

## Строки, которые не должны компилироваться

В этом уроке она одна — в [`00-corrections.ts`](00-corrections.ts),
помечена `// ❌ TS2339`. Раскомментируйте и запустите `yarn typecheck`:
код ошибки должен совпасть с заявленным.

Их мало не случайно. Главная мысль урока
[«забытый `await` не ловит никто»](../README.md#забытый-await) как раз о том,
что компилятору тут нечего сказать: `click()` без `await` — совершенно законный
TypeScript.
