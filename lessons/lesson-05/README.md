# Урок 5. Замыкание, объекты, `this`

Всё держится на трёх мыслях:

1. функция помнит место, где её **написали**: оттуда она берёт имена,
   даже когда её вызывают совсем в другом месте. Это замыкание;
2. в переменной лежит не объект, а **ссылка** на него: присваивание
   и `{ ...obj }` копируют ссылки, а не сами объекты;
3. `this` берётся из места, где функцию **вызвали**, — ровно наоборот
   первому.

**Прошли:** повторение, замыкание, объекты и из методов с `this` — всё,
кроме `call`, `apply` и `bind`. Они в [уроке 6](#дальше-урок-6).

Несколько мест ниже сформулированы точнее, чем прозвучали на занятии.
Если запомнилось иначе — верьте конспекту и проверьте запуском.

Запись занятия — в чате группы. [Домашка](homework/README.md) ·
[примеры](examples/README.md).

## Повторение: где видно имя

Подробно — в [уроке 4](../lesson-04/README.md#где-видно-имя). Коротко:

- `let` и `const` живут в ближайших `{}`. Изнутри видно внешнее,
  снаружи внутреннее — нет. Своё имя в блоке **затеняет** внешнее.
- `var` не знает границ блока и цикла, только границы функции. После
  `for (var loopVar = 1; loopVar <= 3; loopVar++) {}` в `loopVar` лежит
  `4`: на этом значении условие `<= 3` перестало выполняться.
- **Поднятие**: до выполнения движок заводит все имена — в начале
  **своей области** (функции или блока), а не всей программы.
  `function` — сразу с телом, её можно вызвать выше. `let` и `const` до
  своей строки в мёртвой зоне — `ReferenceError`. `var` до своей строки —
  `undefined`.

## Вложенные функции и замыкание

Пример: [`01-closure.ts`](examples/01-closure.ts). Замыкание — не отдельная
конструкция языка. Оно получается само из двух правил: «изнутри видно
внешнее» и «функция помнит, где её написали».

### Функция внутри функции

```ts
function greetGroup(greeting: string): string {
  function greetOne(name: string): string {
    return `${greeting}, ${name}`;
  }
  return `${greetOne('Ann')}; ${greetOne('Bob')}`;
}
console.log(greetGroup('Привет')); // Привет, Ann; Привет, Bob
```

Тело функции — тоже блок. Поэтому `greetOne` берёт `greeting` у внешней
функции, а свой у неё только `name`. Снаружи `greetOne` не видно
(`TS2304`), как любое имя из блока. Так пишут помощника, который нужен
только одной функции.

### Лексическое окружение

При **каждом вызове** функции движок заводит служебный объект —
**лексическое окружение**. В нём параметры и переменные этого вызова
и ссылка на **внешнее** окружение — то, где функция написана.

```text
окружение innerLevel   town: 'Киев'        — нашли здесь
       │ внешнее
окружение outerLevel   country: 'Украина'  — здесь нет, поднялись, нашли
       │ внешнее
модуль                 planet: 'Земля'     — поднялись ещё раз
       │ внешнее
globalThis             Math, console
       │
не нашли нигде → ReferenceError
```

Имя ищется в своём окружении, потом во внешнем — и так до глобального
объекта. Цепочка ведёт **только наружу**, поэтому снаружи внутреннего
не видно. Вызвали функцию десять раз — завели десять окружений.

### Функция помнит место, где её написали

```ts
const label = 'снаружи';
function makePrinter(): () => string {
  const label = 'внутри';
  return () => label;
}
const printLabel = makePrinter();
console.log(printLabel(), label); // внутри снаружи
```

| Часть | Что значит |
|---|---|
| `(): () => string` | `makePrinter` ничего не принимает и **возвращает функцию**, которая вернёт строку |
| `return () => label` | вернули не строку, а саму стрелку, без вызова |

Стрелку **написали** внутри `makePrinter`. Ссылку на внешнее окружение
она получила в момент **создания**, а не вызова: это окружение вызова
`makePrinter`, где `label` — `'внутри'`. Сама `label` лежит не в окружении
стрелки, а в этом внешнем, и стрелка находит её по ссылке. Откуда стрелку
потом вызвали, роли не играет.

> **Функция помнит место, где её НАПИСАЛИ, — не где ВЫЗВАЛИ.**

### Замыкание

```ts
function makeCounter(): () => number {
  let count = 0;
  return () => {
    count = count + 1;
    return count;
  };
}
const firstCounter = makeCounter();
const secondCounter = makeCounter();
console.log(firstCounter(), firstCounter(), firstCounter(), secondCounter()); // 1 2 3 1
```

`makeCounter()` закончилась, а её окружение живо: на него ссылается
стрелка. Пока жива стрелка, жива и `count`. Это и есть **замыкание** —
функция вместе с окружением места, где её создали.

`makeCounter` вызвали дважды — два окружения, в каждом своя `count`.
Отсюда `1 2 3` у первого счётчика и `1` у второго: второй вызов ничего
не «выкидывает», он просто завёл новое окружение. Снаружи до `count`
не добраться — это настоящая приватная переменная.

С параметром то же самое: `makeGreeter('Hello')` и `makeGreeter('Hola')`
дают две функции, у каждой свой `greeting`.

### Замыкание ничего не копирует

Частая неверная картинка: «функция сложила переменные к себе
в окружение и дальше работает со своими». На деле у неё только
**ссылка** на окружение места создания. Переменные она читает оттуда
при каждом вызове.

Проверка — две функции из **одного** вызова:

```ts
function makeTally(): { add: () => void; read: () => number } {
  let total = 0;
  return {
    add: () => {
      total = total + 1;
    },
    read: () => total,
  };
}
const tally = makeTally();
tally.add();
tally.add();
console.log(tally.read()); // 2
```

Если бы каждая функция скопировала `total` к себе, `read()` вернула бы
`0`. Она возвращает `2`: обе смотрят в одно окружение и видят одну
переменную.

### Держит переменную, а не значение

```ts
let mood = 'до';
const readMood = (): string => mood;
console.log(readMood()); // до
mood = 'после';
console.log(readMood()); // после
```

`readMood` не сохранила текст `'до'`, она читает `mood` в момент
**вызова**. Это правило JavaScript, в других языках бывает иначе.

То же в цикле:

```ts
const varReaders: (() => number)[] = [];
for (var varIndex = 0; varIndex < 3; varIndex++) {
  varReaders.push(() => varIndex);
}
console.log(varReaders[0](), varReaders[1](), varReaders[2]()); // 3 3 3
```

| Часть | Что значит |
|---|---|
| `(() => number)[]` | массив функций: каждая ничего не принимает и возвращает число |
| `varReaders.push(() => varIndex)` | положить в массив **новую функцию**. Она создаётся, но **не вызывается** |
| `varReaders[0]()` | `[0]` — взять первую функцию, `()` — вызвать её |

- Пока шёл цикл, ни одна функция не запускалась.
- `var` — **одна** переменная на весь цикл, все три функции держат её.
- Цикл остановился, когда `varIndex` стала `3`: `3 < 3` ложно. Функции
  вызваны после этого — все читают `3`.

С `let` вместо `var` вывод — `0 1 2`: `let` заводит **новую** переменную
на каждый проход, у каждой функции своя. Поэтому в циклах пишут `let`.

> **На каком числе встаёт цикл, решает условие.** У
> `for (var i = 1; i <= 3; i++)` после цикла в `i` будет `4`: `i++`
> срабатывает после тела, и цикл заканчивается, когда `4 <= 3` — ложь.
> Функции из такого цикла вернут `4 4 4`.

## Объекты

Пример: [`02-objects.ts`](examples/02-objects.ts).

### Литерал и свойства

```ts
const book = {
  title: 'Дюна',
  year: 1965,
  'in stock': true,
};
const width = 3;
const height = 4;
const size = { width, height }; // { width: 3, height: 4 }
```

| Часть | Что значит |
|---|---|
| `{ … }` справа от `=` | **литерал объекта**: создаёт новый объект прямо здесь |
| `title: 'Дюна'` | **свойство**: ключ и значение. Значение — любое, в том числе другой объект |
| `'in stock': true` | ключ с пробелом пишется в кавычках |
| `{ width, height }` | короткая запись: то же, что `{ width: width, height: height }` |

Создают объект почти всегда литералом. `new Object()` делает то же,
и так почти не пишут.

**Не всё в JavaScript — объект.** Семь примитивов из урока 2 (строки,
числа, `true`/`false`, `null`, `undefined` и другие) — не объекты:
`typeof 'abc'` — `string`, и завести у строки своё свойство нельзя.

### Обращение к свойствам

| Запись | Когда |
|---|---|
| `book.title` | обычный случай: ключ известен и без пробелов |
| `book['in stock']` | ключ с пробелом или другими особыми символами |
| `book[fieldName]` | ключ лежит в переменной. Без кавычек: берётся **значение** `fieldName` |

Свойство читают и меняют одной записью: `book.year = 1966`. Ключи
объекта — **строки**: ключ-число превращается в строку,
`Object.keys({ 1: 'один' })` → `['1']`.

Несуществующее свойство: `book.price` TypeScript не пропустит (`TS2339`),
а JavaScript не упадёт и отдаст `undefined`.

### Вычисляемые свойства

```ts
function makePair(key: string, value: number): Record<string, number> {
  return { [key]: value };
}
const prefix = 'max';
const limits = { [`${prefix}Age`]: 99, [prefix + 'Size']: 10 };
// makePair('age', 30) → { age: 30 }, limits → { maxAge: 99, maxSize: 10 }
```

| Часть | Что значит |
|---|---|
| `{ [key]: value }` | ключом станет **значение** переменной `key`, а не слово `key` |
| `` [`${prefix}Age`] `` | в скобках любое выражение: оно вычислится при создании объекта |
| `Record<string, number>` | тип: объект, где ключи — строки, а значения — числа |

Без скобок ключ — просто слово: `{ key: 'red', [key]: 'blue' }` при
`key = 'color'` даёт `{ key: 'red', color: 'blue' }`.

### Опциональная цепочка `?.`

```ts
const owner: { name: string; address?: { city: string } } = { name: 'Ann' };
console.log(owner.address?.city);                      // undefined
console.log(owner.address?.city ?? 'город не указан'); // город не указан
```

| Часть | Что значит |
|---|---|
| `address?:` в типе | свойство **необязательное**: его может не быть |
| `owner.address?.city` | если слева `null` или `undefined`, дальше не идём, результат — `undefined` |
| `?? 'город не указан'` | запасное значение только вместо `null` и `undefined` — урок 3 |

Без `?.` строка `owner.address.city` упадёт: у `undefined` нельзя
прочитать `.city`. Кто об этом скажет и когда — разные вещи:

- **TypeScript** — заранее, ещё до запуска: `TS18048: 'owner.address' is
  possibly 'undefined'`;
- **JavaScript** ничего заранее не проверяет. Он выполнит все строки до
  этой и упадёт только на ней: `TypeError: Cannot read properties of
  undefined (reading 'city')`.

`?.` смотрит только на `null` и `undefined`: `0` и `''` для него обычные
значения. `??` — не «логическое и» и не «или»: `&&` на `undefined` вернул
бы `undefined`, а `||` заменил бы и `''`, и `0`. Цепочка может быть любой
длины: `a?.b?.c?.d`.

### Ссылка

```ts
const original = { score: 1 };
const sameObject = original;
sameObject.score = 2;
const twin = { score: 2 };
console.log(original.score, original === sameObject, original === twin); // 2 true false
```

```text
original ───┐
            ├──► { score: 2 }
sameObject ─┘
twin ──────────► { score: 2 }   другой объект → === даёт false
```

- Переменная хранит не объект, а **ссылку** на него.
  `const sameObject = original` второй объект не создаёт: теперь
  на один объект указывают две переменные.
- `===` у объектов сравнивает ссылки, а не содержимое.
- `const` запрещает переприсвоить **переменную** (`original = {…}` —
  `TS2588`). Менять сам объект он не мешает, поэтому `book.year = 1966`
  проходит.

### Копирование

```ts
const profile = { name: 'Ann', contacts: { phone: '111' } };
const shallowCopy = { ...profile, name: 'Bob' };
shallowCopy.contacts.phone = '222';
console.log(profile.name, shallowCopy.name, profile.contacts.phone); // Ann Bob 222

const deepCopy = structuredClone(profile);
deepCopy.contacts.phone = '333';
console.log(profile.contacts.phone, deepCopy.contacts.phone); // 222 333
```

| Часть | Что значит |
|---|---|
| `{ ...profile }` | новый объект, в него разложены свойства `profile` |
| `, name: 'Bob'` после `...` | кто записан позже, тот и останется |
| `structuredClone(profile)` | полная копия со всеми вложенными объектами |

`{ ...profile }` — **поверхностная копия**: скопирован только верхний
уровень. `name` у копии свой. А в `contacts` лежит объект, значит
скопировалась **ссылка** на него, и телефон изменился у обоих.

```text
profile ────► { name: 'Ann', contacts ─┐ }
                                       ├──► { phone: '222' }
shallowCopy ► { name: 'Bob', contacts ─┘ }
```

Чтобы поменять вложенное и не тронуть оригинал, копируют и вложенный
уровень: `{ ...profile, contacts: { ...profile.contacts, phone: '444' } }`.

`structuredClone` не умеет копировать функции: на объекте, где в свойстве
лежит функция, он упадёт с `DataCloneError`. Ещё один способ — через
`JSON` — в [«Сверх плана»](#сверх-плана).

## Методы объекта и `this`

Пример: [`03-methods-and-this.ts`](examples/03-methods-and-this.ts).
Этот механизм противоположен замыканию: замыкание — из места
**написания**, `this` — из места **вызова**.

### Метод и `this`

```ts
const user = {
  name: 'Ann',
  greet(): string {
    return `Привет, я ${this.name}`;
  },
};
console.log(user.greet()); // Привет, я Ann
```

| Часть | Что значит |
|---|---|
| `greet(): string { … }` внутри объекта | **метод** — функция в свойстве объекта. Короткая запись для `greet: function (): string { … }` |
| `this` | объект, у которого метод **вызвали**: здесь `user` |
| `user.greet()` | вызов метода: слева от точки — объект |

`this` — не «свой объект» метода, а тот, у которого метод вызвали. Ниже
видно, почему это разные вещи. Просто `name` без `this.` искалось бы как
обычная переменная снаружи объекта.

### Метод меняет свой объект

```ts
const wallet = {
  balance: 100,
  add(amount: number): number {
    this.balance = this.balance + amount;
    return this.balance;
  },
};
console.log(wallet.add(50), wallet.balance); // 150 150
```

Слева от точки `wallet`, значит `this.balance` — это `wallet.balance`.

### Метода может не быть

```ts
const quiet: { say?(): string } = {};
const loud: { say?(): string } = {
  say(): string {
    return 'Привет';
  },
};
console.log(quiet.say?.(), loud.say?.()); // undefined Привет
```

Метод — обычное свойство, значит может быть необязательным
(`say?(): string`). `quiet.say?.()`: метод есть — вызвать, нет — результат
`undefined`, и вызова не будет. Без `?.` TypeScript не даст: `TS2722`.

### `this` вычисляется при вызове

```ts
function introduce(this: { name: string }): string {
  return `меня зовут ${this.name}`;
}
const cat = { name: 'Мурка', introduce: introduce };
const dog = { name: 'Бобик', introduce: introduce };
console.log(cat.introduce(), dog.introduce(), cat.introduce === dog.introduce);
// меня зовут Мурка меня зовут Бобик true
```

| Часть | Что значит |
|---|---|
| `this: { name: string }` первым в скобках | **не параметр**: при вызове его не передают. Только для TypeScript — «`this` здесь будет объектом с `name`». В JavaScript от него ничего не остаётся: `introduce.length` — `0` |
| `introduce: introduce` | положить функцию `introduce` в свойство с тем же именем |

Функция одна — сравнение даёт `true`. Результат разный, потому что
`this` берётся не из функции, а из **вызова**: что слева от точки.

> **`this` — то, что СЛЕВА ОТ ТОЧКИ в момент ВЫЗОВА.**

Передать объект аргументом нельзя: `introduce(cat)` — `TS2554: Expected
0 arguments, but got 1`. Вызвать без объекта — тоже: `introduce()` —
`TS2684`.

### Метод у копии

```ts
const walletCopy = { ...wallet };
walletCopy.add(10);
console.log(wallet.balance, walletCopy.balance, wallet.add === walletCopy.add); // 150 160 true
```

`...` копирует свойства: число `balance` — значением, потому что это
примитив, а функцию `add` — ссылкой. Литерал тут ни при чём: вложенный
объект, даже записанный литералом, тоже скопировался бы ссылкой.
Функция одна, а `this` у неё — тот, у кого вызвали: изменился баланс
копии.

### Вызвали без объекта — `this` потерялся

```ts
const pet = { name: 'Ann', greet(): string { return 'Привет, я ' + this.name; } };
const detached = pet.greet;
detached(); // TypeError: Cannot read properties of undefined (reading 'name')
```

`const detached = pet.greet` — функцию просто положили в переменную.
Но при вызове точки нет, и брать `this` неоткуда. В модуле (наши файлы)
`this` тогда `undefined`, и чтение `.name` падает.

**TypeScript этого не ловит** — упадёт только запуск. Поэтому в примере
этой строки нет, а проверить её можно в терминале:

```bash
node --input-type=module -e "const pet = { name: 'Ann', greet() { return 'Привет, я ' + this.name; } }; const detached = pet.greet; console.log(detached());"
node -e "const pet = { name: 'Ann', greet() { return 'Привет, я ' + this.name; } }; const detached = pet.greet; console.log(detached());"
```

Первая строка — модуль: `TypeError`. Вторая — старый скрипт: там вместо
`this` подставляется глобальный объект, падения нет, печатается
`Привет, я undefined`. Тихо и хуже.

Наши файлы — модули, поэтому их `function` и `var` верхнего уровня
в `globalThis` не попадают. Это бывает только в старых скриптах:

```bash
node -e "var fromVar = 1; function fromFunction() {} console.log(globalThis.fromVar, typeof globalThis.fromFunction)"
# 1 function
node --input-type=module -e "var fromVar = 1; function fromFunction() {} console.log(globalThis.fromVar, typeof globalThis.fromFunction)"
# undefined undefined
```

Так `this` теряют на практике: метод передают **колбэком**, и вызывает
его уже не объект.

### У стрелки своего `this` нет

```ts
function repeatTimes(times: number, action: (round: number) => void): void {
  for (let round = 1; round <= times; round++) {
    action(round);
  }
}
const team = {
  title: 'Команда',
  members: ['Ann', 'Bob'],
  listMembers(): string[] {
    const lines: string[] = [];
    repeatTimes(this.members.length, (round) => {
      lines.push(`${this.title}: ${this.members[round - 1]}`);
    });
    return lines;
  },
};
console.log(team.listMembers()); // [ 'Команда: Ann', 'Команда: Bob' ]
```

Самый объёмный пример урока — по шагам:

1. `team.listMembers()` — слева от точки `team`, значит `this`
   в `listMembers` — `team`.
2. `listMembers` заводит пустой `lines` и вызывает `repeatTimes(2, стрелка)`.
   Стрелку только **передали**, она ещё не выполнялась.
3. `repeatTimes` дважды вызывает `action(round)` — без точки.
4. У стрелки своего `this` нет. Она берёт его снаружи, по цепочке
   окружений: из вызова `listMembers`, а там это `team`. Отсюда
   `this.title` и `this.members`.
5. `listMembers` возвращает заполненный `lines`.

```text
метод — обычный:        listMembers() { … }    this = team (слева от точки)
колбэк — стрелка:       (round) => this.title   своего this нет → берёт у метода
стрелка ВМЕСТО метода:  listMembers: () => …    this снаружи объекта → не работает
```

Стрелка берёт `this` **вызова** `listMembers`, а не «объект навсегда».
Оторвите сам метод — `const list = team.listMembers; list()` — и упадёт
уже `this.members`. Если вместо стрелки передать обычную `function`,
у неё будет свой `this`, и в этом вызове пустой: TypeScript подчеркнёт
`TS2683`.

## Сверх плана

Пример: [`04-asked-during-lesson.ts`](examples/04-asked-during-lesson.ts).
Прозвучало на занятии, в план не входило.

- **Магазин яблок.** `appleShop()` заводит склад `apples` и возвращает
  функцию «привезти яблоки». Каждый вызов `appleShop()` — новый магазин
  со своим складом, как счётчики. На занятии внутри магазина было своё
  `foo`, и переназначение внешнего `foo` ни на что не повлияло. Функция
  ищет `foo` по цепочке: сначала в окружении своего магазина — и находит
  там своё, **затеняющее** внешнее, так что до внешнего поиск не доходит.
  А живо это окружение после вызова `appleShop()` благодаря замыканию.
  Без своего `foo` поиск дошёл бы до внешнего, и функция увидела бы новое
  значение — как `readMood`.
- **Новое свойство.** JavaScript даёт дописать `obj.b = 4` когда угодно.
  TypeScript — нет (`TS2339`): тип объекта выведен из литерала, `b` в нём
  нет. Если свойство появится позже, его объявляют необязательным:
  `{ a: number; b?: number }`.
- **`const` и объект.** Свойство менять можно, переприсвоить переменную —
  нет (`TS2588`). С `let` можно и то, и другое.
- **Копия через `JSON`.** `JSON.parse(JSON.stringify(obj))` — глубокая
  копия, но только простых данных. Методы и свойства со значением
  `undefined` пропадают, `Date` становится строкой. На маленьких простых
  объектах это быстрее `structuredClone`.
- **`private`** бывает у свойств классов — это урок про ООП.

## Итог урока

1. Вызов функции заводит лексическое окружение. Имя ищется в нём, потом
   во внешнем, до глобального объекта.
2. Функция помнит окружение места, где её **написали**. Пока она жива,
   живо и окружение — это замыкание. Переменные она не копирует, а читает
   по ссылке при каждом вызове: `var` в цикле — одна на всех.
3. В переменной лежит ссылка на объект. `===` сравнивает ссылки,
   `{ ...obj }` копирует только верхний уровень, `structuredClone` — всё.
   `?.` не падает на `null` и `undefined`.
4. `this` — то, что слева от точки в момент **вызова**. Нет точки —
   `this` потерян, и TypeScript этого не ловит. У стрелки своего `this`
   нет, она берёт внешний.

## Словарь терминов

| Термин | Что значит |
|--------|------------|
| **лексическое окружение** (lexical environment) | служебный объект, который заводится при каждом вызове функции: её параметры и переменные плюс ссылка на внешнее окружение — там, где функция написана |
| **замыкание** (closure) | функция вместе с окружением места, где её создали. Пока жива функция, живы и переменные этого окружения. Переменные не копируются: функция читает их по ссылке |
| **контекст** (`this`) | объект, на который указывает `this` внутри вызова: то, что стоит слева от точки. В функции не хранится, определяется при каждом вызове |
| **вычисляемое свойство** (computed property) | свойство, ключ которого записан в `[ ]` и вычисляется при создании объекта: `{ [key]: value }` |
| **опциональная цепочка** (optional chaining) | `?.`: читает дальше, только если слева не `null` и не `undefined`. Иначе результат — `undefined` |
| **ссылка** (reference) | то, что лежит в переменной вместо самого объекта. Присваивание копирует ссылку, а объект остаётся один |
| **поверхностная копия** (shallow copy) | новый объект, в который скопирован только верхний уровень: `{ ...obj }`. Вложенные объекты остаются общими |

Знакомые слова: **метод** — функция в свойстве объекта; **свойство** —
пара «ключ — значение» в объекте; **литерал объекта** — запись `{ … }`,
которая создаёт объект; **затенение** — своё имя во внутреннем блоке
закрывает такое же внешнее.
