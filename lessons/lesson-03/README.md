## Словарь терминов

Восемь слов, которые были выложены до занятия. Оставлены здесь без изменений —
как краткая справка.

### Стрелочная функция

*arrow function*

Короткая запись функции: параметры, стрелка `=>`, тело. Если тело — одно выражение,
фигурные скобки и `return` не нужны.

```ts
const double = (n: number): number => n * 2;
```

Отличается от `function` не только формой: стрелочная — это обычная переменная,
поэтому вызвать её выше по файлу, чем она объявлена, нельзя.

### Колбэк

*callback*

Функция, которую передают **в другую функцию как аргумент**, чтобы та вызвала её
сама, когда посчитает нужным. Вы её пишете, но не вызываете — вызывает принимающая
сторона.

```ts
[1, 2, 3].map((n) => n * 2);   // (n) => n * 2 — колбэк, его вызовет map
```

В тесте `test.describe('имя', () => { ... })` второй аргумент — тоже колбэк.

### Модуль

Файл, который что-то отдаёт наружу или берёт снаружи. Всё, что объявлено внутри
модуля, по умолчанию видно только ему — соседние файлы об этом не знают.

### Экспорт

*export*

Пометка «это имя можно брать из моего файла».

```ts
export const DEFAULT_TIMEOUT = 15000;
export function buildProfileUrl(uid: string): string { ... }
```

Без `export` имя остаётся внутренним.

### Импорт

*import*

Взять имя из другого файла.

```ts
import { DEFAULT_TIMEOUT, buildProfileUrl } from './wl-helpers';
```

Путь с точки (`./`, `../`) означает «наш файл в проекте», без точки
(`@playwright/test`) — «пакет из библиотеки».

### Деструктуризация

*destructuring*

Способ вытащить поля объекта или элементы массива в отдельные переменные одной
строкой.

```ts
const { who, host } = session;   // из объекта — по имени поля
const [first, second] = sizes;   // из массива — по позиции
```

Работает и в параметрах функции — именно так устроено `async ({ page }) => {...}`
в каждом тесте.

### Спред

*spread*, `...`

«Разложить содержимое сюда». Делает **новую** копию, а не ссылку на старый объект.

```ts
const copy = { ...base };                      // копия
const changed = { ...base, embedMode: 'inline' }; // копия с изменением
const all = [...smoke, 'regression'];          // склейка массивов
```

Копия поверхностная: вложенные объекты остаются общими с оригиналом.

### Фикстура

*fixture*

Готовый объект, который Playwright создаёт для теста сам и передаёт в колбэк:
`page` — вкладка браузера, есть ещё `browser`, `context` и другие. В фигурных
скобках просят только то, что нужно этому тесту.

```ts
test('название', async ({ page }) => { ... });
```

## Уточнения к занятию

### Спред копирует поверхностно

Самое важное. На уроке спред был поставлен в один ряд с полным копированием —
это не совсем так. Спред делает **новый** объект, но только верхний уровень: всё
*вложенное* остаётся общим с оригиналом.

```ts
const config = { locale: 'en', retry: { count: 3 } };
const copy = { ...config };

copy === config              // false — объект действительно новый
copy.retry === config.retry  // true  — а внутренность общая

config.retry.count = 99;
copy.retry.count             // 99 — поменялось и здесь
```

Уровней копирования три, и их легко перепутать:

| Запись | Что получилось |
|---|---|
| `const a = obj;` | Не копия вообще — второе имя для того же объекта |
| `const b = { ...obj };` | Поверхностная копия — новый верхний уровень, общая внутренность |
| `const c = structuredClone(obj);` | Глубокая копия — всё целиком |

### `export default` в проекте всё-таки есть

Прозвучало «у нас нигде не используется». На `draft` — 15 файлов, и все одного
сорта: `playwright.config.ts` (и его варианты `.e2e`, `.probes`, `.setup`),
`globalSetup.ts`, `global-teardown.ts`, `testrail-reporter.ts`.

Правило узнавания: `export default` стоит там, где файл целиком существует ради
одной вещи, которую забирает инструмент. В тестах и хелперах — действительно
только именованные экспорты.

### Переменные поднимаются — но трогать их нельзя

Прозвучало, что `const` и `let` «не поднимаются». Поднимаются; просто до строки
объявления лежат в мёртвой зоне. Видно по тексту ошибки:

```
ReferenceError: Cannot access 'x' before initialization   ← поднялась, недоступна
ReferenceError: x is not defined                          ← если бы не поднималась
```

`tsc` на таком коде даёт `TS2448` и `TS2454`. Подробно — на уроке 4.

### `??` называется оператором нулевого слияния

На уроке он несколько раз был назван «логическим И». Логическое И — это `&&`,
отдельный оператор, который мы не разбирали. Пара, которую сравнивали,
называется «`||` и `??`». Смысл был объяснён правильно — сломано только название,
но именно оно уйдёт в голову вместе со смыслом.

```ts
0 || 100   // 100 — 0 это falsy
0 ?? 100   // 0   — 0 это не null и не undefined
0 && 100   // 0   — третий оператор, на уроке не разбирался
```

### `find` возвращает `T | undefined`

Прозвучало «`find` возвращает единственное правильное значение». А если ничего
не нашлось — возвращает `undefined`, и тип это знает:

```ts
const firstFree = spots.find((spot) => spot === 0);
const exact: number = firstFree;   // ❌ TS2322: 'number | undefined' → 'number'
```

Ради таких значений `?.` и `??` из начала урока и существуют:

```ts
const safe = spots.find((s) => s === 777) ?? -1;
```

### Мелочи

- Стрелочная функция отличается от `function` не только формой записи: у неё нет
  своего `this` и `arguments`, и её нельзя вызвать через `new`
  (`TypeError: A is not a constructor`). Для чтения тестов пока не мешает —
  вернёмся к этому вместе с `this`.
- Playwright по умолчанию берёт **половину логических ядер**, а не один поток.
  В `wl-e2e` число задано явно: `workers: 8`, `retries: 1`.
- `workerIndex` считается **с нуля**.

## Значения, которых может не быть

Долг с прошлого урока. Обе конструкции существуют ради одного: значения,
которого может не быть.

**`?.` — optional chaining.** Читается как «если слева `null` или `undefined` —
остановись и верни `undefined`; иначе иди дальше». Позволяет обращаться к полям,
про которые неизвестно, существуют они или нет.

**`??` — оператор нулевого слияния.** «Если слева `null` или `undefined` —
возьми правое». Ровно два значения, больше никаких.

**`||` — логическое или.** Смотрит шире: на все восемь falsy-значений.

```
false · 0 · -0 · 0n · '' · null · undefined · NaN
```

Список закрытый. Пустой массив, пустой объект и строка `'0'` — truthy.

Расходятся `||` и `??` ровно там, где ноль или пустая строка — законный ответ,
а не «значения нет»:

```ts
const spots: number | undefined = 0;

spots || 10   // 10 ← ноль сочли за «пусто». Обычно это баг
spots ?? 10   // 0  ← ноль свободных мест это настоящий ответ
```

Поэтому для чисел и строк по умолчанию берут `??`, а `||` — осознанно, когда
пустая строка действительно должна считаться отсутствием. Настоящий пример
такого случая, `helpers/monolith/client-web/book-now-page.ts:59`:

```ts
const catName = category.querySelector('.js-service-category')?.textContent?.trim() ?? '';
```

Читается как цепочка отказов: элемента может не быть → `?.`; текста у элемента
может не быть → второй `?.`; если после всего вышло `null` или `undefined` →
пустая строка. Обе конструкции встречаются в проекте постоянно: `?.` — 699 раз,
`??` — 508.

Смешивать `||` и `??` без скобок компилятор запрещает — приоритет не угадывается:

```ts
primary ?? secondary || fallback     // ❌ TS5076
(primary ?? secondary) || fallback   // ✅ выбор сделан явно
```

Пример: [`01-optional-and-nullish.ts`](examples/01-optional-and-nullish.ts)

## Три способа объявить функцию

```ts
function addDeclared(a: number, b: number): number { return a + b; }        // объявление
const addExpressed = function (a: number, b: number): number { return a + b; }; // выражение
const addArrow = (a: number, b: number): number => a + b;                   // стрелочная
```

Результат у всех трёх одинаковый. Разница — в двух местах.

**Первое: подъём.** Объявление функции поднимается целиком, и вызвать её можно
выше по файлу, чем она написана. Два других способа — обычные переменные:
до строки объявления они существуют, но недоступны.

```ts
addDeclared(1, 1);   // ✅ работает
addArrow(1, 1);      // ❌ TS2448: used before its declaration
const addArrow = (a: number, b: number): number => a + b;
```

**Второе: стрелочная — не просто короткая запись.** У неё нет своего `this`
и `arguments`, и её нельзя вызвать через `new`. Для чтения тестов это пока
не мешает, но «отличается только формой» — неправда.

**Короткая форма.** Если тело — одно выражение, фигурные скобки и `return`
не нужны. Отсюда ловушка: объект пишется теми же фигурными скобками, что и тело
функции, и без круглых скобок компилятор прочитает `{` как начало тела.

```ts
const makeBad = (id: string) => { id };      // вернёт undefined
const makeGood = (id: string) => ({ id });   // вернёт { id: '...' }
```

**`void`** — «эта функция ничего не возвращает», и компилятор следит за
обещанием. Но если `void` стоит в типе *колбэка*, запрета нет: возвращённое
значение просто выбрасывается. Иначе `[1, 2].forEach((n) => n)` не
компилировался бы ни у кого.

Пример: [`02-functions.ts`](examples/02-functions.ts)

## Функция как значение и колбэк

В JavaScript функция — такое же значение, как число или строка. Её можно
положить в переменную, в поле объекта, в массив — и передать в другую функцию.
Последнее и есть колбэк.

```ts
const operations: Array<(a: number) => number> = [
  (a) => a + 1,
  (a) => a - 1,
  (a) => a * a,
];

for (const operation of operations) {
  console.log(operation(5));   // 6, 4, 25
}
```

Тип читается так: массив, элемент — функция, принимающая число и возвращающая
число. Угловые скобки здесь — те же дженерики из урока 2.

**`map`, `filter`, `find`** устроены одинаково: проходят по каждому элементу
и на каждом вызывают ваш колбэк. Разница — что они делают с результатом.

| Метод | Что возвращает |
|---|---|
| `map` | **Новый** массив той же длины, исходный не тронут |
| `filter` | Новый массив только из тех элементов, на которых колбэк вернул truthy |
| `find` | Первый подходящий элемент — **или `undefined`**, если такого нет |

**Своя функция с колбэком.** Место, где чаще всего путаются: колбэк объявлен
с параметром, а откуда в него приходит значение — не видно.

```ts
function repeat(times: number, callback: (index: number) => void): void {
  for (let i = 0; i < times; i += 1) {
    callback(i);          // ← вот отсюда и приходит
  }
}

repeat(3, (index) => console.log('проход №', index + 1));
```

Вы колбэк **пишете**, но не вызываете. Вызывает принимающая сторона — столько
раз, сколько сочтёт нужным. Если непонятно, вынесите колбэк в отдельную
переменную: связь становится видна.

В тесте всё то же самое:

```ts
test.describe('название', () => { ... });
//              ^^^^^^^^   ^^^^^^^^^^^^
//              1-й арг    2-й аргумент — колбэк
```

Playwright вызовет его сам, когда дойдёт до этого теста.

Пример: [`03-functions-as-values.ts`](examples/03-functions-as-values.ts)

## Модули, импорт и экспорт

Модуль — файл, который что-то отдаёт наружу или берёт снаружи. Всё, что
объявлено внутри, по умолчанию видно только ему.

```ts
export const DEFAULT_TIMEOUT = 15000;          // именованный экспорт
export default { workers: 8 };                 // экспорт по умолчанию, один на файл

import { DEFAULT_TIMEOUT } from './helper';    // именованный импорт
import { login as loginFromHelper } from './helper';  // с переименованием
import runConfig from './helper';              // импорт по умолчанию
```

**`as` нужен чаще, чем кажется.** В `wl-e2e` `clickSaveButton` экспортируется
из **четырёх** разных хелперов — импортировать два одноимённых имени без
переименования нельзя. `as` в импортах встречается в десяти файлах.

**Форма пути** решает, где искать:

| Путь | Где ищем |
|---|---|
| `'./C154005.helpers'` | Файл рядом, в этой же папке |
| `'../../../helpers/widgets-wl-ui-helper'` | Файл выше по дереву |
| `'@playwright/test'` | `node_modules` |
| `'wl-e2e-automation-helpers/monolith/...'` | `node_modules` — наш пакет монорепы |

Начинается с точки — файл; не начинается — `node_modules`. Собачка тут ни при
чём: `@` — часть имени пакета, а не признак места. Локальный пакет монорепы
лежит в `node_modules` ровно так же — Yarn кладёт туда симлинк на `helpers/`,
это видно командой `ls -la node_modules | grep wl-e2e`. Разбор —
в [`modules/04-modules.ts`](examples/modules/04-modules.ts).

**Изоляция.** Два модуля могут объявить функцию с одинаковым именем и не
конфликтовать — в `wl-e2e` так и есть. А файл без единого `import`/`export`
модулем не является: его объявления попадают в общую область видимости, отсюда
`TS2393` и `TS2451`. Ровно поэтому в примерах курса стоит пустой `export {};`.

Пример: [`modules/04-modules.ts`](examples/modules/04-modules.ts) — двумя
файлами, с настоящим импортом. У папки свой `tsconfig.json`,
[почему — в README примеров](examples/#папка-modules).

## Деструктуризация и спред

**Деструктуризация** — вытащить поля объекта или элементы массива в отдельные
переменные одной строкой.

```ts
const { who, env } = session;              // из объекта — по имени поля
const { token: customToken } = session;    // с переименованием
const [smallest, medium] = sizes;          // из массива — по позиции
const [first, , third] = sizes;            // пропустить второй
const [head, ...tail] = sizes;             // остаток в массив
```

Для объекта имена обязаны совпадать с полями; для массива — любые, потому что
там нет имён, только позиции.

**Деструктуризация параметров** — та самая конструкция из каждого теста:

```ts
function runShort({ page, retries }: RunOptions): string { ... }

test.beforeEach(async ({ page }, testInfo) => { ... });
//                     ^^^^^^^^  ^^^^^^^^
//                     1-й параметр,       2-й параметр,
//                     разобранный         обычный
```

Фигурные скобки относятся **только к первому параметру**, а не ко всей
сигнатуре. Playwright передаёт первым аргументом объект со всеми фикстурами —
в скобках просят нужные этому тесту.

**Спред** (`...`) — «разложи сюда всё содержимое».

```ts
const copy = { ...base };                     // копия
const changed = { ...base, locale: 'ua' };    // копия с изменением
const all = [...smoke, 'regression'];         // склейка массивов
```

Порядок важен: что написано позже, то и побеждает. `{ ...base, locale: 'ua' }`
даст `'ua'`, а `{ locale: 'ua', ...base }` — значение из `base`.

И главное: **копия поверхностная** — см. [уточнения](#спред-копирует-поверхностно).

Пример: [`05-destructuring-spread.ts`](examples/05-destructuring-spread.ts)

## `async` и `await` — коротко

Разобрали вскользь, полностью — на уроке 5.

`await` перед вызовом функции: «дождись, пока это закончится, и дай результат».
`async` перед объявлением функции: «внутри есть `await`, значит и саму функцию
надо ждать».

Почти всё в Playwright требует ожидания — клик, переход, проверка, — отсюда
`await` почти в каждой строке. Не ставят его там, где ждать нечего: например,
функция читает переменную окружения и сразу возвращает результат.

Это укороченная запись работы с промисами. Сами промисы — тема урока 5.
