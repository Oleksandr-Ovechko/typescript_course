## Сравнения

Пример: [`01-comparisons.ts`](examples/01-comparisons.ts).

### Сравнение даёт `true` или `false`

```ts
console.log('1)', 2 < 2, 2 <= 2, 2 > 1, 2 >= 3, 2 !== 2);   // 1) false true true false false
```

| Оператор | Читается |
|---|---|
| `<` · `>` | меньше · больше |
| `<=` · `>=` | меньше или равно · больше или равно |
| `===` · `!==` | равно · не равно, без приведения типов (урок 2) |

Любое сравнение даёт `boolean`: ровно `true` или `false`. У «не равно»
тоже две формы: строгая `!==` и нестрогая `!=`. Пишут строгую, по той же
причине, что `===`.

### Строки сравниваются по кодам символов

```ts
console.log('2)', 'apple' < 'banana', 'Book' < 'book', 'Zebra' < 'apple');   // 2) true true true
console.log('4)', 'ё' > 'я', 'ёлка' > 'яблоко');                             // 4) true true
```

У каждого символа есть номер (код). Две строки сравниваются символ за
символом слева направо, по этим номерам. Для латиницы номера идут по
алфавиту, но **все заглавные стоят раньше всех строчных**: `'Zebra'`
«меньше» `'apple'`. Это не словарный порядок: в кириллице `ё` стоит
после `я`.

Сравнить текст без учёта регистра — привести обе стороны к одному
регистру: `title.toLowerCase() === 'book'`.

### Строка-число против числа

```ts
console.log('5)', '10' < '9', 10 < 9, Number('10') < 9);   // 5) true false false
```

Со страницы цифры приходят строкой. Две строки `<` сравнивает по символам:
`'1'` раньше `'9'`, значит, `'10'` «меньше». **Числа сравнивать только
после `Number(…)`**.

### `'0'` истинное, и всё же `0 == '0'`

```ts
console.log('6)', Boolean(0), Boolean('0'), Boolean('false'), Boolean(' '));   // 6) false true true true
```

Ложных значений восемь (урок 2), `'0'` среди них нет: непустая строка
истинна, что бы в ней ни было написано.

А теперь сравним ноль со строкой `'0'` через `==`. TypeScript такую строку
не пропустит (`TS2367`: сравнение числа со строкой выглядит ненамеренным),
поэтому — в терминале, где типы не проверяются:

```bash
node -e "console.log(0 == '0', '1e1' == 10, '10' == '1e1')"
# → true true false
```

`==` приводит **строку к числу**, а не число к строке, и неважно,
с какой стороны стоит строка: `'0'` → `0`, значения равны. Ложное
«равно» истинному. Проверка направления — `'1e1'`, запись числа 10:
`'1e1' == 10` — правда, а две строки `'10' == '1e1'` — ложь. Если бы `==`
превращал число в строку, вышло бы наоборот.

**Правило — всегда `===`.**

## Логика: `&&`, `||`, `!`

Пример: [`02-logic.ts`](examples/02-logic.ts).

### Два условия в одном

В тесте решение часто зависит от двух вещей сразу: «диалог не открылся
**и** попытка последняя».

```ts
console.log('1)', true && false, true || false, !true);        // 1) false true false
console.log('2)', 2 > 1 && 'Book' < 'book', 2 > 3 || 2 > 1);   // 2) true true
```

| Оператор | Название | `true`, когда |
|---|---|---|
| `a && b` | логическое И | обе стороны `true` |
| `a \|\| b` | логическое ИЛИ | хотя бы одна `true` |
| `!a` | логическое НЕ | `a` — `false` |

Порядок такой: сначала `!`, потом сравнения, потом `&&`, потом `||`.
Поэтому в строке 2 скобки не нужны: `2 > 1 && …` — это `(2 > 1) && …`.
А сравнение, которое нужно перевернуть, берут в скобки: `!(total > 10)`.

### `||` и `&&` возвращают значение

```ts
const typedName: string = '';
const savedName: string = 'Ann';
const otherName: string = 'Bob';
console.log('4)', typedName || 'гость', savedName || 'гость');      // 4) гость Ann
console.log('5)', savedName && otherName, savedName || otherName);  // 5) Bob Ann

const timeoutMs: number = 0;
console.log('7)', timeoutMs || 30_000, timeoutMs && 'не ноль');     // 7) 30000 0
```

> 🔤 **Сокращённое вычисление** (short-circuit) — `&&` и `||` идут слева
> направо и останавливаются, как только ответ известен. Возвращают они
> **тот операнд, на котором остановились**, а не `true`/`false`.

| Запись | Вернёт |
|---|---|
| `a \|\| b` | первое **истинное**: `a`, если оно truthy, иначе `b` |
| `a && b` | первое **ложное**: `a`, если оно falsy, иначе `b` |

Если ложных нет, `&&` дойдёт до конца и вернёт последний операнд:
`'Ann' && 'Bob'` — это `'Bob'`. Если истинных нет, `||` вернёт последний.

`typedName || 'гость'` — классическое запасное значение: пустая строка
ложная, подставился `'гость'`. **Но ноль тоже ложный**: `timeoutMs || 30_000`
заменил таймаут `0` («не ждать») на 30 секунд. Для этого случая есть `??`
(ниже, в ветвлениях).

`30_000` — то же число, что `30000`: подчёркивание стоит только для глаз.
Работает и в дробных (`0.000_5`), и в шестнадцатеричных (`0xff_ff`).

**Как это выглядит в рабочем проекте** — так выбирают окружение для теста:

```ts
const APP_ENV = process.env.APP_ENV || 'demo';
```

`process.env.APP_ENV` — переменная окружения, с которой запустили тест.
Не задали — `undefined`, и берётся `'demo'`.

## Ветвления

Примеры: [`03-branches.ts`](examples/03-branches.ts),
[`04-nullish.ts`](examples/04-nullish.ts).

### `if`, `else if`, `else`

```ts
const statusCode: number = 404;
if (statusCode < 300) {
  console.log('не напечатается: успех');
} else if (statusCode < 500) {
  console.log('1) ошибка клиента:', statusCode);   // 1) ошибка клиента: 404
} else {
  console.log('не напечатается: ошибка сервера');
}
```

Условия проверяются **сверху вниз**, и выполняется **первая** ветка, где
условие `true`. Остальные даже не проверяются. Поэтому порядок решает:

```ts
const okCode: number = 250;
if (okCode < 500) {
  console.log('2) ошибка клиента?', okCode);   // 2) ошибка клиента? 250
} else if (okCode < 300) {
  console.log('не напечатается: успех');
}
```

Всё, что меньше 300, меньше и 500, поэтому до «успеха» код не дойдёт
никогда. Широкое условие — ниже узкого.

В скобках не обязательно сравнение: `if (typedName)` приводит значение
к `boolean` по правилам ложных значений. Тело из одной инструкции можно
записать без фигурных скобок — `if (x) console.log(x);` — но читать так
труднее, и в проектах скобки обычно ставят всегда.

### Тернарник и его цепочка

`if` выбирает, какой кусок **выполнить**. А часто нужно выбрать **значение**.

```ts
console.log('5)', statusCode < 400 ? 'прошёл' : 'упал');   // 5) упал
const statusText =
  statusCode < 300 ? 'успех'
  : statusCode < 500 ? 'ошибка клиента'
  : 'ошибка сервера';
console.log('6)', statusText);                            // 6) ошибка клиента
```

| Часть | Что значит |
|---|---|
| `условие ? A : B` | если `true` — результат `A`, если `false` — `B` |

Тернарник — **выражение**: у него есть значение, поэтому он стоит справа
от `=` или внутри `console.log(…)`. `if` — **инструкция**, значения у неё нет.

Цепочка `a ? x : b ? y : z` читается «если `a` — `x`, иначе если `b` — `y`,
иначе `z`» и проверяется сверху вниз, как `else if`. Длинную цепочку
переносят: каждое условие на своей строке, двоеточие — в начале строки.
Она же через `if` — в примере, результат тот же, строк вдвое больше.
Условий больше двух или в ветке нужно что-то кроме значения — пишите `if`.

### `switch`

Когда одно значение сравнивают с точными вариантами, `else if` выходит
длинным.

```ts
const delayUnit: string = 'Week(s)';
let delayDays = 0;
switch (delayUnit) {
  case 'Day(s)':
    delayDays = 1;
    break;
  case 'Week(s)':
    delayDays = 7;
    break;
  default:
    console.log('неизвестная единица:', delayUnit);
}
console.log('8)', delayUnit, '→', delayDays);   // 8) Week(s) → 7
```

| Часть | Что значит |
|---|---|
| `switch (x)` | сравнить `x` с каждым `case` по очереди, через `===` |
| `case 'Week(s)':` | метка: если совпало, выполнять **отсюда** |
| `break` | выйти из `switch` |
| `default:` | ни один `case` не совпал. Необязателен; стоит последним — `break` после него не нужен |

### `switch` без `break`

`case` — не отдельный блок, а **точка входа**. Где остановиться, говорит
только `break`.

```ts
const unit: string = 'Week(s)';
let days = 0;
switch (unit) {
  case 'Day(s)':
    days = days + 1;
  case 'Week(s)':
    days = days + 7;
  case 'Month(s)':
    days = days + 30;
    break;
  default:
    days = -1;
}
console.log('10)', days);   // 10) 37
```

Вошли в `'Week(s)'`, прибавили 7, а `break` нет — выполнение пошло
**сквозь** следующую метку, прибавило 30 и остановилось на `break`.
До `default` не дошли. По-английски это fall-through, «проваливание».
**TypeScript этого не ловит.** Ловит **линтер** — программа, которая ищет
подозрительные места в коде (самый распространённый — ESLint, правило
`no-fallthrough`).

### `??` — запасное значение, только если значения нет

**Запасное значение** — то, что берут, когда своего нет: имя не ввели —
«гость», таймаут не задали — 30 секунд. Весь вопрос в том, что считать
«своего нет». Для `||` — любое ложное, в том числе `0` и `''`. Для `??` —
только `null` и `undefined`.

```ts
const timeoutMs: number = 0;
console.log('1)', timeoutMs || 30_000, timeoutMs ?? 30_000);   // 1) 30000 0

const retries: number = 0;
const label: string | null = null;
console.log('2)', retries ?? 3, retries || 3, label ?? 'нет'); // 2) 0 3 нет
```

`a ?? b` возвращает `a`, если это не `null` и не `undefined`, иначе `b`.
Ноль, пустая строка и `false` — это значения, и `??` их сохраняет, даже
если они ложные: `false ?? true` — это `false`.

| Слева | `x \|\| запас` | `x ?? запас` |
|---|---|---|
| `0`, `''`, `false` | запас | `x` |
| `null`, `undefined` | запас | запас |
| остальное | `x` | `x` |

`string | null` — тип «строка или `null`». Так пишут значение, которого
может не быть. Без `| null` TypeScript не даст положить `null`
в переменную типа `string` (`TS2322`). `|` в типе — не логическое ИЛИ, а
**объединение** типов. Подробно такие типы — в уроке про union.

Запасных значений бывает несколько — «из командной строки, иначе из
конфига, иначе по умолчанию»:

```ts
const timeoutFromCli: number | undefined = undefined;
const timeoutFromConfig: number | undefined = 10_000;
console.log('5)', timeoutFromCli ?? timeoutFromConfig ?? 30_000);   // 5) 10000
```

Цепочка идёт слева направо и отдаёт первое значение, которое не `null`
и не `undefined`. Был бы в конфиге `0` — цепочка остановилась бы на нём.

## Массив и циклы

Пример: [`05-arrays-and-loops.ts`](examples/05-arrays-and-loops.ts).

### Массив: длина, край, `push`

```ts
const caseIds = ['C157112', 'C22041', 'C19877'];
console.log('1)', caseIds.length, caseIds[0], caseIds[caseIds.length - 1], caseIds[99]);
// 1) 3 C157112 C19877 undefined
caseIds.push('C21532');
console.log('3)', caseIds.length);   // 3) 4
```

- `length` — свойство, без скобок: сколько элементов в массиве.
- Индексы считаются с нуля, поэтому последний элемент — `length - 1`,
  а `caseIds[caseIds.length]` — уже за краем.
- За краем массива не ошибка, а `undefined`. Массив от такого чтения
  не растёт. **Для TypeScript `caseIds[99]` — строка**, а на деле там
  `undefined`: здесь он не поможет.
- `push` дописывает элемент в конец. Массив объявлен через `const`
  и всё равно меняется: `const` запрещает положить под имя **другой**
  массив, но не менять этот же.

### `for` со счётчиком

```ts
for (let index = 0; index < caseIds.length; index++) {
  console.log('4)', index, caseIds[index]);
}
// 4) 0 C157112
// 4) 1 C22041
// 4) 2 C19877
// 4) 3 C21532
```

Одно выполнение тела называется **проходом**. В скобках — **заголовок**
из трёх частей, и выполняются они в **разное** время:

| Часть | Когда |
|---|---|
| `let index = 0` | один раз, до первого прохода |
| `index < caseIds.length` | **перед** каждым проходом; если `false` — цикл закончен |
| `index++` | **после** каждого прохода; то же, что `index = index + 1` (`index--` — минус один) |

- `<=` вместо `<` — **на один проход больше**: при `index === 4` условие
  `4 <= 4` даёт `true`, и цикл читает индекс за краем. Ошибки нет, есть
  тихий `undefined`.
- Если условие ложно с первой же проверки — например, `index > caseIds.length`
  при `index = 0`, — тело не выполнится **ни разу**: цикл сразу закончится.
  Бесконечным он от этого не станет.

### `break` и потолок

Самый частый цикл в тестах — не обход списка, а повтор: попробовать,
и если получилось — **перестать**. Только что созданный клиент появляется
в поиске не сразу. Вместо настоящего поиска — заранее записанные ответы:

```ts
const searchHits: boolean[] = [false, true, true];
let clientFound = false;
for (let attempt = 1; attempt <= 3; attempt++) {
  clientFound = searchHits[attempt - 1];
  console.log('7) попытка', attempt, '→', clientFound);
  if (clientFound) {
    break;
  }
}
console.log('8) найден:', clientFound);
// 7) попытка 1 → false
// 7) попытка 2 → true
// 8) найден: true
```

`break` — выйти из цикла **сейчас**, не дожидаясь условия в заголовке.
Третьей попытки не было.

> 🔤 **Потолок** (cap) — предел числа попыток или времени, после которого
> цикл сдаётся. Здесь он равен трём: `attempt <= 3`.

Потолок нужен любому самописному повтору. Без потолка тест не падает,
а **зависает** и умирает по общему таймауту с бесполезным сообщением.

**Как это выглядит в рабочем проекте** — тот же повтор в настоящем тесте:

```ts
for (let attempt = 0; attempt < 3; attempt++) {
  await searchInput.fill(clientData);
  await searchInput.press('Enter');
  if (await resultItem.waitFor({ state: 'visible', timeout: 5_000 })
        .then(() => true).catch(() => false)) {
    break;
  }
}
```

Наш `searchHits[attempt - 1]` здесь записан как «результат показался
за 5 секунд?». Как это устроено (`await`, `waitFor`) — уроки про
асинхронность и Playwright. Всё остальное уже знакомо.

### `while` — когда счётчика нет

В `for` заранее известно, сколько проходов максимум. А если крутиться
надо «пока не случится»?

```ts
const statusFeed: string[] = ['loading', 'loading', 'ready'];
let pollNo = 0;
while (statusFeed[pollNo] !== 'ready' && pollNo < 10) {
  pollNo++;
}
console.log('9) ready на опросе №', pollNo + 1);   // 9) ready на опросе № 3
```

`while (условие)` проверяет условие, и если оно `true`, выполняет тело
и проверяет снова. Останавливается по условию — так же, как `for`
по средней части заголовка; `break` внутри `while` работает так же,
как в `for`. `pollNo < 10` — потолок. Без него, если `ready` не придёт
никогда, цикл не кончится: терминал повиснет, остановить его — `Ctrl+C`.
Поэтому в тестах чаще пишут `for`: счётчик, условие и потолок там стоят
в одной строке.

### `for...of` и `continue`

В `for` ради элемента пришлось заводить счётчик, условие и шаг. Если нужен
только сам элемент, есть запись короче:

```ts
const queue = ['C1', 'skip', 'C2', 'stop', 'C3'];
const taken: string[] = [];
for (const item of queue) {
  if (item === 'skip') {
    continue;
  }
  if (item === 'stop') {
    break;
  }
  taken.push(item);
}
console.log('10)', taken.join(','));   // 10) C1,C2
```

В `for (const x of список)` на каждом проходе в `x` лежит очередной
**элемент**. Индекса нет, поэтому выйти за край нельзя. `continue`
заканчивает **этот** проход и переходит к следующему, а `break` обрывает
весь цикл.

- `continue` и `break` — не особенность `for...of`: они работают
  **в любом цикле** — `for`, `while`, `do...while`, `for...in`.
- `for...of` ходит не только по массивам, но и по всему, что можно
  перебрать, — например, по строке, символ за символом:
  `for (const letter of 'C19')` даст `C`, `1`, `9`. Как это устроено —
  урок про итераторы.

### `for...in` — ключи, а не элементы

```ts
const names = ['x', 'y'];
for (const key in names) {
  console.log('13)', typeof key, key, key + 1);
}
// 13) string 0 01
// 13) string 1 11
```

Похожая запись `for...in` даёт не элементы, а **ключи**: у объекта это
имена полей, у массива — индексы. И ключи всегда **строки**: `'0'`, `'1'`.
Поэтому `key + 1` склеивает, а не складывает. По массиву ходят через `of`;
`for...in` — для объектов, до них дойдём в уроке про объекты.

## Сверх плана

Пример: [`06-asked-during-lesson.ts`](examples/06-asked-during-lesson.ts).
Прозвучало на занятии, в план не входило.

- **`pop`** — обратный `push`: убирает последний элемент и возвращает его.
  Массив меняется.
- **`do { … } while (условие)`** — как `while`, но условие проверяется
  **после** прохода, поэтому тело выполнится хотя бы раз, даже если
  условие ложно с самого начала.
- **`for (;;)`** — все три части заголовка необязательны. Без условия
  цикл бесконечен, выйти — только через `break`. Пишут так редко.
- **Зачем сравнивать строки на «больше-меньше»** — чаще всего для
  сортировки. Метод `sort` без аргументов сортирует строки по кодам
  символов (заглавные раньше строчных). Свой порядок задают функцией
  сравнения, и она должна вернуть **число**: меньше нуля — `a` раньше `b`,
  больше нуля — `b` раньше `a`, ноль — порядок не важен. Для текста такое
  число даёт `a.localeCompare(b)`. Вернуть `a < b` (то есть `true`/`false`)
  — частая ошибка: «меньше нуля» не придёт никогда, и массив
  не отсортируется. TypeScript её ловит (`TS2345`). Функции и стрелочная
  запись `(a, b) => …` — урок 4.
- **Тип «или» для значения, которого пока нет**: `let durationMs: number | null = null;`
  — сейчас `null`, потом посчитаем и положим число.
- **Port forwarding в VS Code**: локальный сервер можно открыть другим
  людям по ссылке — вкладка **Ports**, видимость **Public**. Так на
  занятии работали тесты.

## Итог

1. Сравнения дают `true`/`false`. Две строки `<` сравнивает по кодам
   символов, поэтому `'10' < '9'`. `==` приводит строку к числу, и
   `0 == '0'` — правда; пишите `===`.
2. `||` отдаёт первое истинное, `&&` — первое ложное. `x || запас`
   заменяет и `0`, и `''`; `x ?? запас` — только `null` и `undefined`.
3. `if`/`else if` выполняет первую верную ветку сверху вниз, тернарник
   выбирает **значение**. `switch` без `break` проваливается дальше,
   и TypeScript молчит.
4. За краем массива — `undefined`, не ошибка. У каждого повтора должен
   быть **потолок**. `break` выходит из цикла, `continue` — из прохода,
   в любом цикле. По элементам ходят через `for...of`, `for...in` даёт
   ключи-строки.

## Словарь терминов

| Термин | Что значит |
|--------|------------|
| **сокращённое вычисление** (short-circuit) | `&&` и `\|\|` идут слева направо и останавливаются, как только ответ известен. Возвращают тот операнд, на котором остановились: пустая строка `\|\| 'гость'` → `'гость'` |
| **потолок** (cap) | предел числа попыток или времени, после которого повтор сдаётся. Без потолка тест не падает, а зависает |

Знакомые слова, которые звучали: **ветвление** — выбор, какой кусок кода
выполнить; **цикл** — повтор куска кода; **проход** (итерация) — одно
выполнение тела цикла; **заголовок цикла** — часть `for` в скобках;
**запасное значение** — то, что берут, когда своего нет; **операнд** —
значение по одну из сторон оператора (в `a && b` операнды — `a` и `b`).
