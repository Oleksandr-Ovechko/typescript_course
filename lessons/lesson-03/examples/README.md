## Папка `modules/`

Пример про импорт и экспорт лежит отдельно, двумя файлами: только так импорт
получается настоящий, а не описанный на словах.

У папки **свой `tsconfig.json`** — из-за настоящего конфликта, который в самом
`wl-e2e` не проявляется:

| Как написать импорт | `tsc` | `node` |
|---|:---:|:---:|
| `from './04-modules-helper'` | ✅ | ❌ `ERR_MODULE_NOT_FOUND` |
| `from './04-modules-helper.ts'` | ❌ `TS5097` | ✅ |

Формы, которая устраивает обоих, нет. В `wl-e2e` импорты пишутся без расширения
и работают, потому что тесты запускает Playwright: он прогоняет файлы через
babel со своим разрешением путей, а не через `node`. Мы запускаем файлы
напрямую — значит, расширение обязательно, а компилятору нужно об этом сказать
отдельной настройкой.

```bash
node lessons/lesson-03/examples/modules/04-modules.ts   # запустить
yarn typecheck:modules                                  # проверить типы
```

## Как читать пометки в коде

`// ❌ TS####` перед закомментированной строкой — код, который **не должен**
компилироваться, и код ошибки, которую вы увидите. Раскомментируйте, посмотрите
на подчёркивание в редакторе, верните обратно. Это часть упражнения.

`export {};` в конце файла — техническая строка. Без неё файл считается
глобальным скриптом, и его объявления столкнутся с соседними примерами:
`TS2393` для функций, `TS2451` для `const` и `let`. В `modules/04-modules.ts`
её нет — там уже есть настоящие импорты, и файл является модулем без неё.
