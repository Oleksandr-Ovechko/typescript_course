# Урок 1. ИИ-инструменты в работе · введение в проект `wl-e2e`

Первое занятие курса. Сначала — инструмент, с которым вы будете работать
каждый день: Claude Code в терминале. Как он видит проект, кто разрешает
его действия, что он помнит и почему его ответ нужно проверять. Потом —
сам `wl-e2e`: из каких частей он собран, как его поставить и как через
него проходит один тест — от команды до клика.

Это **план и словарь**: они выложены до занятия. Полный конспект,
примеры и домашка появятся здесь после урока.

## До занятия

1. **Установить Claude Code** и войти при первом запуске
   ([официальная инструкция](https://code.claude.com/docs/en/quickstart)):

   ```bash
   # macOS, Linux, WSL
   curl -fsSL https://claude.ai/install.sh | bash
   ```

   ```powershell
   # Windows PowerShell
   irm https://claude.ai/install.ps1 | iex
   ```

   Проверка: `claude --version` печатает номер версии.
2. **Склонировать этот репозиторий** и `wl-e2e`, в `wl-e2e`
   переключиться на ветку `test-generation`. Ставить `wl-e2e` заранее
   не нужно — установку разберём на занятии по шагам.

## План

1. **Как устроен курс** — какие материалы когда появляются и как ими
   пользоваться.
2. **Claude Code: первый разговор** — запуск в папке проекта, что видно
   в окне, пять клавиш на первые минуты, режимы разрешений и режим
   планирования. Ответ Claude — гипотеза.
3. **Контекст** — почему с каждым сообщением уходит весь разговор,
   что такое сжатие, `/context`, `/compact`, `/clear`; `CLAUDE.md`;
   модель, усилие и расход; как учиться вместе с Claude.
4. **Claude внутри `wl-e2e`** — четыре `CLAUDE.md`, команды, агенты,
   MCP-серверы и хуки проекта.
5. **Проект: карта и установка** — пять воркспейсов, что лежит
   в корне, что делает каждая команда установки, окружения.
6. **Путь одного теста** — `--list`, `yarn case` и `--env`, через какие
   файлы проходит тест.
7. *Резерв:* первый файл на TypeScript — `node` его запускает,
   `yarn typecheck` проверяет.

## Словарь терминов

| Термин | Что значит |
|--------|------------|
| **режим разрешений** (permission mode) | правило, по которому Claude Code решает, выполнить действие сразу или сначала спросить вас. Переключение — `Shift+Tab`; **режим планирования** (`plan`) ничего не меняет, а только предлагает план |
| **контекст** (context window) | всё, что модель видит, отвечая на очередное сообщение: разговор, прочитанные файлы, вывод команд, инструкции проекта. У контекста есть предел; когда он близко, разговор сжимается в пересказ |
| **`CLAUDE.md`** | файл с инструкциями для Claude, который сам загружается в начале каждого разговора: как устроен проект, какие команды, какие правила |
| **воркспейс** (workspace) | папка со своим `package.json` внутри общего репозитория. В `wl-e2e` их пять: корень, `helpers` и три проекта тестов |
| **окружение** | бизнес WL, на котором идёт тест, и всё, чтобы туда попасть: адрес, ID бизнеса, учётки. Файлы `config/.env.<имя>` (в git) и `config/.env.<имя>.secure` (пароли, не в git) |
| **спек** (spec) | файл с тестами, `*.spec.ts`. Имя — по номеру кейса в TestRail: `C19633.spec.ts` |
| **хелпер** (helper) | функция, которая делает один шаг теста: «войти», «открыть расписание». Спек состоит из вызовов хелперов |

Встретятся на занятии, но запоминать пока не нужно — узнаете в лицо:
**агент** (отдельный Claude со своим заданием), **команда** (`/имя` —
готовый сценарий), **MCP-сервер** (дополнительный инструмент Claude,
например живой браузер), **хук** (скрипт, который может запретить
действие).
