# Урок 1. ИИ-инструменты в работе · как устроен JS/TS-проект · первый файл на TypeScript

Первое занятие курса. Сначала — инструмент, с которым вы будете работать
каждый день: Claude Code в терминале. Как он видит проект, кто разрешает
его действия, что он помнит и почему его ответ нужно проверять. Потом —
из чего состоит любой проект на JavaScript: какой Node ему нужен, какие
пакеты, какие команды. Разберём это на репозитории курса и посмотрим, как
то же самое выглядит в большом рабочем проекте. И в конце — первый файл
на TypeScript.

Это **план и словарь**: они выложены до занятия. Полный конспект,
примеры и домашка появятся здесь после урока.

## До занятия

1. **Установить Claude Code** и войти при первом запуске
   ([официальная инструкция](https://code.claude.com/docs/en/quickstart)):

   ```bash
   # macOS, Linux, WSL
   curl -fsSL https://claude.ai/install.sh | bash
   ```

   ```powershell
   # Windows PowerShell
   irm https://claude.ai/install.ps1 | iex
   ```

   Проверка: `claude --version` печатает номер версии.
2. **Поставить репозиторий курса** — по разделу «Установка»
   в [`README.md`](../../README.md) курса. Проверка: `yarn typecheck`
   заканчивается строкой `Done in …`. Что делает каждая команда
   установки — разберём на занятии.

Больше ничего ставить не нужно.

## План

1. **Как устроен курс** — какие материалы когда появляются и как ими
   пользоваться.
2. **Claude Code: первый разговор** — запуск в папке проекта, что видно
   в окне, пять клавиш на первые минуты, режимы разрешений и режим
   планирования. Ответ Claude — гипотеза.
3. **Контекст** — почему с каждым сообщением уходит весь разговор,
   что такое сжатие, `/context`, `/compact`, `/clear`; `CLAUDE.md`
   и что ещё бывает в `.claude/`; модель, усилие и расход; как учиться
   вместе с Claude.
4. **Как устроен JS/TS-проект** — `.nvmrc` и версия Node, `package.json`,
   пакеты и зависимости, `yarn install`, `node_modules`, скрипты.
5. **То же в настоящем проекте** — показ на рабочем проекте: те же файлы,
   только больше, и один настоящий тест на Playwright.
6. **Первый файл на TypeScript** — `node` его запускает,
   `yarn typecheck` проверяет.

## Словарь терминов

| Термин | Что значит |
|--------|------------|
| **режим разрешений** (permission mode) | правило, по которому Claude Code решает, выполнить действие сразу или сначала спросить вас. Переключение — `Shift+Tab`; **режим планирования** (`plan`) ничего не меняет, а только предлагает план |
| **контекст** (context window) | всё, что модель видит, отвечая на очередное сообщение: разговор, прочитанные файлы, вывод команд, инструкции проекта. У контекста есть предел; когда он близко, разговор сжимается в пересказ |
| **`CLAUDE.md`** | файл с инструкциями для Claude, который сам загружается в начале каждого разговора: как устроен проект, какие команды, какие правила |
| **пакет** (package) | готовая программа или библиотека на JavaScript из общего реестра (npm). Проект её не пишет, а ставит. Пакет, без которого проект не работает, — его **зависимость** |
| **`package.json`** | файл в корне проекта на JavaScript: как проект называется, какие пакеты ему нужны и каких версий, какие команды у него есть |
| **скрипт** (script) | именованная команда из раздела `"scripts"` в `package.json`; запускается `yarn <имя>` — например, `yarn typecheck` |
| **спек** (spec) | файл с тестами, имя кончается на `.spec.ts` |

Встретятся на занятии, но запоминать пока не нужно — узнаете в лицо:
**команда** (`/имя` — готовый сценарий для Claude), **агент** (отдельный
Claude со своим заданием), **MCP-сервер** (дополнительный инструмент
Claude, например живой браузер), **хук** (скрипт, который может запретить
действие Claude), **Node** (программа, которая выполняет JavaScript вне
браузера), **`nvm`** (менеджер версий Node), **хелпер** (готовая функция,
которая делает один шаг теста: «войти», «открыть страницу»).
