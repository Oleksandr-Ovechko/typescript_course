# Урок 1. Проект, транспиляция, встроенные типы

Конспект того, что **реально** было на уроке (план был шире — часть перенесена).

## Часть 1. Знакомство с проектом wl-e2e (~35 мин)

| Что | Зачем |
|-----|-------|
| `CLAUDE.md` в корне и в каждом проекте | входная точка и для человека, и для Клода; читается всегда, переживает компактизацию контекста |
| `.claude/commands/` | скиллы — повторяемые действия через `/команду` |
| `.claude/knowledge/page-facts/` | база знаний о неочевидном поведении страниц. Ищет Клод через MCP-сервер `page-facts`; `INDEX.md` — сводка, которая генерируется скриптом (`yarn build:page-facts-index`) и руками не правится |
| `.claude/workflows/` | рой агентов с заданными фазами, моделями и промптами (позже; есть только на ветке `test-generation`) |
| `package.json` | зависимости + `scripts` как ярлыки для длинных команд |
| `RULES.md` | правила написания тестов с номерами (A9, W8, T10…); единственный реестр правил |
| `UI-PATTERNS.md` | как на самом деле ведёт себя интерфейс WL (ожидания, селекты, кэш); открывают по ситуации |
| `CONVENTIONS.md` | документ для людей: введение в проект, предметная область, обоснования |
| ESLint | механические правила, которые проверяются без человека; то, что в `RULES.md` требует суждения, линтер не ловит |
| `.nvmrc` | фиксирует версию Node на проекте |
| MCP-серверы | внешние инструменты, к которым обращается Клод |

**Архитектура тестов.** Общие хелперы (корневой `helpers/**` и `projects/<проект>/helpers/**`)
**заморожены** против изменения — правило A9 в `RULES.md`. Существующие файлы и функции
не правятся, и дописать новую функцию в существующий файл — тоже изменение. Новый общий
хелпер добавляется только **новым файлом** в подходящей папке (`pages/`, `components/`,
`flows/`, `utils/`). Нужно другое поведение существующего — копируете хелпер в свой
`C123456.helpers.ts` и правите там. Дубликаты — осознанно принятый риск. Механической
блокировки при коммите нет: правило проверяется на ревью.

**Правила проекта важнее существующих примеров.** Старые тесты написаны в старом стиле;
ориентируемся на `RULES.md`, а не на соседний файл.

**Три проекта:** `monolith`, `widgets`, `explorer` (устарел). Тесты запускаются из папки
проекта, не из корня. У каждого несколько конфигов Playwright — по типу прогона
(обычный, `e2e`, `setup`, `verify`); окружение выбирается файлом `config/.env.<имя>`.
Тесты из `tests/regression-run/` при ручном запуске перезапускаются один раз; в прогоне
регрессии повторов нет намеренно — повтор спрятал бы нестабильный тест. Тесты из
`end-to-end-tests/` не перезапускаются никогда: они создают сущности с soft delete.

**Ветки:** `main` (устарела) · `draft` (основная, туда PR) · `test-generation` (сервер
генерации; до 17.10.2026 называлась `autonomous-test-gen-experiment`; опережает `draft`
на тысячи коммитов и целиком в него не мержится — готовый тест переносят новой веткой
от `draft`).

## Часть 2. TypeScript

- TS — надстройка над JS; валидный JS остаётся валидным TS
- Node как рантайм: движок V8 + файлы, сеть, процессы
- Транспиляция TS → JS через `tsc`; `dist/`, source maps и зачем они при отладке
- `tsconfig.json`: `target`, `module`, `moduleResolution`, `strict`, `noEmit`, `rootDir`, `outDir`
- Статическая типизация против динамической; синтаксис `имя: тип`
- Примитивы: `number`, `string`, `boolean`, `bigint`, `undefined`, `null`, `symbol`
- Всё остальное — объекты; сравнение **по ссылке**; ключи — строки (число приводится
  к строке) или символы
- Массивы: `number[]`, `Array<number>`, дырявые массивы, `push` / `pop`, `Array.isArray`
- Функции: объявление, параметры, тип возврата, `noImplicitAny`
- `Map` и `Set`, их методы, типизация
- `any` / `unknown` / `never`
- `enum` и tuple

## ⚠️ Ошибки этого урока

Шесть штук — разобраны в [уроке 2](../lesson-02/README.md#работа-над-ошибками-первого-урока),
с кодом, который можно запустить: [`examples/00-errata.ts`](../lesson-02/examples/00-errata.ts).

Коротко: примитивов **7**, а не 8/4 · `strict` в tsconfig ≠ `'use strict'` ·
`tsc` не ставим глобально · Map и Set — **не** массивы · `enum` у нас **не** используют ·
forward declaration функций в JS **нет**.

Ещё четыре неточности — [там же, в уроке 2](../lesson-02/README.md#ещё-четыре-неточности-первого-урока):
`async`/`await` появились в ES2017, а не в ES2022 · `symbol` — из ES2015, а не из «последних
спецификаций» · явный `any` запрещает не tsconfig, а линтер (`no-explicit-any`), вместо
него — `unknown` · в tuple можно сделать `push` лишнего элемента — известная дыра
TypeScript, а не нововведение.

И главное, что не прозвучало: **типов в рантайме нет**, поэтому тест может
запуститься с ошибкой типов.
