## Claude Code: где и как запускать

Claude Code есть в терминале (команда `claude`) и во вкладке Code
десктопного приложения — это один и тот же инструмент. Отличие от чата
в браузере: он **сидит в папке проекта** — сам читает файлы, ищет
по коду, запускает команды и правит код.

В курсе работаем **в терминале**: `node` и `yarn` всё равно запускаются
там, а у терминальной версии больше настроек (строка состояния, хуки,
свои команды). Десктоп под Linux — бета: работает только на Debian-подобных
системах, без Computer Use и диктовки
([desktop-linux](https://code.claude.com/docs/en/desktop-linux)).

Установка — [quickstart](https://code.claude.com/docs/en/quickstart);
запуск — в папке проекта:

```bash
cd ~/work/typescript_course
claude
```

Claude работает **в той папке, где его запустили**: её файлы он видит,
за её пределы без спроса не ходит.

**Первые клавиши и команды:**

| Что | Зачем |
|---|---|
| `/` | меню всех команд; набирайте — список фильтруется |
| `Esc` | остановить ответ или действие; сделанное до этого остаётся |
| `Esc` `Esc` или `/rewind` | откатить разговор и/или правки файлов к одному из прошлых сообщений |
| `/clear` | начать разговор с чистого листа; прошлый сохраняется |
| `claude -c` | продолжить последний разговор в этой папке; `claude -r` или `/resume` — выбрать из списка |

> ⚠️ `/rewind` откатывает только правки, которые Claude сделал **своими
> инструментами** редактирования. То, что изменила запущенная им команда
> в терминале, он не откатит. Это не замена git — git будет в уроках 6–7
> ([checkpointing](https://code.claude.com/docs/en/checkpointing)).

## Встроенные команды и навыки

Всё, что набирается через `/`, — не одно и то же
([commands](https://code.claude.com/docs/en/commands),
[skills](https://code.claude.com/docs/en/skills)):

| Что | Пример | Как устроено |
|---|---|---|
| **встроенная команда** | `/clear`, `/model`, `/compact`, `/statusline` | часть самого Claude Code, логика зашита в программу |
| **поставляемый навык** (skill) | `/code-review`, `/simplify`, `/batch` | готовая инструкция, которую Claude выполняет; в таблице команд помечен «Skill» |
| **свой навык** | что угодно | файл `SKILL.md` в `.claude/skills/<имя>/` проекта или в `~/.claude/skills/`. Старый формат — `.claude/commands/<имя>.md` — тоже работает |

Свои навыки видны только в том проекте, где лежат (или везде, если
лежат в `~/.claude/`). Поэтому в разных папках список в меню `/` разный.

**Как сделать свой навык.** Сначала пройдите процесс вместе с Claude
руками, в одной сессии; когда он получился — попросите Claude записать
его в навык. Так навык описывает то, что действительно сработало.
Создавать навыки помогает плагин `skill-creator` — он не встроенный,
ставится из официального маркетплейса:
`/plugin install skill-creator@claude-plugins-official`.

## Кто разрешает действия

**Режим разрешений** — правило, по которому Claude Code решает, выполнить
действие сразу или сначала спросить вас. Текущий режим — внизу окна,
переключение — `Shift+Tab`
([permission-modes](https://code.claude.com/docs/en/permission-modes)).

| Режим | Что делает |
|---|---|
| ручной (`default`) | читает сам; перед правкой файла и перед командой спрашивает |
| `acceptEdits` | правки файлов — сам, команды — спрашивает |
| `plan` — **режим планирования** | ничего не меняет: читает, думает и предлагает план |
| `auto` | не спрашивает: каждое действие перед запуском проверяет **отдельная модель-классификатор** |

Новая сессия в терминале начинается в `auto`.

**Режим планирования.** Для любой задачи крупнее вопроса — сначала `plan`.
Claude соберёт план, вы его прочитаете и выберете: «Yes, and use auto mode»
(выполнять в авто-режиме), «Yes, manually approve edits» (выполнять,
спрашивая про каждую правку) или «No, keep planning» (дорабатывать план).
В `plan` он **не может** ничего поменять, даже если решит, что «и так
понятно»: просьба словами — пожелание, режим — ограничение.

**Авто-режим** не спрашивает про каждое действие. Опасное (удалить
файлы, `git reset --hard`, запустить скачанный скрипт) классификатор
блокирует: действие не выполняется, Claude получает причину, вам
приходит уведомление. Спрашивать вас он начнёт, только если
блокировок будет **3 подряд или 20 всего** — тогда авто-режим встаёт
на паузу. Документация прямо пишет: безопасности авто-режим не гарантирует.
Заблокированное можно разрешить в `/permissions`, вкладка «Recently
blocked», клавиша `r`
([auto-mode-config](https://code.claude.com/docs/en/auto-mode-config)).

**Свои правила — `/permissions`** ([permissions](https://code.claude.com/docs/en/permissions)):

| Список | Что значит |
|---|---|
| allow | разрешено без вопроса, например `Bash(git status)` |
| ask | спрашивать всегда |
| deny | запрещено всегда |

Правила `deny` проверяет сам Claude Code, **до** классификатора, и ничто
их не отменяет — ни модель, ни авто-режим. Оговорка: правило для `Bash`
сравнивает **текст** команды, поэтому ту же программу, вызванную иначе,
оно может не узнать. Это удобство, а не защита.

> ⚠️ `claude --dangerously-skip-permissions` отключает все вопросы
> и проверки. Так запускают Claude в автоматических прогонах, где
> спросить некого. В работе — не использовать.

## Ответ Claude: гипотеза

**Ответ Claude — гипотеза.** Проверяется запуском кода, `yarn typecheck`,
поиском по проекту. Не «он сказал», а «я запустил и увидел». За результат
отвечает тот, кто им пользуется.

Почему это не паранойя: обзор возможностей Claude Code, рассказанный
на курсе по памяти, при проверке по документации дал 14 неверных или
неподтверждённых утверждений из 27. Ошибается не только ИИ — ошибается
любой, кто говорит не проверив.

## Контекст: что Claude помнит

**Контекст** (context window) — всё, что модель видит, отвечая
на очередное сообщение: ваши сообщения, её ответы, прочитанные файлы,
вывод команд, инструкции проекта
([context-window](https://code.claude.com/docs/en/context-window)).

1. Модель **ничего не хранит между сообщениями**. С каждым вашим
   сообщением Claude Code отправляет **весь разговор целиком**.
2. Поэтому разговор только растёт: каждый прочитанный файл и вывод
   каждой команды остаются в нём до конца.
3. Чтобы не платить за одно и то же снова, совпадающее начало разговора
   **кэшируется**: оно всё равно отправляется, но обрабатывается быстрее
   и стоит дешевле ([prompt-caching](https://code.claude.com/docs/en/prompt-caching)).
4. Когда контекст подходит к пределу, Claude Code **сжимает** разговор —
   заменяет старое кратким пересказом. Чего нет в пересказе, модель больше
   не видит.

Объём меряют в **токенах** — кусочках слов. Русское слово обычно
занимает несколько токенов. Предел окна — до миллиона токенов: столько
по умолчанию у Fable, Sonnet 5 и новее, Haiku 5.5, Opus 4.7 и новее
([model-config](https://code.claude.com/docs/en/model-config)).

Никаких порогов вида «после 60 % модель начинает забывать» документация
не называет. Правило проще:

> **Одна задача — один разговор.** Закончили задачу — `/clear`.
> Разговор, в котором успели починить три разных теста, хуже каждого
> из трёх отдельных.

| Команда | Что делает |
|---|---|
| `/context` | показывает, чем занят контекст. «Он стал путаться» — смотреть сначала сюда |
| `/compact что сохранить` | сжать **сейчас**, с указанием, что оставить: `/compact оставь всё про упавший тест` |
| `/clear` | чистый лист |
| `/btw вопрос` | вопрос «в сторону»: отвечает из текущего контекста, в историю разговора не попадает |

**Сообщение, отправленное, пока Claude работает,** не ждёт конца ответа:
Claude получит его, как только закончит текущие действия, — в том же
ходе. До конца хода ждут только команды `/` и `!`
([interactive-mode](https://code.claude.com/docs/en/interactive-mode)).

## `CLAUDE.md` и что ещё бывает в `.claude/`

**`CLAUDE.md`** — файл с инструкциями для Claude, который загружается
в контекст **сам**, в начале каждого разговора: как устроен проект,
какие команды, какие правила ([memory](https://code.claude.com/docs/en/memory)).

| Какой | Когда загружается |
|---|---|
| `CLAUDE.md` в папке запуска и во всех папках **выше** | при запуске |
| `CLAUDE.md` во **вложенной** папке | когда Claude прочитает или изменит файл в ней |
| `~/.claude/CLAUDE.md` — ваш личный, для всех проектов | при запуске. Его пишете вы |

- Правка `CLAUDE.md` посреди разговора подхватится после `/clear`,
  `/compact` или перезапуска.
- `/init` создаёт черновик `CLAUDE.md` для нового проекта; `/memory` —
  открыть и поправить.
- **`AGENTS.md`** — то же для любых ИИ-агентов, не только Claude. Claude
  Code читает его сам, если `CLAUDE.md` в папке нет. Документация
  советует не переименовывать, а оставить `CLAUDE.md` и импортировать
  в него `AGENTS.md` строкой `@AGENTS.md`.
- **Автопамять** — то, что Claude решил запомнить сам, — лежит
  не в `CLAUDE.md`, а в `~/.claude/projects/<проект>/memory/`
  (оглавление — `MEMORY.md`).

> ⚠️ `CLAUDE.md` — **совет, а не запрет**. Если действие не должно
> произойти никогда — это правило `deny` или хук, не текст.

**Что ещё бывает в `.claude/` — узнать в лицо:**

| Что | Что это | Где |
|---|---|---|
| **навык** `/имя` | готовый сценарий, который запускают по имени | `.claude/skills/`, `.claude/commands/` |
| **агент** (субагент) | отдельный Claude со своим заданием, своим контекстом и, если нужно, своим набором разрешённых инструментов; основной поручает ему часть работы | `.claude/agents/<имя>.md`; без полей `name` и `description` в шапке файла Claude Code его молча пропускает ([sub-agents](https://code.claude.com/docs/en/sub-agents)) |
| **MCP-сервер** | дополнительный инструмент сверх встроенных: Jira, TestRail, живой браузер (`playwright`). Список — `/mcp` | `.mcp.json` проекта, `~/.claude.json` ([mcp](https://code.claude.com/docs/en/mcp)) |
| **хук** | скрипт, который запускается до или после действия Claude и может его запретить | `hooks` в `.claude/settings.json` ([hooks](https://code.claude.com/docs/en/hooks)) |

Агент — это, по сути, заранее подготовленная инструкция и такая же
сессия Claude, только отдельная. Отдельные агенты имеют смысл для
больших задач, где один разговор не вместит все шаги. Для обычной
работы хватает режима планирования и авто-режима.

## Модель, усилие, расход

| Команда | Что |
|---|---|
| `/model` | выбрать модель; стрелками влево-вправо там же — усилие |
| `/effort` | сколько модель думает: `low`, `medium`, `high`, `xhigh`, `max`. Без аргумента — ползунок. По умолчанию у Opus 5.5, Sonnet 5.5 и Haiku 5.5 — `medium` |
| `/usage` | лимиты и расход |
| `/statusline` | настроить строку состояния внизу — **словами**: «покажи модель, папку и сколько занято контекста» |

Модели по возрастанию возможностей: **Haiku → Sonnet → Opus → Fable**.
По умолчанию у большинства — Opus 5.5. Fable документация называет
самыми способными моделями, «для задач больше одного захода»; выбирают
её явно: `/model fable` ([model-config](https://code.claude.com/docs/en/model-config)).

Как выбирать — совет ведущего, не правило документации:

- механическая работа (найти строку во всех файлах, заменить
  одинаковую ошибку) — Haiku, низкое усилие;
- обычная ежедневная работа — Sonnet, `medium` или `high`;
- большие задачи с анализом и планом — Opus;
- «дороже значит лучше» не работает: модель с низким усилием может
  справиться не хуже модели классом выше; а дорогая модель иногда
  выходит дешевле, потому что быстрее доходит до результата. Проверять
  на своих задачах.

> ⚠️ `/fast` — та же модель, быстрее, но **по повышенной цене**, и на
> подписке списывается не с лимита плана, а с отдельно включённых
> кредитов ([fast-mode](https://code.claude.com/docs/en/fast-mode)).
> Не включать «просто попробовать».

## Учиться вместе с Claude

1. `claude` в папке курса — у него есть все конспекты, примеры и домашки.
2. «Объясни раздел про … из `lessons/lesson-02/README.md` на другом
   примере», «задай мне пять вопросов по этому уроку и проверь ответы».
3. **Стиль ответа — `/output-style`**
   ([output-styles](https://code.claude.com/docs/en/output-styles)):
   - `Explanatory` — добавляет пояснения «почему так» (блоки `Insight`);
   - `Learning` — то же, плюс оставляет куски кода **вам** дописать
     (`TODO(human)`).

   Выбор сохраняется для текущего проекта (`.claude/settings.local.json`).
   Для всех проектов — `"outputStyle": "Explanatory"` в `~/.claude/settings.json`.
4. **Домашку Claude за вас не делает.** Сначала сами, потом — непонятное
   с Claude. Домашка проверяет, как понимаете *вы*.

## Что ещё есть в меню: узнать в лицо

| Команда | Что делает |
|---|---|
| `/voice` | голосовой ввод: держите пробел и говорите. `/voice tap` — нажал, говоришь, нажал |
| `/branch` | копия разговора — продолжить в другую сторону, не трогая этот. Слить две ветки обратно нельзя |
| `/fork` | то же, но копия уходит работать в фон |
| `/goal` | цель, к которой Claude идёт сам, ход за ходом. Пишите в цели и предел: «…или остановись через 20 ходов» |
| `/remote-control` | управлять этой сессией с телефона; `/mobile` — QR-код, чтобы поставить мобильное приложение |
| `/cd` | перейти в другую папку, не теряя разговор |
| `/copy` | скопировать последний ответ |
| `/autocompact` | когда сжимать контекст автоматически |
| `/autofix-pr` | следить за PR и чинить замечания ревью и CI (облачная сессия, нужен `gh`) |
| `@имя` сессии | написать другой открытой сессии Claude; список — `/list-agents` |

Сторонние программы, которые показывались на занятии (например, herdr
для управления многихи сессиями сразу), к Claude Code не относятся: у самого Claude
Code для этого есть `claude agents` и `claude --bg`.

## Как устроен проект на JavaScript

**Прочитать и выполнить у себя до урока 2.** Все команды — в корне
репозитория курса.

### `.nvmrc` — какой Node

```bash
cat .nvmrc
node --version
```

```
25.9.0
v25.9.0
```

| Часть | Что значит |
|---|---|
| `cat .nvmrc` | вывести содержимое файла на экран. `cat` — команда терминала, не JavaScript |
| `.nvmrc` | файл, где проект записал, какая версия Node ему нужна |
| `node --version` | какую версию Node вы сейчас запускаете |

**Node** — программа, которая выполняет JavaScript вне браузера:
в терминале, на сервере, в CI. Тесты запускаются им же. Версии Node
ведут себя по-разному, поэтому проект записывает свою в `.nvmrc`, а
**`nvm`** (менеджер версий Node) ставит её командой `nvm install`.
Вторая строка другая — `nvm use`. Действует только в этом окне
терминала; сделать постоянной — `nvm alias default 25.9.0`.

### `package.json` — паспорт проекта

```bash
cat package.json
```

```
{
  "name": "js-ts-course",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "description": "JS/TS and test automation course",
  "scripts": {
    "typecheck": "tsc --noEmit"
  },
  "devDependencies": {
    "typescript": "^5.9.3"
  },
  "engines": {
    "node": ">=22.18.0"
  }

```

**Пакет** — готовая программа или библиотека на JavaScript из общего
реестра (npm). Проект её не пишет, а ставит. Пакет, без которого
проект не работает, — его **зависимость**.

| Поле | Что значит |
|---|---|
| `"name"`, `"version"` | имя и версия проекта |
| `"private": true` | не публиковать в реестр — даже случайно |
| `"type": "module"` | файлы проекта — модули современного вида (урок 5) |
| `"scripts"` | команды проекта — ниже |
| `"devDependencies"` | пакеты для разработки. Здесь один — `typescript`, проверка типов |
| `"^5.9.3"` | диапазон: «5.9.3 или новее, но в пределах 5.x» |
| `"engines"` | какой Node нужен: не старее 22.18 |

Раз в `package.json` диапазон, у двух людей могли бы стоять разные
версии. Поэтому рядом лежит **`yarn.lock`**: там записана **точная**
версия каждого пакета, включая пакеты, нужные самим пакетам. По нему
у всех и в CI ставится одно и то же — у курса `typescript` `5.9.3`.

| `node_modules` | папка, куда `yarn` кладёт пакеты. В git её нет: у каждого своя, собирается из `yarn.lock` |

Время в последней строке у всех своё. Склонировали любой проект —

| Часть | Что значит |
|---|---|
| `yarn typecheck` | найти в `"scripts"` команду с именем `typecheck` и выполнить |
| `$ tsc --noEmit` | `yarn` печатает, что именно запустил, — ту строку из `package.json` |

| `--noEmit` | только проверить, файлов не создавать |

**Скрипт** — именованная команда из `"scripts"`; запускается
`yarn <имя>`. Так все в проекте запускают одно и то же одним именем.

**В большом проекте всё то же самое, только больше.** У нашего рабочего
проекта тот же `.nvmrc`; `package.json` пять — у каждой части свой;
в корне 32 скрипта, у одной из частей — 41, среди зависимостей —
`@playwright/test`, сам Playwright. Тесты лежат в **спеках** — файлах
`*.spec.ts`, их там больше четырёх тысяч. И скрипт `typecheck` там — тот же
`tsc --noEmit`. Прочитали `package.json` курса — прочитаете любой.

## Первый файл на TypeScript

Раскомментируйте в `playground/scratch.ts` первый кусок (или напишите
его в своём файле — см. домашку):

```ts
const caseId: string = 'C19633';
const attempts: number = 3;
console.log('кейс', caseId, 'попыток', attempts);
```

```bash
node playground/scratch.ts
```

```
кейс C19633 попыток 3
```

**TypeScript** — это JavaScript плюс **типы** после имени: `: string`
(строка), `: number` (число). `node` (22.18 и новее) запускает `.ts`
напрямую, но типы перед запуском просто **выбрасывает**.

Кто тогда их проверяет? Допишите строку с неподходящим значением:

```text
const retryLimitBroken: number = 'три';
```

```bash
node playground/scratch.ts     # выполнит, ошибки не заметит
yarn typecheck                 # найдёт
```

```
playground/scratch.ts(…): error TS2322: Type 'string' is not assignable to type 'number'.
```

| Часть | Что значит |
|---|---|
| `playground/scratch.ts(…)` | файл, строка и символ, где ошибка |
| `TS2322` | код ошибки: по нему её ищут в интернете |
| `Type 'string' is not assignable to type 'number'` | «значение типа `string` нельзя положить туда, где объявлен `number`» |

`node` файл **запустил** — типов для него нет. `yarn typecheck` файл
**не запускал**, а прочитал и нашёл несоответствие. Отсюда главное для
тестов: тест может запуститься и даже пройти с ошибкой типов. Поэтому
в любом проекте на TypeScript проверка типов — обязательный шаг перед
тем, как изменение примут. Сотрите дописанную строку.

## Словарь терминов

| Термин | Что значит |
|--------|------------|
| **режим разрешений** (permission mode) | правило, по которому Claude Code решает, выполнить действие сразу или сначала спросить вас. Переключение — `Shift+Tab`; **режим планирования** (`plan`) ничего не меняет, а только предлагает план |
| **контекст** (context window) | всё, что модель видит, отвечая на очередное сообщение: разговор, прочитанные файлы, вывод команд, инструкции проекта. С каждым сообщением отправляется целиком. У контекста есть предел; когда он близко, разговор сжимается в пересказ |
| **`CLAUDE.md`** | файл с инструкциями для Claude, который сам загружается в начале каждого разговора: как устроен проект, какие команды, какие правила |
| **пакет** (package) | готовая программа или библиотека на JavaScript из общего реестра (npm). Проект её не пишет, а ставит. Пакет, без которого проект не работает, — его **зависимость** |
| **`package.json`** | файл в корне проекта на JavaScript: как проект называется, какие пакеты ему нужны и каких версий, какие команды у него есть |
| **скрипт** (script) | именованная команда из раздела `"scripts"` в `package.json`; запускается `yarn <имя>` — например, `yarn typecheck` |
| **спек** (spec) | файл с тестами, имя кончается на `.spec.ts` |

Узнать в лицо, запоминать пока не нужно: **навык** (`/имя` — готовый
сценарий для Claude), **агент** (отдельный Claude со своим заданием),
**MCP-сервер** (дополнительный инструмент Claude, например живой
браузер), **хук** (скрипт, который может запретить действие Claude),
**токен** (кусочек слова — единица, в которой меряют контекст и расход),
**Node** (программа, которая выполняет JavaScript вне браузера), **`nvm`**
(менеджер версий Node), **хелпер** (готовая функция, которая делает
один шаг теста: «войти», «открыть страницу»).
