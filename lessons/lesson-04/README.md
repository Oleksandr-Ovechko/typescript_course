# Урок 4. Ловушки JavaScript

Занятие про то, от чего типы не спасают: `toFixed` возвращает строку,
`0.1 + 0.2` не равно `0.3`, `sort()` расставляет числа как попало, а `arr[99]`
компилятор считает числом. Всё это компилируется без единого замечания
и падает в рантайме — или, что хуже, не падает, а тихо проверяет не то.

## Зачем этот урок

Предыдущие три урока были про то, как читать и писать код. Этот — про то, как
язык обращается со значениями за вашей спиной.

Тема не разблокирует чтение тестов, поэтому и вынесена отдельным занятием.
Но именно эти вещи потом стоят часов отладки: тест «проверяет» сумму, которая
на самом деле строка; сортировка «работает», потому что данные и так были
отсортированы; проверка на пустоту всегда истинна.

## Словарь терминов

### Приведение типов

*type coercion* — JavaScript сам превращает значение в другой тип, когда
операция этого требует. Молча, без предупреждения. `'5' + 2` даёт `'52'`,
потому что двойка стала строкой.

### Ложные значения

*falsy* — значения, которые в условии ведут себя как `false`. Их ровно восемь:
`false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN`. Всё остальное —
**истинное** (truthy), включая пустой массив, пустой объект и строку `'0'`.

### Временная мёртвая зона

*TDZ, temporal dead zone* — участок кода от начала блока до строки с `let`
или `const`. Переменная там уже существует (она «всплыла»), но обращаться
к ней нельзя — будет `ReferenceError`.

### Кодовая единица

Ячейка, из которых состоит строка в памяти. `.length` считает именно их,
а не символы. Обычная буква — одна ячейка, эмодзи — две и больше.

### Глубокая и поверхностная копия

**Поверхностная** — новый объект, но вложенные объекты общие с оригиналом.
Это то, что делает спред. **Глубокая** — скопировано всё целиком,
`structuredClone`.

## Уточнения к занятию

Несколько мест, где на уроке прозвучала неточность. Весь код — в
[`00-corrections.ts`](examples/00-corrections.ts), запускается.

### `parseInt` теряет копейки

Прозвучал совет: чтобы сравнить сумму из репорта, сделать ей `parseInt`.
`parseInt` читает до первой точки, и всё после неё отбрасывает:

```
parseInt('12.5')      → 12
parseInt('0.1')       → 0
parseInt('1234.56')   → 1234      ← потеряли 56 центов
parseFloat('1234.56') → 1234.56
```

Для дробных нужен `parseFloat` или `Number`. Подробно, вместе с настоящим
кодом из `wl-e2e`, — в разделе
[Дробные числа в настоящих тестах](#дробные-числа-в-настоящих-тестах).

### Колбэк `sort` возвращает число, а не `true`/`false`

Возвращать нужно **число**: отрицательное, ноль или положительное. Булев
колбэк не сортирует вообще, потому что `false` превращается в `0`,
а `0` для `sort` означает «элементы равны»:

```
[10, 9, 1, 100].sort((a, b) => a - b)   → [1, 9, 10, 100]
[5, 4, 3, 2, 1].sort((a, b) => a > b)   → [5, 4, 3, 2, 1]   ← не тронут
```

В TypeScript спасает сигнатура (`TS2345`), в чистом JavaScript — ничто.
Ошибка живучая: тест «сортировка по возрастанию» проходит ровно тогда,
когда данные и так были отсортированы.

### `setTimeout` ждёт конца кода, а не компиляции

Прозвучало «откладывает вызов до завершения компиляции». Компиляция закончилась
задолго до этого. `setTimeout` кладёт колбэк в очередь, и движок берёт его,
когда доработал **весь синхронный код**:

```
1. синхронный код — первым
2. промис — раньше setTimeout
3. setTimeout — последним
```

Формулировка «после того, как закончится текущий код» — та, которая объясняет
[ловушку с циклом](#область-видимости-и-ссылки).

### `Number.EPSILON` — не «минимально различимая разница»

Это расстояние между `1` и следующим представимым числом (`2.22e-16`).
Рядом с единицей приём работает, дальше — нет:

```
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON                  → true
Math.abs((1e9 + 0.1 + 0.2) - (1e9 + 0.3)) < Number.EPSILON  → false
```

В тестах этим не занимаются вовсе — там `toBeCloseTo`, см.
[последний раздел](#дробные-числа-в-настоящих-тестах).

## `typeof` и его враньё

Пример: [`01-typeof-and-checks.ts`](examples/01-typeof-and-checks.ts)

```ts
console.log(typeof null, typeof [], typeof NaN, typeof function () {});
// object object number function
```

Три сюрприза из четырёх.

`typeof null === 'object'` — историческая ошибка 1995 года. Исправить нельзя:
слишком много кода на неё завязано.

`typeof [] === 'object'` — формально верно, массив и правда объект. Но для нас
бесполезно: отличить массив от обычного объекта так не выйдет.

`typeof NaN === 'number'` — тоже формально верно. `NaN` это «не число» в смысле
«результат неудачной арифметики», но по типу это число.

Отдельно: `typeof` — **единственная конструкция, которая не бросает ошибку
на необъявленной переменной**. Она возвращает строку `'undefined'`. Всё
остальное даст `ReferenceError`. TypeScript такое не пропустит, но в чужом коде
встречается — так проверяют глобальные переменные.

### Чем проверять на самом деле

| Что проверяем | Чем |
|---|---|
| массив | `Array.isArray(x)` |
| `NaN` | `Number.isNaN(x)`, а не `isNaN(x)` |
| `null` | `x === null` |
| `null` или `undefined` | `x == null` — единственное узаконенное `==` |
| точный тип объекта | `Object.prototype.toString.call(x)` |

Две проверки на `NaN` дают **разный** ответ на одно и то же значение:

```ts
Number.isNaN('foo')                 // false
isNaN('foo' as unknown as number)   // true
```

`isNaN` сначала приводит аргумент к числу, получает `NaN` и говорит `true` —
то есть отвечает на вопрос «станет ли это `NaN`, если превратить в число».
Почти никогда не то, что нужно. `Number.isNaN` не приводит ничего: «это именно
значение `NaN`?» — и честно отвечает `false`, потому что это строка.

Разница видна ещё до запуска, в сигнатурах:

```
declare function isNaN(number: number): boolean;   // глобальная, lib.es5.d.ts
Number.isNaN(number: unknown): boolean;            // lib.es2015.core.d.ts
```

`isNaN` объявлен принимающим **число** — потому что он число из аргумента
и делает. Дать ему строку значит соврать, и компилятор требует оформить враньё
явно. `Number.isNaN` объявлен принимающим `unknown` — он ничего не приводит
и готов ответить про любое значение.

### Зачем приведение двойное

`as` — это не преобразование значения, а обещание компилятору: «поверь, тип
на самом деле такой». Чтобы обещание не было заведомо ложным, `as` разрешён
только между типами, которые хоть как-то пересекаются. `string` и `number`
не пересекаются никак:

```
error TS2352: Conversion of type 'string' to type 'number' may be a mistake
because neither type sufficiently overlaps with the other.
If this was intentional, convert the expression to 'unknown' first.
```

Компилятор сам диктует обход в тексте ошибки. `unknown` совместим со всем
в обе стороны, поэтому цепочка `string → unknown → number` проходит: каждый
шаг по отдельности законен. `as any` сработал бы так же, но `unknown` аккуратнее —
он выключает проверку ровно в этом выражении, а `any` расползается дальше.

И главное: **оба приведения существуют только при компиляции.** В рантайме
остаётся `isNaN('foo')` — значение как было строкой, так и осталось.

### Значение, которого нет, а тип есть

```ts
const spots = [3, 0, 12];
const far = spots[99];

console.log(far, typeof far);   // undefined undefined
console.log(far + 1);           // NaN
```

Главное здесь — **компилятор не сказал ни слова**. Наведите курсор на `far`:
тип `number`. Не `number | undefined`, а просто `number`. TypeScript считает,
что раз массив числовой, то по любому индексу лежит число. Проверять индекс
он не умеет.

Настройка `noUncheckedIndexedAccess` это чинит. В `wl-e2e` она **не включена**,
как и в большинстве проектов: слишком много кода пришлось бы переписать.

А вот `find` честно сообщает, что может не найти:

```ts
const found = spots.find((spot) => spot === 777);   // number | undefined
console.log(found + 1);                             // ❌ TS18048
```

Два одинаковых `undefined`, и только про один из них компилятор предупреждает.
Ровно поэтому и нужен этот урок.

### Где это встретится в тестах

```ts
await container.locator('.css-row').nth(0).click();
```

Если элементов меньше, чем вы просите, поведение зависит от того, что именно
вы написали:

| Запись | Что будет |
|---|---|
| `elements[5].click()`, где `elements` — результат `.all()` | `TypeError: Cannot read properties of undefined` сразу |
| `.locator('.css-row').nth(5).click()` | Локатор создастся, но действие не найдёт элемент и упадёт по таймауту |

Компилятор молчит в обоих случаях.

## Приведение типов

Пример: [`02-coercion.ts`](examples/02-coercion.ts)

### Восемь ложных значений

```ts
const falsy: unknown[] = [false, 0, -0, 0n, '', null, undefined, NaN];
falsy.map((value) => Boolean(value));   // восемь раз false
```

Это **полный** список. Всё остальное истинно, в том числе:

```ts
Boolean('0');    // true — непустая строка
Boolean('false') // true — тоже непустая строка
Boolean([]);     // true — объект
Boolean({});     // true — объект
```

Практическое следствие, которое стоит запомнить отдельно:

```ts
if (arr) { }          // всегда истинно, даже для пустого массива
if (arr.length) { }   // вот это проверяет, что элементы есть
```

### `==` против `===`

```ts
0 == ''      // true
0 == '0'     // true
'' == '0'    // false   ← !
```

Если `a == b` и `b == c`, то `a == c` — **не выполняется**. Отношение
нетранзитивно, то есть на нём нельзя строить рассуждения. Отсюда правило:
**всегда `===`**.

Единственное узаконенное исключение — проверка на «ничего»:

```ts
if (x == null) { }   // сразу и null, и undefined
```

И ещё одна несогласованность, чтобы почувствовать масштаб: пустой массив
равен `false` и равен пустой строке, но сам по себе в условии истинный.
Одно и то же значение ведёт себя по-разному в `if` и в `==`.

### `+` — это два разных оператора

```ts
'5' + 2      // '52'   склейка
'5' - 2      //  3     вычитание
1 + 2 + '3'  // '33'   слева направо: 3, потом '3' + '3'
'1' + 2 + 3  // '123'  строка появилась сразу
```

Если хоть один операнд строка — `+` склеивает. У `-` строкового смысла нет,
поэтому он приводит к числу.

> **Всё, что вы достали со страницы, — строка.** `innerText`, `textContent`,
> `getAttribute`, `inputValue` возвращают строку всегда. `'12' + 1` даст `'121'`,
> а не `13`. Приводить явно: `Number(...)`.

## Числа

Пример: [`03-numbers.ts`](examples/03-numbers.ts)

### Дробные

```ts
0.1 + 0.2          // 0.30000000000000004
0.1 + 0.2 === 0.3  // false
(0.1 + 0.7) * 10   // 7.999999999999999
```

Это не баг JavaScript — так работают дробные числа почти во всех языках.
Число хранится в двоичной системе, а `0.1` в двоичной — бесконечная дробь,
как `1/3` в десятичной. Её обрезают, и накапливается погрешность.

Отсюда правило: **дробные не сравнивают через `===`**. В тестах для этого есть
`toBeCloseTo`, см. [последний раздел](#дробные-числа-в-настоящих-тестах).

### `NaN`

`NaN` — единственное значение в языке, **не равное самому себе**:

```ts
const parsed = Number('двенадцать');   // NaN
parsed === parsed                       // false
Number.isNaN(parsed)                    // true
```

Отсюда старый приём проверки `x !== x`, истинный только для `NaN`. Писать так
не надо — есть `Number.isNaN`.

### `parseInt`, `parseFloat` и `Number`

```ts
parseInt('12px')    // 12      читает слева, пока может
parseFloat('12px')  // 12
Number('12px')      // NaN     всё или ничего

parseInt('12.5')    // 12      ← целое, дробную часть отрезает
parseFloat('12.5')  // 12.5
```

И набор несогласованностей, которые надо просто знать:

```ts
parseInt('')       // NaN
Number('')         // 0     ← !
Number(null)       // 0     ← !
Number(undefined)  // NaN
```

Пустая строка со страницы превращается `Number(...)` в **ноль**. И дефолт
через `??` после этого уже не сработает — ноль это не `null`:

```ts
const timeout = Number(fromPage) ?? 10;   // 0, а не 10
```

### `toFixed` возвращает строку

```ts
(1.005).toFixed(2)     // '1.00'   а не '1.01'
typeof (1).toFixed(2)  // 'string' ← !
'1.00' + 1             // '1.001'  склейка, а не 2
```

Два сюрприза сразу. `(1.005).toFixed(2)` даёт `'1.00'`, потому что `1.005`
хранится чуть меньше, чем 1.005 — та же погрешность, что и в начале раздела.

И главное: **`toFixed` — для вывода, не для вычислений.** Нужно число
обратно — `Number(x.toFixed(2))`.

## Строки

Пример: [`04-strings.ts`](examples/04-strings.ts)

**Строки неизменяемы.** Ни один строковый метод не меняет строку — все
возвращают новую. `text.trim();` отдельной строкой не делает ничего.

**`replace` меняет только первое вхождение**, если в первом аргументе строка:

```ts
'a-a'.replace('a', 'b')      // 'b-a'
'a-a'.replaceAll('a', 'b')   // 'b-b'
'a-a'.replace(/a/g, 'b')     // 'b-b'
```

**`.length` считает ячейки, а не буквы:**

```ts
'привет'.length     // 6
'👍'.length         // 2   ← одна «буква», две ячейки
[...'👍'].length    // 1   ← спред разбирает по настоящим символам
'👨‍👩‍👧'.length      // 8   ← несколько эмодзи с невидимыми соединителями
'👍'.slice(0, 1)    // '�' — разрезали эмодзи пополам
```

Обрезая текст со страницы по `.length`, можно так же сломать символ.

**`sort()` без колбэка сравнивает элементы как строки** — самая практичная
ловушка этого блока:

```ts
[10, 9, 1, 100].sort()               // [1, 10, 100, 9]   ← !
[10, 9, 1, 100].sort((a, b) => a - b) // [1, 9, 10, 100]
```

`100` оказывается раньше `9`, потому что сравниваются символы, а `'1'` меньше
`'9'`. И то же самое с буквами: по умолчанию сортировка идёт по кодам символов,
поэтому `ё` уезжает в конец. `localeCompare` знает алфавит:

```ts
['ё', 'е', 'ж'].sort()                              // ['е', 'ж', 'ё']
['ё', 'е', 'ж'].sort((a, b) => a.localeCompare(b))  // ['е', 'ё', 'ж']
```

## Область видимости и ссылки

Пример: [`05-scope-and-copies.ts`](examples/05-scope-and-copies.ts)

### `var` не знает про блоки

```ts
{
  var varInBlock = 'вижусь снаружи';
  let letInBlock = 'не вижусь';
}
console.log(varInBlock);   // работает
console.log(letInBlock);   // ❌ TS2304
```

`let` и `const` живут внутри блока `{}`. `var` — внутри всей функции, блоки
для него не существуют.

### Всплытие и мёртвая зона

Обе переменные «всплывают» — движок знает о них заранее. Разница в том, что
`var` сразу получает значение `undefined`, а `let` и `const` до своей строки
лежат во **временной мёртвой зоне**, и любое обращение даёт `ReferenceError`.

Это не недостаток `let`, а защита: `var` молча даёт `undefined`, и ошибка
всплывает позже и в другом месте.

Отличить «переменная в мёртвой зоне» от «переменной вообще нет» можно только
по тексту ошибки — тип у обеих одинаковый:

```
Cannot access 'tdzConst' before initialization   ← есть, всплыла, не инициализирована
neverExisted is not defined                       ← нет вовсе
```

### `const` запрещает переприсваивание, а не изменение

```ts
const list = [1];
list.push(2);   // можно — содержимое
list = [];      // ❌ TS2588 — нельзя, это переприсваивание
```

`const` фиксирует **ссылку**, а не содержимое.

### Спред копирует только верхний уровень

```ts
const runConfig = { project: 'widgets', browser: { headless: true } };
const copied = { ...runConfig };

runConfig.project = 'monolith';
runConfig.browser.headless = false;

copied.project           // 'widgets' ← скопировалось
copied.browser.headless  // false     ← НЕ скопировалось
```

Спред делает **новый** объект, но кладёт в него те же самые значения; а значение
поля `browser` — это ссылка. Новый объект и старый смотрят на один и тот же
вложенный объект.

| Запись | Что получилось |
|---|---|
| `const a = obj;` | Не копия вообще — второе имя того же объекта |
| `const b = { ...obj };` | Поверхностная копия: новый верхний уровень, общая внутренность |
| `const c = structuredClone(obj);` | Глубокая копия — всё целиком |

В `wl-e2e` глубокого копирования не делают вообще: ни `structuredClone`,
ни приёма `JSON.parse(JSON.stringify(x))` — ноль вхождений обоих. Значит,
каждый спред в проекте обязан быть безопасен именно как поверхностный.

### Классическая ловушка с циклом

```ts
for (var i = 0; i < 3; i++) setTimeout(() => console.log('var:', i));
for (let j = 0; j < 3; j++) setTimeout(() => console.log('let:', j));

// var: 3   var: 3   var: 3
// let: 0   let: 1   let: 2
```

`setTimeout` откладывает вызов колбэка до конца всего синхронного кода — цикл
к этому моменту уже закончился. `var i` — **одна** переменная на весь цикл,
и к моменту вызова в ней лежит `3`. `let j` создаёт **новую** переменную
на каждой итерации, поэтому каждый колбэк помнит своё значение.

> Правило: по умолчанию `const`, `let` — когда правда нужно переприсвоить,
> `var` — никогда. В `wl-e2e` `var` не встречается ни разу.

## Дробные числа в настоящих тестах

Пример: [`06-numbers-in-tests.ts`](examples/06-numbers-in-tests.ts)

Вопрос с занятия: как автоматизировать репорт, где суммы с копейками. Ответ
целиком лежит в проекте — там это уже написано.

**Шаг 1. Достать число из текста.** Со страницы приходит строка со знаком
валюты, разделителями разрядов и переводами строк. Вырезать всё, кроме цифр
и точки, и прочитать `parseFloat`:

```ts
// wl-e2e/helpers/monolith/store/store-page.ts:52
export async function extractPrice(locator: Locator): Promise<number> {
  const text = await locator.evaluate((el) => el.getAttribute('data-amount') || el.textContent || '');
  return parseFloat(text.replace(/[^0-9.]/g, ''));
}
```

Запятую не понимает ни `parseFloat`, ни `Number` — `parseFloat('1,234.56')`
даёт `1`. Поэтому она вырезается **до** вызова.

Почему `parseFloat`, а не `parseInt` — см.
[уточнения](#parseint-теряет-копейки). Почему не всегда `Number` — он требует,
чтобы вся строка была числом: `Number('19.99 USD')` это `NaN`,
а `parseFloat('19.99 USD')` это `19.99`.

**Шаг 2. Сравнить.** Не через `===`:

```ts
// projects/monolith/tests/regression-run/app-drawer-store/store-main/C50360.spec.ts:90
expect(sumAmounts(splitAmounts), 'the three selected methods should split the whole order total')
  .toBeCloseTo(orderTotal, 2);

// C50360.helpers.ts:339 — складывает строки, снятые со страницы
export function sumAmounts(values: string[]): number {
  return values.reduce((total, value) => total + Number(value), 0);
}
```

Здесь сходятся обе половины урока: `Number(...)` обязателен, иначе `+` склеит
строки; и `Number('')` это ноль, поэтому пустая ячейка молча добавит `0`
вместо того, чтобы уронить проверку.

`toBeCloseTo` — 53 вхождения в `wl-e2e`. Внутри там одна строка:

```js
pass = Math.abs(expected - received) < Math.pow(10, -precision) / 2
```

То есть «с точностью до двух знаков». Второй аргумент по умолчанию — `2`,
но лучше писать его явно.

**Шаг 3. Если нужно не сравнивать, а считать** — дробные не используют вообще:
переводят в целые (в центы), считают и переводят обратно.

```ts
const cents = (usd: number): number => Math.round(usd * 100);

cents(10.1) + cents(20.2)              // 3030
(cents(10.1) + cents(20.2)) / 100      // 30.3, точно
```

`toFixed` для этого не годится — он возвращает строку.

## Восемь строк, ради которых занятие

1. `Array.isArray` для массива, `Number.isNaN` для `NaN`, `x === null`
   для `null`.
2. Всегда `===`. Единственное исключение — `x == null`.
3. `toFixed` возвращает **строку**, и она не для вычислений.
4. `sort()` без колбэка сортирует как строки: `[1, 10, 100, 9]`.
   И колбэк возвращает число, а не `true`/`false`.
5. `.length` считает ячейки, а не символы.
6. По умолчанию `const`; `var` — никогда.
7. Спред копирует **верхний уровень**; вложенное остаётся общим.
8. `arr[99]` компилятор считает числом, а в рантайме там `undefined`.
