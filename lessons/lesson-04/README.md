# Урок 4. Функции и область видимости

Всё держится на двух мыслях:

1. функция — это значение: её кладут в переменную, передают другой
   функции и вызывают сразу после создания;
2. имя ищется изнутри наружу — от места, где код **написан**; отсюда
   область видимости.

Замыкание и `this` — в [уроке 5](../lesson-05/README.md).

Несколько мест ниже сформулированы точнее, чем прозвучали на занятии.
Если запомнилось иначе — верьте конспекту и проверьте запуском.

Запись занятия — в чате группы. [Домашка](homework/README.md) ·
[примеры](examples/README.md).

## Как записать функцию

Пример: [`01-writing-functions.ts`](examples/01-writing-functions.ts).

### Объявление, `return`, `void`

Кусок кода, который нужен много раз, заворачивают в **функцию**: пишут
один раз, вызывают по имени.

```ts
function greet(name: string): string {
  return `Привет, ${name}!`;
}
console.log(greet('Ann'), greet('Bob')); // Привет, Ann! Привет, Bob!
```

| Часть | Что значит |
|---|---|
| `function greet` | объявить функцию с именем `greet` |
| `(name: string)` | **параметр** — имя для того, что передадут при вызове, с типом |
| `: string` после скобок | тип результата: функция обещает вернуть строку |
| `return …` | отдать значение тому, кто вызвал, и сразу выйти |
| `greet('Ann')` | вызов. `'Ann'` — **аргумент**, он ляжет в параметр |

Тело выполняется при **каждом** вызове, а не при объявлении.

**Функция без `return` возвращает `undefined`** — всегда. Тип `: void`
значит «полезного результата нет»: так помечают функции, которые что-то
делают (печатают, кликают), а не считают. Если `return` нет, TypeScript
поставит `void` сам.

Если тип результата обещан (`: number`), а `return` нет, TypeScript
не пропустит (`TS2355`). Поэтому тип результата и пишут: он ловит
забытый `return`.

`console.log(…)` сначала вычисляет **все** свои аргументы и только потом
печатает. Поэтому если среди аргументов есть функция, которая печатает
сама, её строка появится раньше.

### Три записи одной функции

| Запись | Название | Что это |
|---|---|---|
| `function addDeclared(…) {…}` | объявление функции (function declaration) | отдельная инструкция, у функции есть имя |
| `const addExpressed = function (…) {…};` | функциональное выражение (function expression) | функция — **значение** справа от `=`, как число |
| `const addArrow = (…) => …;` | стрелочная функция (arrow function) | то же выражение, короче |

У стрелки два вида тела:

| Стрелка | Что значит |
|---|---|
| `(a, b) => a + b` | короткое тело: значение возвращается само, `return` не пишут |
| `(a, b) => { …; return x; }` | полное тело в фигурных скобках: `return` пишут сами |
| `(n) => ({ value: n })` | вернуть объект: без круглых скобок фигурные прочитаются как тело, и выйдет `undefined` |

Результат у трёх записей один. Различаются они в трёх местах, по каждому
есть свой раздел: **поднятие** ([ниже](#поднятие-и-мёртвая-зона)),
**свой `arguments`** ([ниже](#arguments--старый-способ)) и **свой `this`**
([урок 5](../lesson-05/README.md)). Чаще всего именованную функцию пишут через `function`,
а функцию «на месте» — стрелкой.

### Функция без имени и IIFE

```ts
(function () {
  const hidden = 'видно только внутри';
  console.log(hidden);
})();
const product = ((a: number, b: number): number => a * b)(6, 7);
console.log(product); // 42
```

| Часть | Что значит |
|---|---|
| `function () {…}` | **анонимная** функция — без имени. Стрелки анонимные всегда |
| `(function () {…})` | скобки вокруг: «это выражение». Без них строка, начатая словом `function`, — объявление, и `()` после него — ошибка синтаксиса |
| `(…)()` в конце | сразу вызвать то, что в скобках |

Функцию, которую создали и тут же вызвали, называют **IIFE**
(Immediately Invoked Function Expression, «выражение, вызванное сразу»).
Нужна она ради **своей области видимости**: `hidden` снаружи не видно.
До `let`, `const` и модулей это был главный способ спрятать переменные.
Сегодня так пишут редко, но в старом коде и в чужих библиотеках IIFE
встречается постоянно.

**В `product` лежит число `42`, а не функция и не «запомненный вызов».**
Стрелка вызвана один раз, прямо в этой строке. В переменную положен её
результат, и дальше `product` — обычное число.

Выражение не обязательно безымянное: `const countdown = function tick(…)`
тоже функциональное выражение, только с именем ([рекурсия](#рекурсия-функция-вызывает-саму-себя)).
Чаще же всего анонимная функция живёт аргументом другой функции —
[колбэком](#колбэк).

## Параметры

Пример: [`02-parameters.ts`](examples/02-parameters.ts).

### Значение по умолчанию

```ts
function greetWith(name: string, greeting = 'Привет'): string {
  return `${greeting}, ${name}!`;
}
greetWith('Ann');             // Привет, Ann!
greetWith('Eve', undefined);  // Привет, Eve!
greetWith('Kim', '');         // , Kim!
```

`greeting = 'Привет'` — значение по умолчанию. Тип писать не нужно:
TypeScript выводит его из значения.

**Умолчание срабатывает, только если аргумента нет или передан `undefined`.**
Дело не в типах, а в правиле JavaScript: пустая строка, `0`, `false`
и даже `null` — это переданные значения, и умолчание их не трогает.
Правило похоже на `??` из урока 3, только строже: `??` заменяет и `null`,
а умолчание — нет.

Без умолчания недостающий аргумент TypeScript не пропустит (`TS2554`).
Сам JavaScript не возражал бы: в параметре было бы `undefined`.

### `arguments` — старый способ

Внутри функции, объявленной через `function`, есть объект `arguments` —
**все** переданные аргументы, сколько бы параметров ни было объявлено.

- Это **не массив**, а объект, похожий на массив: длина и номера есть,
  методов массива нет (`Array.isArray(arguments)` → `false`).
  `Array.from(arguments)` делает из него настоящий массив.
- **У стрелки своего `arguments` нет.** Внутри другой функции стрелка видит
  `arguments` внешней, а на верхнем уровне файла такого имени нет вовсе
  (`TS2304`). Это второе отличие стрелки из [трёх](#три-записи-одной-функции).
- В TypeScript-коде `arguments` почти не встречается: лишний аргумент
  отклоняет проверка типов (`TS2554`), а «сколько угодно аргументов»
  собирают по-новому — следующий раздел. Узнавать в старом коде.

### Остаточные параметры и `...` при вызове

```ts
function sumAll(...numbers: number[]): number {
  let sum = 0;
  for (const value of numbers) {
    sum = sum + value;
  }
  return sum;
}
sumAll();            // 0
sumAll(1, 2, 3, 4);  // 10
const prices = [10, 20, 30];
sumAll(...prices);   // 60
Math.max(...prices); // 30
[...prices, 40];     // [ 10, 20, 30, 40 ]
```

Три точки — **одна запись, два противоположных смысла**, и названия у них
разные:

| Где стоит `...` | Что делает | Название |
|---|---|---|
| в параметрах: `(...numbers: number[])` | **собирает** все оставшиеся аргументы в массив | остаточные параметры (rest) |
| при вызове: `sumAll(...prices)` | **раскладывает** массив на отдельные аргументы | спред, расширение (spread) |
| в массиве: `[...prices, 40]` | раскладывает элементы в новый массив | спред |

- `numbers` — **настоящий массив** с типом `number[]`, не как `arguments`.
  Ничего не передали — пустой массив.
- Остаточный параметр — только **последним**: он «все остальные». Обязательные
  параметры — перед ним: `function sumFrom(base: number, ...numbers: number[])`.
  Иначе — `TS1014: A rest parameter must be last in a parameter list`.
- Без `...` передаётся **одно** значение. `countAll(list.length)` — это
  один аргумент (число `3`), а `countAll(...list)` — три.
- `[...prices, 40]` — **новый** массив, `prices` не изменился.
- `console.log` устроен так же: принимает сколько угодно аргументов
  остаточным параметром. Поэтому `console.log(...numbers)` печатает
  числа через пробел, а `console.log(numbers)` — массив.

## Функция — это значение

Пример: [`03-functions-as-values.ts`](examples/03-functions-as-values.ts).

### Без скобок — сама функция

```ts
const sayHello = greet;
console.log(typeof greet, sayHello('Kim')); // function Привет, Kim!
```

Главное место урока. Со скобками — **вызов**: выполнить тело и взять
результат. Без скобок — **сама функция**, такое же значение, как число.
Её можно положить в другую переменную: `sayHello` — та же функция под
вторым именем, а не строка. А раз функция — значение, её можно
и **передать**.

### Тип функции и сама функция

В TypeScript стрелка `=>` бывает в двух ролях, и их легко спутать:

```ts
const multiply: (x: number, y: number) => number = (x, y) => x * y;
//              └── тип: какая функция здесь лежит ──┘   └ сама функция ┘
```

| Слева от `=`, после `:` | Справа от `=` |
|---|---|
| `(x: number, y: number) => number` | `(x, y) => x * y` |
| **тип** — описание: «функция от двух чисел, которая вернёт число» | **сама функция** — что делать |
| ничего не делает, при запуске его нет вовсе | при вызове считает |

Типы `x` и `y` справа TypeScript берёт из описания слева. То же
происходит с параметром-функцией в следующем разделе.

### Колбэк

```ts
function calculate(a: number, b: number, operation: (x: number, y: number) => number): number {
  return operation(a, b);
}
calculate(6, 7, multiply);        // 42
calculate(6, 7, (x, y) => x - y); // -1
```

| Часть | Что значит |
|---|---|
| `operation: (x: number, y: number) => number` | **тип** параметра: сюда передадут функцию от двух чисел, которая вернёт число |
| `calculate(6, 7, multiply)` | передали функцию — **без скобок** |
| `(x, y) => x - y` | анонимная функция, созданная прямо на месте вызова |

`operation` нигде не объявлена — это **имя параметра**, как `a` и `b`.
Описание `operation` ничего не делает, оно только обещает: третьим
аргументом придёт функция такой формы. Какую именно — решают при каждом
вызове. И главное: **мы ни разу не пишем `multiply(…)`**. Вызывает её
`calculate`, со своими `a` и `b`.

> **Колбэк** (callback) — функция, которую передают в другую функцию
> аргументом, чтобы та вызвала её сама. Пишете её вы, вызывает принимающая
> сторона.

Так устроен каждый тест Playwright: в `test('название', async () => { … })`
второй аргумент — колбэк, и вызывает его Playwright.

**Передать — без скобок, вызвать — со скобками.**
`calculate(6, 7, multiply(6, 7))` не скомпилируется (`TS2345`):
`multiply(6, 7)` — это вызов. Он выполнится сразу, ещё до `calculate`,
и вместо функции та получит число `42`.

### Рекурсия: функция вызывает саму себя

```ts
function factorial(n: number): number {
  if (n <= 1) {
    return 1;
  }
  return n * factorial(n - 1);
}
factorial(5); // 120
```

> **Рекурсия** (recursion) — функция вызывает саму себя, каждый раз
> с задачей поменьше. Обязателен **базовый случай** — условие, при котором
> она себя больше не вызывает.

```
factorial(3)
  = 3 * factorial(2)
          = 2 * factorial(1)
                  = 1            ← базовый случай: n <= 1
          = 2 * 1 = 2
  = 3 * 2 = 6
```

Вызовы складываются стопкой, пока не дойдут до базового случая, и потом
сворачиваются обратно с ответами. Без базового случая стопка растёт, пока
не кончится место. Проверить можно безопасно, падает за доли секунды:

```bash
node -e "function down(n) { return down(n + 1); } down(0)"
# RangeError: Maximum call stack size exceeded
```

Это же сообщение будет в упавшем тесте, если функция случайно вызывает
сама себя.

У функционального выражения может быть своё имя:

```ts
const countdown = function tick(n: number): string {
  return n === 0 ? 'старт' : `${n} ${tick(n - 1)}`;
};
countdown(3); // 3 2 1 старт
```

Имя `tick` видно **только внутри** функции — чтобы вызвать себя. Снаружи
её зовут `countdown`, а `tick(3)` даст `TS2304`. В тестах рекурсия
нечаста: обход вложенного — меню с подменю, дерево папок. Почти всё
остальное проще написать циклом.

## Где видно имя

Пример: [`04-scope.ts`](examples/04-scope.ts).

### Блок `{}` и затенение

```ts
const city = 'Kyiv';
{
  const greetingText = `Привет из ${city}`; // Привет из Kyiv
}
{
  const city = 'Lviv';
  console.log(city); // Lviv
}
console.log(city);   // Kyiv
```

> **Область видимости** (scope) — участок кода, где имя существует.
> Для `let` и `const` это ближайшие фигурные скобки: блок `{}`, тело
> функции, `if`, `for`. Изнутри видно внешнее, снаружи внутреннее — нет.

- Фигурные скобки можно поставить и просто так, без `if` и `for` — это
  **блок**. Внутри видно внешнее `city`, а `greetingText` снаружи
  не видно (`TS2304`).
- Во втором блоке **объявлено** своё `city`. Это не переприсваивание
  внешнего, а другое имя в другой области. Оно **затеняет** внешнее:
  внутри — `Lviv`, а внешнее никто не трогал.
- Параметр — тоже имя внутри своей функции. Поэтому `x` в одной
  функции и `x` в другой друг другу не мешают.

### `var` — устаревшее

```ts
{
  var leakedVar = 'вижусь снаружи';
}
console.log(leakedVar); // вижусь снаружи
for (var loopVar = 1; loopVar <= 3; loopVar++) {}
console.log(loopVar);   // 4
```

Область `var` — **функция**. Блоки `{}`, `if` и `for` для неё не граница:
переменная «протекает» наружу. Счётчик цикла тоже протёк и хранит `4` —
значение, на котором условие стало ложным.

А граница функции для `var` — граница: объявленная внутри функции, снаружи
она не видна, как и `let`. «Весь файл» получается, только если `var` стоит
вне всех функций. `var` — запись до 2015 года. Правило: по умолчанию
`const`, `let` — когда правда нужно переприсвоить, `var` — никогда.
Узнавать в старом коде.

### Поднятие и мёртвая зона

```ts
console.log(doubleIt(21)); // 42 — вызвали выше объявления
function doubleIt(n: number): number {
  return n * 2;
}
```

> **Поднятие** (hoisting) — прежде чем выполнять файл, функцию или блок,
> движок заранее заводит все объявленные в **нём** имена. Поднимаются они
> в начало своей области, а не всей программы. `function` заводится сразу
> вместе с телом. `var`, `let` и `const` тоже заводятся заранее, но **без
> значения**.

Поэтому функцию-объявление можно вызвать выше по файлу, а стрелку через
`const` — нельзя (`TS2448`). Что лежит в имени до его строки, видно
в чистом JavaScript:

```bash
node -e "console.log(early); var early = 1"   # undefined
node -e "console.log(late); const late = 1"   # ReferenceError: Cannot access 'late' before initialization
node -e "console.log(never)"                  # ReferenceError: never is not defined
```

> **Временная мёртвая зона** (temporal dead zone) — участок от начала блока
> до строки с `let` или `const`. Имя уже заведено, но обращаться к нему
> нельзя: `ReferenceError`.

|  | до своей строки | после |
|---|---|---|
| `function f` | уже с телом — можно вызывать | то же |
| `var x` | `undefined` — молча | значение |
| `let` / `const` | мёртвая зона — `ReferenceError` | значение |
| нет вовсе | `ReferenceError: x is not defined` | — |

Мёртвая зона — **только** у `let` и `const`. `var` до своей строки молча
отдаёт `undefined`, и ошибка вылезет позже, в другом месте. `const` громко
падает ровно там, где проблема.

**Тип ошибки один — `ReferenceError`, а смысл у сообщений разный**,
и в упавшем тесте это подсказка, что чинить:

| Текст | Что значит |
|---|---|
| `Cannot access 'X' before initialization` | имя **есть**, но его строка ещё не выполнилась — поменять порядок |
| `X is not defined` | имени **нет** — опечатка, не объявили, не импортировали |

Первое сообщение заодно доказывает, что `let` и `const` тоже поднимаются:
иначе было бы «not defined».

### Глобальный объект

```ts
console.log(typeof globalThis, globalThis.Math === Math, typeof window); // object true undefined
```

- Имя ищется **изнутри наружу**: свой блок → внешний блок → функция →
  файл → глобальный объект. **Глобальный объект** — самый внешний уровень.
  Там лежит встроенное: `console`, `Math`, `setTimeout`. Поэтому они есть
  в любом файле, хотя их никто не объявлял.
- Общее имя для него — `globalThis` (это имя свойства, а не ключевое слово).
  В браузере он называется `window`, в Node — `global`. У каждой среды
  свой глобальный объект со своим набором.
- В Node окна нет: `typeof window` — `'undefined'`, а просто `window`
  упадёт с `ReferenceError: window is not defined`. TypeScript при этом
  молчит: в настройках курса подключены типы браузера. **Типы —
  не гарантия того, что есть на самом деле.**
- **Наши функции и переменные в глобальный объект не попадают.** Файлы
  курса — модули (`"type": "module"` в `package.json`), и у модуля своя
  область. `'doubleIt' in globalThis` → `false`. Только в старых скриптах
  (не модулях) `var` и `function` верхнего уровня сами становятся
  свойствами глобального объекта:

  ```bash
  node -e "var fromVar = 1; function fromFunction() {} console.log(globalThis.fromVar, typeof globalThis.fromFunction)"
  # 1 function
  node --input-type=module -e "var fromVar = 1; function fromFunction() {} console.log(globalThis.fromVar, typeof globalThis.fromFunction)"
  # undefined undefined
  ```

  `--input-type=module` — «выполнить как модуль». Глобальный объект ещё
  понадобится в уроке 5, когда `this` «потеряется».

## Сверх плана

Пример: [`05-asked-during-lesson.ts`](examples/05-asked-during-lesson.ts).
Прозвучало на занятии, в план не входило.

- **Шаблонная строка против `+`.** `'Привет, ' + name + '!'` и
  `` `Привет, ${name}!` `` дают одну строку. В обратных кавычках (клавиша
  с тильдой `~`) всё внутри `${…}` вычисляется и подставляется. Без `${…}`
  было бы просто слово `name`. Разница видна на числах:
  `'2 + 3 = ' + 2 + 3` → `2 + 3 = 23`, а `` `2 + 3 = ${2 + 3}` `` → `2 + 3 = 5`.
- **`map` строит новый массив.** На занятии он мелькнул в примере
  с `arguments`. Это не цикл для печати: `map` вызывает колбэк для каждого
  элемента и собирает из того, что колбэк **вернул**, новый массив.
  `[1, 2, 3].map((n) => n * 2)` → `[2, 4, 6]`. Колбэк, который только
  печатает, даст массив из `undefined`. Чтобы просто обойти элементы —
  `for...of`. Остальные методы массива разберём по месту, когда встретятся.
- **Колбэк значением по умолчанию.** Можно ли не передавать действие
  в `calculate` каждый раз? Можно:
  `function calculate(a: number, b: number, operation = (x: number, y: number): number => x + y)`.
  Не передали — сложит, передали — сделает то, что передали. А если
  действие всегда одно, параметр-функция не нужен вовсе: его пишут прямо
  в теле. Колбэк нужен, когда действие выбирает тот, кто вызывает.
- **`window` в браузере.** В консоли браузера (`F12` → Console) у `window`
  много вложенных объектов, через точку их можно смотреть:
  - `history.length` — сколько записей в истории **этой вкладки**
    (страниц, по которым в ней переходили), а не сколько вкладок открыто;
  - `navigator.language` — язык браузера;
  - `navigator.hardwareConcurrency` — число логических ядер процессора;
  - `navigator.connection.effectiveType` — оценка канала (`'4g'`),
    а не имя сети. В Chromium там ещё `rtt`, `downlink` и `saveData`,
    имени сети нет.

  Эти данные доступны любому сайту без спроса.

## Итог урока

1. Функция без `return` возвращает `undefined`. `: void` это обещает,
   а `: number` без `return` TypeScript не пропустит.
2. Три записи — объявление, выражение, стрелка. Анонимная функция
   в скобках с `()` после них вызывается сразу — это IIFE, и у неё своя
   область видимости.
3. Умолчание параметра срабатывает **только** на `undefined` или
   отсутствие аргумента. `...` в параметрах **собирает** аргументы
   в массив (остаточные параметры), `...` при вызове — **раскладывает**
   (спред). `arguments` — старое, у стрелок его нет.
4. Без скобок — сама функция, со скобками — вызов. Колбэк передают
   без скобок. Тип параметра-функции — только описание. Рекурсии нужен
   базовый случай.
5. `let`/`const` живут в ближайших `{}`, `var` — во всей функции.
   До строки `let`/`const` — мёртвая зона, `function` можно вызвать выше.
   Самый внешний уровень — глобальный объект `globalThis`. Наши функции
   в нём не лежат: файлы — модули.

## Словарь терминов

| Термин | Что значит |
|--------|------------|
| **колбэк** (callback) | функция, которую передают в другую функцию аргументом, чтобы та вызвала её сама: `calculate(6, 7, multiply)`. Передают **без скобок**, скобки — это вызов |
| **рекурсия** (recursion) | функция вызывает саму себя, каждый раз с задачей поменьше. Нужен базовый случай — когда она себя больше не вызывает |
| **область видимости** (scope) | участок кода, где имя существует. Для `let` и `const` — ближайшие фигурные скобки. Изнутри видно внешнее, снаружи внутреннее — нет |
| **поднятие** (hoisting) | до выполнения файла, функции или блока движок заранее заводит все объявленные в нём имена. `function` — сразу с телом, поэтому её можно вызвать выше объявления |
| **временная мёртвая зона** (temporal dead zone) | участок от начала блока до строки с `let` или `const`. Имя уже есть, но обращаться к нему нельзя: `ReferenceError: Cannot access '…' before initialization` |

Знакомые слова: **параметр** — имя в скобках объявления функции;
**аргумент** — значение, которое передают при вызове; **стрелочная
функция** — запись через `=>`: `(n: number) => n * 2`; **значение
по умолчанию** — то, что параметр получит, если аргумент не передали:
`greeting = 'Привет'`; **остаточные параметры** — `...numbers`
в параметрах, собирают аргументы в массив; **спред** — `...prices`
при вызове или в массиве, раскладывает; **метод** — функция в свойстве
объекта; **IIFE** — функция, которую создали и сразу вызвали: `(() => …)()`;
**глобальный объект** — `globalThis`, самый внешний уровень, где лежат
`console` и `Math`.
