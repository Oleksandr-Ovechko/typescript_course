# CLAUDE.md — курс JS/TypeScript для команды wl-e2e

Учебный репозиторий: материалы менторства для перехода из ручного QA в автоматизацию
на проекте `wl-e2e`. Здесь — технические соглашения репозитория.

## Главный принцип

Курс **не** строится вокруг учебного пет-проекта. Каждый пример — либо настоящий код
из `wl-e2e`, либо его упрощённая версия. Придумывать абстрактные сущности («магазин
футболок») вместо `SessionIdentity`, `LoginOpts` или `QuickContactSource` не нужно:
знание должно ложиться прямо на рабочий репозиторий.

## Структура

```
tsconfig.json                 настройки компилятора — копия корневого из wl-e2e
lessons/lesson-NN/
├── README.md                 конспект урока: темы с объяснениями + словарь терминов
├── examples/                 готовый код всех тем, по файлу на тему
│   ├── README.md             таблица «файл → тема → о чём»
│   ├── NN-*.ts               запускаются и проходят typecheck
│   └── broken/               намеренно НЕ проходят typecheck, свой tsconfig
└── homework/                 задания, свой tsconfig
playground/                   код текущего урока: заполняется до занятия, закомментирован
```

## Команды

```bash
node playground/scratch.ts        запустить свой код
node lessons/.../examples/X.ts    запустить пример
yarn typecheck                    типы: playground + examples
yarn typecheck:hw2                типы: домашка урока 2
yarn typecheck:hw3                типы: домашка урока 3
yarn typecheck:hw5                типы: домашка урока 5
yarn typecheck:hw6                типы: домашка урока 6
yarn typecheck:hw10               типы: домашка урока 10
yarn typecheck:hw12               типы: домашка урока 12
yarn typecheck:modules            типы: пример с импортом между файлами
yarn typecheck:broken             намеренно сломанные файлы
```

## Инварианты

**`tsconfig.json` дословно повторяет корневой `tsconfig.json` из `wl-e2e`.**
Поведение компилятора в курсе и на проекте должно совпадать один в один. Менять
настройки только вслед за проектом.

**Node ≥ 22.18** — на нём `node file.ts` работает напрямую. Версия зафиксирована
в `.nvmrc` (25.9.0, как в `wl-e2e`).

**Отдельные tsconfig-проекты.** Корневой покрывает `playground/` и `examples/`.
Свои конфиги есть у `homework/` и `examples/broken/` — там ошибки намеренные
и не должны мешаться с настоящими, — и у `lesson-03/examples/modules/`, где нужен
`allowImportingTsExtensions` (см. ниже). Дочерние конфиги обязаны переопределять
`"exclude": []` — иначе унаследуют `exclude` корневого и исключат сами себя
(`TS18003`).

**Импорт между файлами примеров: общей формы нет.** `from './helper'` проходит
`tsc`, но `node` даёт `ERR_MODULE_NOT_FOUND`; `from './helper.ts'` запускается,
но `tsc` даёт `TS5097`. В `wl-e2e` конфликта нет: там файлы запускает Playwright
через babel, а не `node` напрямую. Примеры с настоящим импортом между файлами
класть в подпапку со своим конфигом и `allowImportingTsExtensions: true`.

**Скрипты называются `typecheck`, а не `check`** — `check` это встроенная команда
Yarn 1, она перехватывает одноимённый скрипт.

## Код урока живёт в трёх местах

| Где | Когда | Комментарии |
|-----|-------|-------------|
| `docs/lesson-NN.md` | пишется первой | Развёрнутые объяснения, ожидаемый вывод |
| `playground/scratch.ts` | заполняется **до** занятия | **Никаких** — только код и разделители блоков. Сам код **закомментирован**: раскомментируется по ходу занятия |
| `lessons/lesson-NN/examples/` | собирается **после** занятия | Для самостоятельного чтения |

`scratch.ts` собирается из методички скриптом `docs/scripts/build-scratch.py`,
а не руками: он же сверяет вывод раскомментированной копии с тем, что в методичке
записано как «Вывод:». Подробности процесса — в `docs/README.md`.

## Формат примеров

- **Шапка-докблок** в начале файла: что внутри, как запустить.
- **Разделители по темам** — `// ── Название темы ──────`. В `examples/` называть
  по теме, **без номеров**: номера ведут в методичку, которой у учеников нет.
  В `playground/scratch.ts` — наоборот, нумерация методички сохраняется: файл
  живёт ровно одно занятие, и по нему ведущий и группа держат общее место.
- **Код, который не должен компилироваться**, — закомментирован с пометкой
  `// ❌ TS####` и настоящим кодом ошибки. Проверяется скриптом, а не на глаз.
- **`export {};` в конце каждого файла.** Без него файл считается глобальным
  скриптом и его объявления сталкиваются с соседними примерами (`TS2451`).
  В самом `wl-e2e` такой строки нет: там каждый файл уже модуль.

**Примеры к инструментальным урокам — `bash`, а не TypeScript.** Уроки 8 и 9
про git, и примеры в них — исполняемые сценарии `.sh`. Правила те же (шапка,
разделители по темам), плюс два своих:

- **Своя песочница в `/tmp/wl-git-examples/<урок>-<тема>`**, которая сносится
  в начале скрипта и остаётся после — чтобы можно было зайти и поковырять.
  Ничего за пределами `/tmp` пример не трогает: у учеников открыт рабочий
  репозиторий, и цена ошибки в примере иначе слишком велика.
- **`set -e` и локальный `git config`** — падать на первой же ошибке
  и не зависеть от глобальных настроек читателя.

Проверяются они не `tsc`, а запуском: `bash lessons/lesson-08/examples/*.sh`
должен отработать с нулевым кодом возврата, а объяснения внутри — совпадать
с настоящим выводом.
